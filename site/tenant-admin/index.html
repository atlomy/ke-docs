Tenant Administration

Audience: Tenant administrator — the person running one knowledge environment. Last aligned with platform state: 2026-05-25 Platform version: V2 (pre-1.0)

Purpose​

You operate one knowledge environment on a multi-tenant platform. This area of the documentation tells you what you configure, where each control lives, and how to verify changes reach the surfaces you expect. Read this if you are onboarding a new environment, revising a configuration after researcher feedback, or auditing what your environment is doing.

The platform ships generic. Your job is to shape four things: how the platform speaks, who can do what, what data comes in, and what the platform records about how it is being used.

Ordered by how often a typical operator uses each.

See Voice and Vocabulary.
  • Permissions panel — contributors, role composition, project rules, ownership transfers, audit. Substrate: Spec 0018 Sprint C + customers/services/permission_admin.py · Maturity: Active · Limit: standard-role permission primitives are fixed; custom roles compose them. See Permissions Panel.
  • Data import wizard — Django admin path for parser-first / LLM-second proposal review across xlsx, MySQL, CSV bundle, and Coda sources. Substrate: Spec 0011 + Spec 0017 + ADR-010 + ADR-017 + ADR-034 · Maturity: Active · Limit: full v4 React surface still rolling out; today's surface is the Django bridge plus async worker ledger. See Data Import Wizard.
  • Vocabulary grounding — link tenant vocabulary to external authorities (Wikidata, PeriodO). Substrate: Spec 0026 + customers/services/vocabulary_derivation.py · Maturity: Active · Limit: tenant admin is the only role that can confirm a grounding. See Vocabulary Grounding.
  • AI-assisted vocabulary bootstrap — one-pass onboarding workflow that proposes an initial vocabulary set so the safety-floor gate can unlock. Substrate: Spec 0029 + ADR-044 §3 + customers/services/vocabulary_bootstrap.py · Maturity: Active · Limit: bootstrap is one-pass; the live surface owns post-onboarding edits. See AI-Assisted Bootstrap.
  • Efficiency tips — short contextual nudges surfaced to researchers in the wizard and workspace; on/off per environment plus aggregate acceptance ratios. Substrate: Spec 0030 + customers/services/tip_recommender.py + Client.tips_enabled · Maturity: Active · Limit: tips never block researcher action; acceptance ratios are k-anonymity-floor clamped. See Efficiency Tips.
  • Citation integrity — structural guarantees behind citable Editions and DOI-safe artifact versions. Substrate: ADR-022 + Spec 0008 + ADR-020 + atlomyapp/management/commands/ingest_3d_model_glb.py · Maturity: Active · Limit: platform does not mint DOIs; it exposes stable identity for an external minter. See Citation Integrity.
  • Media review surface — single-page UI to review one artifact-version's attestations, with manual-add, re-extraction dry-run, and Edition promotion. Substrate: Spec 0012 + ADR-022 Phase 5 + Spec 0014 (async re-extraction) · Maturity: Active · Limit: edition promotion requires admin role; ClaimCluster authoring is deferred. See Media Review Surface.
  • Entry Surface readiness — review panel for public facet/autocomplete controls before launch. Substrate: ADR-019 + ADR-029 + Spec 0021 + Spec 0022 + atlomyapp/services/entry_surface_facets.py · Maturity: Active · Limit: a review surface, not an auto-apply surface; promoting a public control is a separate explicit step. Usability — how you use it​

The most common operator paths:

  • Onboarding a new environment: configure voice and vocabulary; run AI-assisted bootstrap if no grounded or derived vocabulary exists; confirm a few groundings if external authorities apply; configure permission roles and invite contributors; choose a CSL citation style; decide whether efficiency tips are on.
  • Bringing in new source data: open /admin/data_import/mappingproject/ and use the appropriate Upload button (xlsx, MySQL, CSV bundle, or Coda). The wizard parses, classifies risk, generates proposals, and routes them through Flow B two-step approval (scholar approve, then admin apply).
  • Reviewing media attestations: open any MEDIA EpistemicEntity in the Django admin and follow the deep link to /admin/epistemic/epistemicentity/<uuid>/media-review/. Approve / amend / strip per row; promote to Edition when ready to cite.
  • Auditing recent activity: open /admin/permissions/ and use the Audit tab. Permission changes, ownership transfers, vocabulary edits, and AI-reviewed commits are all here.
  • Checking what the platform is recording: /admin/monitoring/telemetry/ shows current-tenant signal counts, suggestion-quality bars, paused auto-apply categories, and vocabulary-derived labels.

Troubleshooting​

SymptomLikely causeFix
The wording on a researcher-facing surface is still the platform defaultThe relevant TenantVocabularyEntry is missing or unconfirmedOpen the vocabulary surface (see Voice and Vocabulary), find the canonical key, and add or confirm an entry. Verify with the {% voice %} tag's fallback chain.
The safety-floor gate is closed and researchers cannot authorNo vocabulary entry is grounded, derived, or AI-reviewed for the required canonical keysRun AI-assisted bootstrap, or ground entries through the grounding workflow, or import data so the derivation lane writes entries. Any of the three paths satisfies the gate.
The Permissions Panel shows a vocabulary-startup-linter bannerThe startup lint pass found missing entries, broken grounding references, or inconsistenciesClick into the surfaced rows. The lint is read-only — acting on the findings is your decision.
The import wizard shows status_reason="llm_unavailable" on a proposalLLM_PROVIDER=bedrock or AWS Bedrock credentials are missing in the environmentParser-only proposals are still reviewable. To enable Bedrock, set BEDROCK_AWS_ACCESS_KEY_ID, BEDROCK_AWS_SECRET_ACCESS_KEY, AWS_BEDROCK_REGION, AWS_BEDROCK_MODEL_ID and re-run.
A re-import overwrote a researcher's manual editsThe job used --replace or --clear rather than --merge-replaceRestore from your environment's backup; re-run with --merge-replace. See ADR-017 Phase 2.A.

If a failure mode is well-documented in a specific feature page, the page below it owns the deeper troubleshooting; this README only flags the top-level cases.
