Data Import Wizard

Purpose​

The Data Import Wizard brings source data into your environment without bypassing review. It reads an uploaded source (an Excel workbook, a MySQL dump or live connection, a set of CSV files, or a Coda document), proposes how each table and column should land in your environment, routes every proposal through a two-step approval, and writes records only after you start the final import. Read this when you bring in a new corpus, re-import a source whose shape you already know, or a researcher reports that an import did the wrong thing.

The wizard is the supported path for getting data into an environment. For repair work or bulk operations outside the wizard, contact your platform operator.

Features​

Ordered roughly by what you touch first.

  • Guided entry from the sidebar — Imports & AI → Imports opens the first wizard step with your recent imports and saved setups. All imports lists every import, with shortcut buttons (Start import, Excel, Database, CSV files, Coda) in its top-right toolbar. Pending Review is a flat queue of suggestions awaiting review across imports. Background Jobs shows the status of background uploads. Maturity: Active. Limit: the plain admin "Add" form does not read a source — always start from an upload route.
  • At-a-glance import state on the list — the All imports list carries a Current stop column and a per-import proposal tally (approved / rejected / pending / total), so you can see which imports are waiting on you and at which step (for example, "Stage 4 — Needs choices") without opening each one. Maturity: Active.
  • Excel upload — a project name, an optional description, and an .xlsx file. Files up to 5 MB import inline; larger files, up to 100 MB, run in the background. Maturity: Active.
  • MySQL upload — two modes: a dump file (.sql or .sql.gz; 50 MB inline, up to 500 MB in the background) or a live connection address with optional credentials. Live-connection reads always run inline, and the credentials are held only for that request — they are never saved. A saved connection can reference a secret kept in the platform's managed secret store instead of carrying a password; the secret is resolved at run time. Maturity: Active.
  • CSV upload — several files in one submission; each file becomes a table named after the file. Limits: 10 MB per file and 30 MB total inline; 50 MB per file and 250 MB total in the background. The wizard can suggest connections between files by matching overlapping values; these suggestions are deliberately more cautious than connections declared inside a single workbook. Maturity: Active.
  • Coda upload — a project name, the Coda document name, a one-time API key, and an optional subset of tables. The key is held only for the upload/materialize request path and is not saved with the import or job payload. If rows have already been retained for replay, a retry can use that retained copy; otherwise the wizard asks for the key again instead of failing silently. Maturity: Active.
  • Background imports — an upload that exceeds its inline limit is refused before processing, with a message telling you the limit. Resubmit with the background option: a status page refreshes while the job runs and links to the wizard when it is ready. You can close the tab; the job keeps working. Maturity: Active.
  • Six-step review flow — Step 1 Bring in your data, Step 2 Here's what we found, Step 3 What we'll do, Step 4 A few things to confirm, Step 5 Practice run, Step 6 Ready when you are. Nothing is written to your environment until you press Start import in Step 6. Maturity: Active.
  • Autonomy setting (Step 3) — "How involved do you want to be?": Hands off, Stay informed, Ask if unsure, or Confirm everything, saved per import. The setting controls how many of the wizard's confident structural readings are applied for you — always with an undo window — versus held for your decision. At the two most hands-off settings this can include a change to an existing setup that has no imported records yet; at Ask if unsure, only additive changes the wizard is highly confident about move ahead; Confirm everything holds every suggestion for you. High-risk suggestions and restructure suggestions wait for explicit review whatever the setting. For a first import of an unfamiliar corpus, use Confirm everything when table meanings must be checked one by one before the final import. Maturity: Active.
  • Suggestion cards with reasons (Step 3) — each card shows what would change, a confidence percentage, the evidence behind the reading, and plain-language reasons. Respond with Looks good or open Change this. Card actions are protected form submissions; a stray link click cannot alter a suggestion. Maturity: Active.
  • Change a table's meaning — when the wizard read a table's meaning wrong, pick the correct meaning under Change this. The suggestion retargets cleanly: risk is re-assessed against the new meaning, and every card, preview, and the final import follow the correction. A card carrying an older unapplied change request shows a "requested, not applied yet" banner with Apply change and Keep original actions, and a plain confirmation cannot approve a stale meaning. Maturity: Active. Limit: a completed import is closed — to reinterpret its tables, start a new import.
  • Undo for automatic decisions — when the wizard applies a suggestion for you, a toast names exactly what was decided, and "applied for you" always names its cause. The undo window pauses while you hover or focus the toast, and the paused time genuinely extends the window. When a setting change applies several suggestions at once, you get one combined toast with Undo all. Maturity: Active. Limit: undo reverses review decisions before the final import; it does not undo records written in Step 6.
  • Confirmations that are remembered (Step 4) — your answers to the wizard's clarifying questions are saved with the import. Where retained source rows are available, a "show me" view displays the surrounding source cells so you can answer from evidence rather than memory. Later imports of the same shape reuse your answers. Maturity: Active.
  • Practice run (Step 5) — a full dry run before anything is saved. Issues are grouped by cause rather than by row, with a good/warning/error breakdown, and each group links back to the review queue or exports a summary of the affected rows. Maturity: Active.
  • Draft reader preview — an admin-only preview of how approved rows will read on your public entry surface, rendered by the same machinery the real import uses. Restructured fields are marked in the preview, including "keep both" companion fields. The preview publishes nothing. Maturity: Active.
  • Saved setups and format recognition — a successful import creates or updates a saved setup. When you upload a familiar shape again, Step 2 shows "We've seen this format before" with a confidence figure, and every choice stays editable. Saved setups store structure, never your source rows. Maturity: Active.
  • Decisions carried forward on re-import — when you re-import over already-imported data, decisions that are structurally unchanged from your prior import are carried forward instead of re-asked. Anything new, changed, or ambiguous goes back to review; uncertainty always routes to review, never to a silent carry-over. Maturity: Active.
  • Two-step approval with risk levels — every suggestion gets a risk level (low, medium, or high) with visible reasons. A suggestion held for review goes through two steps: a reviewer approves first, then an administrator applies. When your autonomy setting lets a confident structural reading move ahead for you, the decision is system-mediated and the undo window applies; for audit-sensitive imports, ask your platform operator to check the auto-apply markers and status reason rather than relying only on a visible reviewer name. Suggestions refined by AI always go through human review; AI never changes your environment directly. If the risk level changed while a suggestion sat in review — because the environment changed around it — apply is blocked until you read and acknowledge the new level. Maturity: Active.
  • Needs revision — a reviewer can send a suggestion back with a required note instead of rejecting it outright. The suggestion blocks the final import until it is revised, and the note travels with it. Maturity: Active.
  • Restructure suggestions — the wizard can propose shape improvements it detects in your source: a lookup column becomes a picker field, a supporting table becomes the option list behind a picker, or sibling language columns merge into one multilingual field. You choose Keep both (the original field plus a typed companion field) or Replace. Approved restructures are carried through the final import. These suggestions never apply automatically, whatever their confidence. Maturity: Active.
  • Honest receipts, with progress still being hardened — the final run records per-table outcomes and the completion receipt leads with what happened: record and connection counts, "references not linked yet" with a per-link breakdown, and an Open your workspace action. Every table in the plan produces exactly one outcome row — "created N records", or "will create 0 records" with the reason — predicted in the practice run and confirmed after the run. The linking pass can be much longer than the table-write steps; the wait/progress view is still being hardened for that long phase. Maturity: Active.
  • Live cold-import proof — a 2026-06-29 browser walk ran a fresh Coda import through the wizard and completed the final import into the workspace: 10 workspace tables, 10,080 records, and 29,696 relationships. The receipt led to browsable workspace tables. Maturity: Built for that import class; keep using the practice run and receipt for each new source because source shape still matters.
  • Resolve a "nothing will import" stop from inside the wizard — when the practice run finds that your approved choices would bring in zero rows, Step 5 names the situation ("Nothing will import yet") and offers only the action it can honestly deliver for that cause, rather than a dead end: fix the conflicting columns (it deep-links you back to Step 3), return to the review queue, or align/restructure the flagged columns. You never lose your work — there is no new upload and no re-run from scratch. Maturity: Active.
  • Keep non-standard values as-is (import as text) — when the source checks flagged a column only for advisory reasons (its values don't match the type or script the wizard expected, which can be intentional), Step 5 offers Import these as-is (keep non-standard values). The column is brought in as text with its values stored exactly as they appear — nothing is coerced or dropped. A DRY RUN card previews the change before you commit: the flagged column moves from skipped to kept, a note states the values are kept as text, a Won't touch list bounds what stays unchanged, and a seal states "No source rows are written until you run the import." This is offered only for advisory flags; a structural problem (a duplicate key, a missing column) must be corrected and is never offered as keep-as-is. If you later undo the decision, it is fully reversed — a subsequent normal approval will not silently re-apply it. Maturity: Active. Limit: a transformation history of the kept column and in-place cell correction are planned, not yet present.
  • Import assistant chat — a chat control on each wizard step that knows where you are in the flow. It can explain what it sees and propose actions, but a proposed action is never executed until you confirm it. Each import session has a chat budget; when the budget runs out the chat pauses and every import control keeps working. Your environment's AI settings can turn the assistant off. Maturity: Active.
  • AI refinement is optional — when no AI provider is configured for your platform, the wizard still works end to end: the structural reading produces the suggestions, and the import is marked that AI refinement was unavailable. To enable AI refinement, contact your platform operator. Maturity: Active.
  • Efficiency tips (Step 3) — short tip cards can appear alongside suggestion cards when tips are enabled for your environment. Tips never block an action. See Efficiency Tips. Maturity: Active.
  • Import telemetry — when capture is enabled, import steps emit operational counts that carry no source content: no rows, filenames, document or table names, credentials, or tokens. See Telemetry. Maturity: Active. Limit: collection runs in the platform; a dedicated screen for browsing these metrics is not yet available.

Usability — how you use it​

  1. Start in the sidebar at Imports & AI → Imports. Step 1 shows the source choices, your recent imports, and your saved setups. The All imports list offers the same upload routes as toolbar buttons.
  2. Submit the source that matches your shape — Excel, database, CSV files, or Coda. Within the inline size limit, the wizard reads the source immediately and opens the review. Above it, choose the background option and follow the status page; it links to the wizard when the job completes.
  3. Walk the six steps. Review what was found (Step 2), decide on suggestions and set how involved you want to be (Step 3), answer the clarifying questions (Step 4), and read the practice run (Step 5).
  4. Approve in two steps. A reviewer approves each suggestion, then an administrator applies it. If the risk level shifted while the suggestion waited, read the new level and acknowledge it before applying.
  5. Start the import (Step 6). Once every suggestion is approved or rejected, Start import becomes available. If your source needs a credential to read rows at import time — a Coda key or a live database password — Step 6 asks for it again and uses it only for that request path. Read the receipt when the run completes, and use Open your workspace to see the results. If a run is interrupted, your setup, approvals, and practice run are kept; starting again resumes from the stopped table, and completed tables are not written twice. For a Coda import that already fetched its rows before being interrupted, retrying replays the saved copy of those rows and does not ask for the one-time key again; if that saved copy is unreadable, the wizard asks for the key rather than failing silently.

Risk levels in plain terms:

LevelWhat it meansWhat happens
LowThe change is additive — a new table meaning, a new field, or no change to anything that exists.Quick lane. Confident low-risk suggestions can move ahead for you, with undo, depending on your autonomy setting.
MediumThe change alters an existing setup that has no imported records yet.Held for review by default. At the two most hands-off autonomy settings, a confident structural reading at this level can also move ahead for you, with undo.
HighThe change alters a setup that already has imported records, or removes or merges whole tables.Held for explicit confirmation even after reviewer approval. Never applied automatically. A second pair of eyes is expected.

Re-importing source data​

Re-importing a source you have brought in before is a normal operation:

  • The wizard recognizes the saved setup, carries your unchanged decisions forward, and asks only about what is new or changed.
  • For refreshing the records themselves, the platform supports two behaviours. Edit-preserving refresh matches incoming rows to existing records by their source identity, refreshes the values the source manages, and keeps researcher edits to fields the source does not manage — the right default for routine re-runs. Full refresh wipes the existing rows and reloads from scratch — destructive to researcher edits, only for genuine start-over situations. If you are unsure which behaviour a planned re-import will use, check with your platform operator before running it.

SymptomLikely causeFix
The imports list is emptyNo imports have been started yetStart from Imports & AI → Imports, or use the upload buttons on the All imports toolbar.
"Add" opened a bare form that does nothing usefulThe plain admin "Add" form does not read a sourceClose it and start from an upload route. The wizard only opens for imports created through an upload.
The wizard says AI suggestions were unavailableNo AI provider is configured for your platformThe structural reading still produced suggestions — review them as usual. To enable AI refinement, contact your platform operator.
A re-import overwrote researcher editsA full-refresh re-import replaced the rows instead of an edit-preserving refreshContact your platform operator to restore from your environment's backup, then re-run as an edit-preserving refresh.
An upload was refused as too largeThe file exceeds the inline limit for its source typeResubmit with the background option. Background limits: Excel 100 MB; MySQL dump 500 MB; CSV 50 MB per file and 250 MB total.
Apply is blocked, asking you to acknowledge a risk changeThe risk level was re-assessed at apply time and differs from when the reviewer approvedRead the new level and its reason. Acknowledge it to proceed, or reject the suggestion and revisit it.
A Coda or saved-database re-import fails with a credential errorThe saved connection's secret reference could not be resolvedCheck the saved connection in your environment. If the secret is held in the platform's secret store, contact your platform operator.
Several suggestion cards target the same findingEach finding should produce exactly one suggestionThis should not happen. Contact your platform operator.

Your work is preserved; no re-upload is needed.

Restart only after the run reports failure or your platform operator confirms the worker stopped.
