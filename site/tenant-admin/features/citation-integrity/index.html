Citation Integrity and DOI Safety

Audience: Tenant administrator; secondary readers: prospective tenant institutions, Data Protection Officers, IRB reviewers, library/repository partners considering DOI minting via the platform, scholarly editors planning peer-reviewed publication of platform-cited research. Last aligned with platform state: 2026-05-25 Platform version: V2 (pre-1.0)

Purpose​

When a researcher in your environment ratifies a binding set on a media artifact — saying "these terms correctly describe these regions of this artifact" — and a DOI is minted on top of that ratified state, the platform structurally guarantees the cited data cannot silently change. Background re-extraction runs are refused at the database layer. False-positive bindings researchers reject stay rejected across re-runs. Read this when evaluating the platform for a peer-reviewed publication or DOI-minted scholarly artifact, or when answering an institution's editorial / DPO / library question about how citation integrity is enforced.

This page explains the guarantees in plain language. The deeper engineering reference lives in ADR-022; the operational reviewer surface that produces ratified state is the Media Review Surface.

Features​

  • Three-layer artifact identity — Layer 1 citable identity (the publishable artifact name + optional DOI / Zotero / institutional handle), Layer 2 platform-internal UUIDs (never published), Layer 3 locator (the artifact's natural self-description: glTF node names, IIIF region selectors, TEI @xml:id values). Substrate: ADR-022 §A.1 · Maturity: Active · Limit: the platform never rewrites the artifact file at ingest; Layer 2 UUIDs are never published.
  • REVISION / EDITION artifact-version primitive — every binding set is either a mutable REVISION (working copy) or a frozen EDITION (citable, peer-review-targetable). Substrate: ADR-022 + ArtifactVersion.kind · Maturity: Active · Limit: an environment may carry many REVISIONs for the same artifact; promoting to EDITION is a deliberate operation gated by the admin role.
  • promoteRevisionToEdition GraphQL mutation — the explicit transition; once promoted, the artifact-version is structurally protected against re-extraction. Substrate: ADR-022 + atlomyapp/graphql/schema.py · Maturity: Active · Limit: requires admin role; the modal lives on the Media Review Surface.
  • Edition-frozen re-extraction guard — the data layer rejects any ingest_3d_model_glb run that would mutate an EDITION-kind ArtifactVersion; raises a hard CommandError. Substrate: ADR-022 hardening + atlomyapp/management/commands/ingest_3d_model_glb.py:362-373 · Maturity: Active · Limit: structural — not a warning, not a log line; the pipeline stops before any anchor or attestation is touched.
  • STRIP soft-delete tombstone — markAttestationOverride(action: STRIP) flips the attestation's status to STRIPPED rather than deleting the row, so re-extraction recognises the rejection and refuses to re-propose. Substrate: ADR-022 hardening + atlomyapp/graphql/schema.py:1040-1095 + atlomyapp/management/commands/ingest_3d_model_glb.py:454-469 · Maturity: Active · Limit: markAttestationOverride.deleted returns false for STRIP — a backward-incompatible change for any client that branched on deleted.
  • Researcher-override preservation within REVISIONs — APPROVE and AMEND set metadata.researcher_override = true; the data layer's re-extraction skip rule preserves the row's contents across re-runs. Substrate: ADR-022 + tests/integration/test_researcher_override_preserved_across_revisions.py · Maturity: Active · Limit: applies to attestations the researcher has touched; untouched auto-extracted attestations remain mutable in REVISION mode.
  • Per-row attribution metadata — every researcher action writes researcher_action, researcher_actor, researcher_timestamp, optional researcher_note to the attestation's metadata JSONB; never deleted or rewritten by re-processing. Substrate: ADR-022 + EntityRelationship.metadata · Maturity: Active · Limit: audit-grade durable trail; for formal audit log separate from per-row metadata, see Telemetry.

Usability — how you use it​

The structural guarantees described here are produced by actions taken on the Media Review Surface; this page describes what those actions mean for citation.

  • Promote a citation-ready revision to an Edition: open the Media Review Surface for the artifact, confirm the attestations are correct, click Promote to Edition (requires admin). Provide the Edition label, optional DOI, optional notes. The modal confirms that downstream re-extraction enforcement is structural once promoted.
  • Mint a DOI against an Edition: the platform does not mint DOIs. It exposes the Edition's stable identity (artifact_external_id + version_label + EDITION-kind status) so an external minter — your institutional library, OJS instance, Crossref membership, DataCite tenant, or repository system — can target it.
  • Strip a false-positive binding durably: on the Media Review Surface, click STRIP on the wrong attestation. The row remains as a tombstone; future re-extractions recognise the rejection and refuse to re-propose. Pre-hardening behaviour (hard delete) is gone.
  • Update the artifact file under an active citation: explicitly bump to a new --version-label REVISION on the ingest command. The original EDITION's data and any DOI minted on it remain intact; the new REVISION can be reviewed on its own merits and (if appropriate) promoted to a new EDITION later.

The platform does NOT:

  • Mint DOIs — that is your institution's library / repository system.
  • Host published papers — the platform is the underlying scholarly substrate.
  • Track citation usage statistics — that is institutional bibliometrics.
  • Implement embargo or paywall workflows — REVISIONs and EDITIONs are not access-controlled by date. Hold the EDITION promotion in a private workflow if you need an embargo.

Troubleshooting​

SymptomLikely causeFix
You ran ingest_3d_model_glb on an artifact-version and got ArtifactVersion(...) is frozen for citationThe artifact-version is an EDITION; the data layer refused to mutate itThis is the structural guarantee working as designed. Bump --version-label to a new REVISION and re-run; the original EDITION stays intact.
A researcher stripped an attestation last week, but the latest re-extraction proposed it againThis should not happen — STRIP is a tombstone preserved by the skip ruleFile an issue including the artifact UUID and the stripped edge id. The skip rule is structural per ADR-022 hardening; a regression would be a substrate bug.
A client integration broke when STRIP returned deleted: falseThe post-hardening change returns false for soft-delete; backward-incompatible for clients that branched on deletedConsume status from the response instead. The STRIPPED status is the durable signal.
Promote to Edition is missing or disabledThe page did not resolve an ArtifactVersion, or your role lacks adminConfirm the artifact has at least one ArtifactVersion; verify your role assignment in Permissions Panel.
You need to embargo an Edition until publicationThe platform does not implement embargo workflowsHold the EDITION promotion in a private workflow until the embargo lifts, then promote. The platform does not access-control REVISIONs and EDITIONs by date or visibility tier.
Audit reviewer asks for a formal audit log separate from per-row metadataPer-row metadata is durable but lives on the attestation rowThe platform's telemetry substrate (see Telemetry) provides a separate append-only log of operations including per-attestation override events.
