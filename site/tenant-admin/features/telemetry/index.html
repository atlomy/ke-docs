Telemetry and Privacy

Audience: Tenant administrator; secondary readers: prospective tenant institutions, Data Protection Officers, IRB reviewers. Last aligned with platform state: 2026-05-25 Platform version: V2 (pre-1.0)

Purpose​

The platform collects a deliberately small set of operational signals about how it runs — never a copy of your research content. This page tells you what those signals are, where they live, how long they are kept, what you control, and what to tell an institutional DPO or IRB. Read this when onboarding under a Data Processing Agreement, when an institution's information-security team asks the standard onboarding questions, or before enabling any optional capture (the default posture is capture-off).

The platform is GDPR-aligned by design; the collection posture meets EU university DPO and US academic-IRB expectations.

Features​

  • AI-call records — per-call structured shape: task + model + version, tokens + latency, structured artifact, one-way hashes of prompt and response, refusal / escalation flag, prompt-injection classifier verdict. Substrate: ADR-016 + epistemic/services/proposals/ · Maturity: Active · Limit: NOT recorded — raw prompt text, raw response text, end-user identity beyond platform pseudonym.
  • Search-quality records — zero-result rate, aggregate query patterns (K≥5 only), cross-script statistics. Substrate: ADR-016 · Maturity: Active · Limit: raw query strings off by default; opt-in only with DPO sign-off captured in the configuration. K-anonymity floor (default 5; configurable to 11) suppresses long-tail queries. SSN/email/phone patterns are dropped entirely.
  • Ingestion / pipeline records — tenant + source format, entity counts before / after, materializer outputs, error classes (not values), wall-clock duration. Substrate: ADR-016 + Spec 0011 import wizard ingestion telemetry · Maturity: Active · Limit: contains no personal data by construction; deliberately does not record raw source rows, filenames, staged paths, job ids, document/table names, or credential references.
  • Decision-event records — reviewer reject / undo / post-apply edit / feedback-button signals on proposal review. Substrate: Spec 0018 + Spec 0030 + epistemic/models.py DecisionEvent · Maturity: Active · Limit: records proposal id, structured reason code, source signal, risk/review stratum, tenant-keyed HMAC proposal-shape fingerprint, optional batch counts. Does not record raw reviewer comments or free-form rationale.
  • Tip-event records — TipEvent plus aggregate tip_family_acceptance_ratios; supports the Efficiency Tips surface. Substrate: Spec 0030 Phase 6.A–6.D + TIP_AUTO_PAUSE event type · Maturity: Active · Limit: k-anonymity-floor clamped via TIP_ROLLUP_MIN_K (R3 absorption, 2026-05-25); no per-researcher attribution.
  • Vocabulary-pack consumption events — VocabularyConsumptionEvent for telemetry correlation. Substrate: ADR-044 D.3.14 (PR fc0c3ba5, 2026-05-25) · Maturity: Active · Limit: tenant-local; no content payload.
  • Per-environment retention controls — retention_overrides JSONB on Client carries per-signal-class day counts shorter than platform defaults (cannot be longer). Substrate: ADR-016 · Maturity: Active · Limit: shorter than default only; the platform maximum is the ceiling.
  • /admin/monitoring/telemetry/ panel — first tenant-admin telemetry UI; shows current-tenant signal counts, suggestion-quality bars, paused auto-apply categories, vocabulary-derived labels for how the system is learning. Substrate: Spec 0018 Sprint C tenant telemetry (PR 8b25fc58, 2026-05-20) + threshold chart (PR 7b37fcb3, 2026-05-21) · Maturity: Active · Limit: reads only tenant-local telemetry / ledger rows; never displays raw source rows, filenames, staged paths, credential references, tokens, or job ids.
  • dump_telemetry management command — tenant-scoped export to JSON Lines + signed manifest for GDPR Article 15 access requests. Substrate: ADR-016 · Maturity: Built · Limit: tenant-scoped; produces an audit-grade manifest.

Usability — how you use it​

The day-to-day operator surface is /admin/monitoring/telemetry/. The configuration that controls capture lives on the Client row in the customers admin.

  • Read what is happening in your environment: open /admin/monitoring/telemetry/. The page shows current-tenant signal counts, the suggestion-quality bars, paused auto-apply categories, and vocabulary-derived labels. Filter by time window, source format, signal class, success/failure.
  • Configure retention shorter than default: edit the Client row's retention_overrides JSONB to specify shorter day counts per signal class. The platform maximum is the ceiling; the overrides cannot exceed it.
  • Enable opt-in raw search-query buffer: set search_query_raw_optin = True on the Client row with DPO sign-off captured. The buffer auto-deletes after 60 minutes idle, with a 24-hour absolute cap. After flush only hashed forms survive in the rollup table.
  • Configure FERPA-compliant pseudonymous mode: set is_used_for_coursework = True to suppress identifiable per-user logging entirely.
  • Set residency: telemetry_residency = "eu" | "us" | "default-strictest" on the Client row. Default is default-strictest (EU storage for mixed-affiliation environments).
  • Honour a GDPR Article 15 access request: run dump_telemetry --schema <your_schema> to produce the JSON Lines + signed manifest export. Hand to the data subject.
  • Honour a GDPR Article 17 erasure request: see the right-by-right table below; the active-session buffer is deleted on request; tenant-schema events are pseudonymised in-place; hashed K-anonymized rollups are retained as anonymous aggregates.

Where the data lives​

Each environment runs in its own database schema; PostgreSQL enforces the isolation. Telemetry honours it:

DataWhere it livesWho can read it
AI-call records (structured shape, hashes)Your environment's schemaYou; platform team (read-only, for support)
Search query buffer (raw, opt-in, TTL'd)Your environment's schemaYou; never the platform team
Hashed search rollup (always-on, K-anonymized)Your environment's schemaYou; platform team only as anonymous aggregate
Ingestion-run recordsYour environment's schemaYou; platform team (read-only)
Decision-event recordsYour environment's schemaYou; platform team (read-only)
Cross-environment operational metrics (cost, latency, model name)Public schema; never your contentPlatform team only

Retention defaults​

DataDefault retention
AI-call records (structured shape)30 days verbatim, then 12 months as hashed/aggregate
Search query buffer (raw, opt-in)60 minutes idle; 24 hours absolute cap
Search query rollup (hashed, K-anonymized)30-day rolling window, re-aligned to the annual key rotation
Ingestion-run records12 months
Validation / abuse audit (security-relevant)2 years (GDPR Art. 17(3)(e) — defence of legal claims)
Confirmed prompt-injection raw bytes (S3 quarantine)90 days; legal-hold flag for indefinite retention on specific incidents

These defaults are calibrated against ICO/EDPB operational-log guidance, ISO/IEC 27001:2022 control A.8.15, EU AI Act Article 19, and the relevant AI-provider Usage-Policy retention ceilings.

GDPR rights​

RightHow the platform handles it
Access (Art. 15)Tenant-scoped dump_telemetry export — JSON Lines + signed manifest.
Rectification (Art. 16)Not applicable to operational telemetry. For environment content, rectification flows through the standard editing surface.
Erasure (Art. 17)Buffer purge: yes. Tenant-schema events: user-identifying rows pseudonymised in-place with a tombstone token (Art. 17(3)(b)/(e)). Hashed K-anonymized rollups: retained as anonymous aggregates (EDPB 2025 + Art. 17(3)(d)).
Restriction (Art. 18)Per-user opt-out flag suppresses verbatim telemetry; anonymous aggregates preserved.
Portability (Art. 20)Same export format as Article 15.
Object (Art. 21)Per-user via opt-out flag; environment-level objection deconfigures the signal class entirely.
Automated decision-making (Art. 22)The platform does not make automated decisions with legal or significant effects on data subjects. AI calls are advisory; researcher review gates any production change.

Lawful basis is Legitimate Interest (Art. 6(1)(f)) with documented LIA per signal class. DPIA runs before production capture; annual refresh; per-environment on request.

Third-party exposure​

Third partyWhat they see
AI provider (e.g. Anthropic when routed through AWS Bedrock)Nothing. Bedrock is the trust boundary.
AWSBedrock invocation logging is OFF by default. AWS sees the API call envelope (model + IAM role + timestamp), not payload.
Platform teamRead-only access to your environment schema for support; full access to public-schema cross-environment metrics (cost, latency — never your content).
Anyone elseNothing. No third-party analytics, advertising, or telemetry SaaS.

Offboarding​

When an environment offboards: the schema is dropped (all payload deleted); hashed K-anonymized rollups are deleted with the schema; cross-environment operational metrics (cost, latency in the public schema) are retained for cost-history continuity, but the tenant_id is rewritten to a stable opaque hash. Non-default offboarding can delete the anonymous metric trail too; the trade-off is loss of platform-level cost-trend continuity for the windows that environment participated in.

Troubleshooting​

SymptomLikely causeFix
/admin/monitoring/telemetry/ shows no signalsCapture is off (the default); or the relevant signal class is not yet wired in productionEnable capture per signal class with DPO sign-off captured. DecisionEvent capture paths (reject, undo, post-apply edit, feedback) are wired; LLM-call and search-quality production callers may be separately staged.
You see ExternalCredentialUnavailable in ingestion telemetryA credential reference (AWS Secrets Manager or ExternalServiceCredential) resolved to an unavailable secretCheck the ExternalServiceCredential row and the AWS secret. The telemetry recorded an upload-boundary outcome only; no raw credential material is in the telemetry row.
A DPO asks for the LIA per signal classThe Legitimate Interest Assessment is per-signal-classProvide the relevant section of ADR-016 + the documented LIA. For specific signal classes, the platform team can supply the LIA on request.
An institution requires AWS Sovereign Cloud residencyThe platform supports it as a documented one-way doorTrigger configuration at first request from an environment whose contract requires it. The default residency is default-strictest.
A researcher exercises the right to be forgottenRouting depends on the data classActive-session buffer: DELETE rows for the session id. Tenant-schema events: pseudonymise in-place with the tombstone token. Hashed K-anonymized rollups: retained as anonymous aggregates (EDPB 2025 position).
You want to verify no raw queries are storedThe opt-in raw query buffer is off by defaultInspect the Client row's search_query_raw_optin value. Confirm False. The hashed rollup is HMAC-SHA-256 with a per-environment key, rotated yearly.
