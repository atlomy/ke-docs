AI-Assisted Vocabulary Bootstrap

Audience: Tenant administrator. Last aligned with platform state: 2026-05-25 Platform version: V2 (pre-1.0)

Purpose​

A new environment starts with no grounded entries, no derived entries, no AI-reviewed entries. Until the safety-floor gate is satisfied, researchers cannot author. The AI-assisted bootstrap workflow generates an initial set of vocabulary proposals — derived from your archetype configuration and any source data already imported — for you to review, accept, or reject in one pass. Read this when onboarding a greenfield environment and you do not want to author every vocabulary entry from scratch.

This is a one-pass workflow. After bootstrap, the live Voice and Vocabulary surface owns maintenance and extension.

Features​

  • BootstrapProposal rows — per-row AI proposal, one per proposed vocabulary entry, carrying the canonical key, proposed surface form, originating rule or heuristic, and confidence. Substrate: Spec 0029 + ADR-044 §3 + customers/services/vocabulary_bootstrap.py · Maturity: Active · Limit: proposals live only until the bootstrap commit; not part of the live vocabulary substrate.
  • generate_bootstrap_proposals service — produces the initial proposal set from archetype configuration and imported data; rule-based as of Phase 5.A. Substrate: ADR-044 Phase 5 (PR 1c70eb30, 2026-05-25) · Maturity: Active · Limit: rule-based and discipline-priors today; richer model-based proposals are deferred.
  • commit_accepted_proposals atomic commit — writes every accepted proposal as a TenantVocabularyEntry with status ai_reviewed in a single transaction. Substrate: Spec 0029 design.md "atomic commit" · Maturity: Active · Limit: all-or-nothing; partial commits do not happen.
  • HMAC ai_suggestion_id provenance — tamper-evident reference attached to each committed entry, pointing back to the originating BootstrapProposal. Substrate: ADR-044 D.3.13 (HMAC shape validation) · Maturity: Active · Limit: tamper-evident, not encrypted.
  • Discipline-priors chat shim — Phase 3 extract-only transient broker that elicits discipline context before proposing. Substrate: ADR-044 D.3.12 + Spec 0029 Phase 3 (PR 0485a522, 2026-05-25) · Maturity: Active · Limit: extract-only — no chat transcript persists beyond the bootstrap session.
  • Full 4x safety-floor matrix coverage — bootstrap generator emits proposals across all four canonical-key archetype lanes. Substrate: ADR-044 Phase 6.E (PR 5d99a13a, 2026-05-25) · Maturity: Active · Limit: matrix shape is fixed by the archetype substrate.

Usability — how you use it​

The bootstrap surface appears in the Django admin during onboarding and disappears after the commit.

  • Review proposals: the surface lists BootstrapProposal rows. Each row shows the canonical key, the proposed surface form, the rule or heuristic that produced it, and a confidence indication. Per-row actions are accept, reject, or edit-and-accept.
  • Edit-and-accept: adjust the proposed wording inline before accepting. The edited form is what gets written to the vocabulary entry.
  • Watch the summary header: pending count, accepted count, and an indicator of whether the accepted set is sufficient to unlock the safety-floor gate.
  • Commit: click the atomic commit action at the bottom. Every accepted proposal is written as a TenantVocabularyEntry with status ai_reviewed in one transaction; failure rolls back cleanly, success unlocks downstream gate checks.
  • Audit afterwards: open the Audit tab in Permissions Panel. Each committed entry carries an ai_suggestion_id you can trace back to its proposal.

After bootstrap, you can upgrade ai_reviewed entries to grounded later through the Vocabulary Grounding workflow without losing the original AI provenance.

Troubleshooting​

SymptomLikely causeFix
The bootstrap commit failed and no entries were writtenThe atomic transaction rolled back; the surface shows the failure reasonRead the surface message. Common causes: a canonical key conflict (an entry already exists for that key), a HMAC shape validation failure, or a database write error. Fix the conflict and re-commit.
The safety-floor gate is still closed after a successful bootstrap commitThe accepted proposal set does not cover the canonical keys the gate requiresThe summary header should have told you this before commit. Add or accept more proposals; alternatively ground existing entries via the Vocabulary Grounding workflow.
The bootstrap surface generated very few proposalsThe archetype configuration is sparse or no source data has been imported yetEither import some source data so the rule-based generator has more to work from, or author vocabulary entries directly through the live vocabulary surface; bootstrap is one tool among three (grounded / derived / AI-reviewed).
You see proposals for canonical keys that are not relevant to your environmentThe rule-based generator emits the full 4x safety-floor matrix; some keys may not apply to your archetype shapeReject the irrelevant proposals; they do not commit unless explicitly accepted.
The bootstrap surface is gone but you still need to add AI-reviewed vocabularyBootstrap is a one-pass onboarding workflowUse the live vocabulary surface for any post-onboarding additions. The ai_reviewed status is reachable from the live surface as well when a proposal flow is exposed.
