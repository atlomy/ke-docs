Media Review Surface

Purpose​

Reviewing a media artifact's attestations — confirming or correcting which part of the artifact maps to which term, adding bindings the automatic extractor missed, re-running the extractor, and pinning a working revision as a citable Edition — happens inside the workspace, on the media record's detail pane. Read this when reviewing a freshly ingested media artifact, when the extractor proposes bindings that look wrong, or when you are ready to pin a revision as an Edition.

Two terms used throughout: an anchor is an addressable point inside the artifact (for a 3D model, a named node in the model file), and an attestation is the recorded link between an anchor and a term in your environment. The guarantees described in Citation Integrity rest on the review decisions you take here.

The standalone admin review page (formerly at /admin/.../media-review/) has been retired — all of its review, re-extraction, and Edition-pinning actions now live on the workspace media detail pane described below. If you have an old bookmark to that page, open the record from the workspace Media view instead.

Where it is​

Open the Media view on a media table (it appears only on MEDIA tables), then open a record from the gallery. Its detail pane opens with the model rendered inline and a rail of tabs:

  • Mesh→term — the review surface: each part of the model with the term it is matched to, a state chip, and per-part actions.
  • Files — the artifact's stored files.
  • Viewer (admins) — sets the model's opening camera framing as a live presentation default.
  • Info — read-only record details.
  • Version (admins) — pin a working revision as a citable, frozen Edition, or re-extract the mesh→term bindings.

The researcher-facing walkthrough of the Mesh→term tab is in the See which mesh maps to which term help topic; tuning the camera is in Tune the 3D camera view.

Features​

  • Mesh→term review — the Mesh→term tab lists each part of the model with the term it is matched to and a state chip: auto (extracted, awaiting review), edited (you changed an existing binding), linked (you bound a previously-unmapped part), or unmapped — above counts of how many parts are mapped, edited, and auto. Selecting a part, in the list or in the model itself, highlights it on both sides and opens its card. Maturity: Active.
  • Per-part Approve / Reassign / Strip — Approve confirms an auto binding as correct (shown only while the part is auto); Reassign / Assign term opens a picker to bind the part to a term (search the vocabulary by typing and choose a result by its display label, or paste a term record's id); Strip clears the term, leaving the part unmapped. Every action is recorded with your name and a timestamp. Maturity: Active. Strip is a recorded rejection, not a deletion: the decision is kept so a later re-extraction cannot silently re-propose the same binding.
  • Manual attestation add — bind a part the extractor missed via the term picker: a typeahead searches the term records in your environment as you type, or paste a term record's id directly. Maturity: Active. The typeahead depends on search being activated for your environment; the paste path works regardless.
  • Re-extraction dry run and apply — on the Version tab, re-run the extractor against the same artifact, first as a dry run that reports what would change without writing anything, then as an apply. The job runs in the background and the tab polls its status. Maturity: Active. The status is overall job status only — queued, running, succeeded, or failed — not step-by-step progress. Requires the Admin role. Re-extraction is refused once the version is a frozen Edition.
  • Edition pinning — on the Version tab, pin a working revision as a citable Edition with an Edition label. Maturity: Active. Requires the Admin role. Once pinned, the Edition is frozen: the platform refuses any re-extraction against it. (Everyday citeability is automatic; pinning is the deliberate-permanence act.)
  • Reviewer-decision preservation — approvals, reassignments, strips, and manual additions are all marked as reviewer decisions and survive re-extractions; the extractor never silently overwrites them. Maturity: Active.

Usability — how you use it​

Open the workspace, open a media table's Media view, and open a record from the gallery. Review actions and manual bindings require the Editor or Admin role in your environment; re-extraction and Edition pinning require Admin — the workspace hides the admin-only actions when your role cannot perform them, so you never dead-end on a permission error.

The common review paths:

  • Approve a correct binding: select the part, then Approve. The decision is recorded with your name and timestamp, and future re-extractions leave the binding alone.
  • Reassign or bind a part: select the part, then Reassign / Assign term; search the term by typing and choose a match, or paste the term record's id.
  • Strip a wrong binding: select the part, then Strip. Your rejection is recorded, and the extractor's next run will not re-propose the same binding.
  • Re-extract: on the Version tab, dry run first — the job runs in the background and the tab polls its status until it succeeds or fails — compare the report against the current state, then apply (apply asks for confirmation, because it writes new anchors and attestations).
  • Pin an Edition: on the Version tab, pin the working revision and enter the Edition label. After pinning the Edition is frozen — further extraction work requires a new working revision.

The mesh→term counts refresh after each action, so the tiles always reflect the decisions you have taken so far.

Troubleshooting​

SymptomLikely causeFix
The Media view does not appear on a tableThe table's records are not the MEDIA archetypeThe Media view appears only on MEDIA tables. Confirm the table holds media records.
The model does not render in the detail paneThe media record has no resolvable primary fileThe pane needs the artifact's stored primary file. Confirm the record was ingested completely; the rest of the pane still works for reviewing existing bindings.
The re-extraction actions are disabled or refuseThe current version is a frozen Edition, or the record has no resolvable source fileRe-extraction is refused on a frozen Edition — start a new working revision by re-importing. If the record has no source file, add it.
The term picker returns no matches for a term you know existsSearch has not been activated for your environment, or the search found nothing for your queryThe picker shows a hint when this happens; paste the term record's id directly — the picker works regardless of search state. To get search activated for your environment, contact your platform operator.
The Version tab's pin/re-extract actions are missingYou do not have the Admin roleEdition pinning and re-extraction require Admin. Review and binding actions are available to Editors.
You stripped a binding but the next extraction proposed it againThis should not happen — a strip is durable across re-extractionsContact your platform operator with the artifact id and the details of the stripped binding.
