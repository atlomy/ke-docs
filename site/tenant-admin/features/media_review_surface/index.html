Media Review Surface

Audience: Tenant administrator and reviewers validating media artifact attestations. Last aligned with platform state: 2026-05-25 Platform version: V2 (pre-1.0)

Purpose​

The media review surface is a single page where you review every attestation tied to one media artifact-version, add manual attestations the auto-extractor missed, dry-run a re-extraction before applying, and promote a working revision to a citable Edition. Read this when reviewing a freshly ingested media artifact, when an auto-extractor proposes false-positive bindings, or when you are ready to promote a revision to an Edition so a DOI can be minted against it.

Every action on this page is a single mutation against the GraphQL surface. Results refresh automatically. The structural Citation Integrity guarantees rely on the actions taken here.

Features​

  • Attestation summary card — anchor count, attestation count, mapped / unmapped / overridden / auto / orphan tiles, last-extracted timestamp. Substrate: Spec 0012 + ADR-022 Phase 5 · Maturity: Active · Limit: counts are scoped to the resolved artifact-version.
  • Per-row APPROVE / STRIP / AMEND actions — one row per EntityRelationship; each action is a markAttestationOverride GraphQL mutation. Substrate: Spec 0012 + ADR-022 + atlomyapp/graphql/schema.py · Maturity: Active · Limit: STRIP is a soft-delete (status STRIPPED), not a hard delete — preserved across re-extractions per ADR-022 hardening.
  • Manual attestation add — adds an attestation the auto-extractor missed; TERM typeahead over your environment's searchable TERM slots, optional anchor durable id, optional note. Substrate: Spec 0012 + atlomyapp/graphql/schema.py addManualAttestation · Maturity: Active · Limit: searchable slots are per-environment per TenantArchetypeFormConfig; the picker falls back to raw UUID paste when the search profile is unratified or returns nothing.
  • Re-extraction dry-run and apply — triggerReExtractionAsync(apply=false|true); returns a tenant-scoped job id; the panel polls job status. Substrate: Spec 0014 (async wiring) + Plan 4 Track A · Maturity: Active · Limit: status states only (queued, running, succeeded, failed); no granular progress events.
  • Edition promotion modal — promotes a working revision (REVISION) to a citable Edition (EDITION); requires Edition label, optional DOI, optional notes. Substrate: ADR-022 + promoteRevisionToEdition mutation · Maturity: Active · Limit: requires the admin tenant role; structural enforcement against further re-extraction kicks in immediately on promotion.
  • Researcher-override preservation — APPROVE and AMEND set metadata.researcher_override = true; STRIP sets status STRIPPED; both are preserved across re-extractions. Substrate: ADR-022 hardening + atlomyapp/management/commands/ingest_3d_model_glb.py · Maturity: Active · Limit: tested by tests/integration/test_researcher_override_preserved_across_revisions.py.

Usability — how you use it​

The page is reachable two ways once the substrate is deployed:

  • Direct URL: /admin/epistemic/epistemicentity/<uuid>/media-review/ where <uuid> is the MEDIA EpistemicEntity id.
  • Deep link from the change form: open any MEDIA entity at /admin/epistemic/epistemicentity/<uuid>/change/; a banner above the viewer preview reads "Media review · Review attestations for this artifact →"; click through.

Access requires Django admin auth; mutations require the editor or admin tenant role; Edition promotion requires admin. Anonymous requests redirect to admin login.

The common operator paths:

  • Approve a correct binding: click APPROVE on the row. The row stays in place; the metadata records actor, timestamp, and the researcher_override flag. Future re-extractions skip this row.
  • Strip a wrong binding: click STRIP, confirm. The row stays as a tombstone (status STRIPPED); the auto-extractor's next run will not silently re-propose the same binding.
  • Amend with a note: click AMEND, write the note, save. The row stays in place; the override flag plus your note preserve the binding across re-extractions.
  • Add a missing attestation manually: open the manual-add modal, type at least 2 characters of a TERM, select from the typeahead (or paste a UUID), optionally provide an anchor durable id and a note, save. The new row carries metadata.source = 'researcher_manual' and researcher_override = true.
  • Dry-run a re-extraction: expand the re-extraction panel, click Dry run. The job runs in the background; the panel polls status. Compare the dry-run output against the current state before applying.
  • Promote to Edition: click Promote to Edition (right side of the action bar). Enter the Edition label, optional DOI, optional notes. Confirmation reminds you that downstream re-extraction enforcement becomes structural on promotion.

Troubleshooting​

SymptomLikely causeFix
The page errors on loadThe MEDIA entity is missing required data fields, or the bundle could not parse data-* attributesCheck the browser console for media_review: messages (the bundle reports missing fields loudly). Confirm the MEDIA entity carries the required structural fields.
The re-extraction panel is disabledThe MEDIA entity is missing the source-file pointer (e.g., data['Model URL'] for glTF)Re-extraction needs the source file. The rest of the page still works for review of existing attestations.
TERM typeahead returns no matches for a term you know existsThe environment's TenantSearchProfile is unratified, or the indexer returned nothing for your queryThe picker shows a "No matches — paste an entity UUID instead" hint when this happens; paste the entity UUID directly. The modal works regardless of search-profile state.
Promote to Edition button is missingThe page did not resolve an ArtifactVersion, or your role lacks adminConfirm the artifact has at least one ArtifactVersion (the ingest pipeline creates one). For role: verify in Permissions Panel.
You see UnratifiedSearchEngineError when adding a manual attestationThe TERM typeahead consulted the indexer; the indexer requires a ratified search profileEither ratify the search profile (separate operator step) or paste the entity UUID into the modal.
A re-extraction job has been "running" for a long timeAsync wiring polls until terminal status; large artifacts can take several minutesWait. The job's status will transition to succeeded or failed. Granular progress is not available; the management command does not emit progress events.
You stripped a binding but the next ingest run proposed it againThis should not happen — STRIP is a tombstoneFile an issue including the artifact UUID and the stripped edge id. The data layer skip rule for STRIPPED status is structural; a regression here would be a substrate bug.
