Vocabulary Review

Purpose​

Vocabulary Review is where a researcher decides how the project should treat date wording that the platform deliberately did not guess at. The queue keeps the value exactly as written, shows any deterministic reading beside it, and offers a direct choice: save that reading, ask for an advisory AI reading, enter the dates yourself, or keep the value as written.

There is no proposal-and-approval step inside this page. A saved choice is the review decision. Closing the dialog with its close control or Escape cancels without changing the row.

Access​

Open the workspace account menu, then choose Schema & definitions → Vocabulary review. The page opens inside the shared workspace at /app/workspace/manage/vocabulary.

Access follows the project-wide Review suggestions permission, not the name of a person's role. An active viewer, editor, or administrator can use the page when that permission applies across the whole project. A role whose permission is limited to particular record types or fields does not gain access to this tenant-wide queue. If the menu item is absent, ask a project administrator to check both the permission and its scope in the Permissions Panel.

Old bookmarks under /admin/vocabulary/ and /temporal-review/ redirect to the workspace page while preserving their filters. Use the workspace address for new bookmarks.

What the queue shows​

  • One row per distinct value — repeated occurrences are reviewed once; the row shows how many records contain the value.
  • What the platform read — recognized bounds, machine-readable EDTF, and a plain status are shown without rewriting the source wording.
  • Near-duplicate groups — readings within one year of each other are shown together for comparison, but remain separate decisions.
  • Only work still awaiting a decision — after a successful decision, the row leaves the queue and the live counts update.
  • Explicit failure and partial-result messages — a failed save keeps the dialog open. If a saved decision reaches only some occurrences, the page reports what still needs attention.

Review a value​

  1. Choose Review on the row. The dialog opens on the original value, which remains read-only and is labelled “as written — kept exactly.”

  2. Choose one of the three paths:

    • What we read shows the deterministic parser's result. If its dates are correct, choose Save this match.
    • AI suggestion requests one advisory reading for this value. Nothing is saved automatically. Choose Accept, Edit first, or Reject after checking the result and any linked authority.
    • Enter it yourself lets you state a start year, optional end year, BCE/CE, precision, date kind, and period label, then choose Save these dates.

  3. Confirm the timeline used for comparison when the dialog asks for it. A calendar label describes the source; it never silently converts the years onto another timeline.

  4. To keep the wording without an operable date, choose Leave as written. This is a recorded decision and removes the row from the active queue. To make no decision, close the dialog instead.

The original wording is preserved on every path. Accepting a reading creates a tenant-owned vocabulary declaration and fans that decision out to matching live occurrences where the platform can do so without inventing missing date semantics.

AI and external sources​

The AI tab is advisory and loads only when opened. AI suggestions are off by default for each project and are bounded by the project's token budget. If AI is off, the budget is exhausted, the field is restricted, validation fails, or an authority cannot be reached, the dialog says so and manual review remains available.

External authority lookup is fail-closed. Values that do not pass the privacy and vocabulary checks are not sent outside the project. A linked authority is evidence to review, not an automatic decision.

Current limits​

  • The shared page currently presents a date-shaped review experience. The backend also tracks other vocabulary categories, but an in-page category switcher and category-specific review forms are follow-up work. Register and Custom values on a keyed column are not reviewed here yet — their "Manage" link in the column's per-record editor goes to the column's own field settings instead. See Field configuration.
  • The queue itself shows values still awaiting review; it is not a history browser for completed decisions.
  • A column-context link can offer Match these dates to run a complete census for that declared column. The general workspace menu opens the project-wide queue and does not show that column action.
  • A column that behaves like unbounded free text is refused as a bulk vocabulary census. Deterministically readable dates remain usable; the page explains that nothing was queued from the open-ended tail.

Troubleshooting​

SymptomLikely causeFix
Vocabulary review is missing from the workspace menuYour active membership does not have project-wide Review suggestions permissionAsk a project administrator to check the permission and remove any record-type or field scope from that capability.
The page says it could not load the queueYour session expired, access was revoked, or the request failedRefresh once. If it persists, sign in again or ask an administrator to confirm your access.
Saving fails and the dialog stays openThe decision was refused, access changed, or the server could not save itKeep the dialog open, read the error, correct the entry if needed, and retry. No change was applied.
AI says it is unavailableAI is off, its budget is exhausted, the field is restricted, or a provider failedUse What we read or Enter it yourself. An administrator can review project AI settings separately.
A saved match reports that some occurrences still need attentionSome occurrences lacked a safe comparison timeline or had an extent the writeback could not applyReview the reported remainder; the platform kept those occurrences unchanged rather than guessing.
A column census says the column reads as free textThe distinct-value tail is not bounded enough to treat as a controlled vocabularyReview deterministically recognized dates and configure a narrower vocabulary-bearing column instead of forcing the free-text tail into the queue.
