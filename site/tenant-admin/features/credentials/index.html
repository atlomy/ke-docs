Saved connections and credentials

Purpose​

A saved connection is your environment's named reference to an outside service — a Coda account, a live MySQL database, or another recognized provider. The connection stores where the secret lives, never the secret itself: the platform reads the actual key or password from its storage place only at the moment a feature uses it, and never writes it to the database, to logs, or to background-job records. Read this page when you prepare a background import that reads from a live source, when an import fails with a credential error, or when you need to know exactly what the platform does and does not store.

Saved connections are an operator-mediated surface. You view, edit, scope, and validate your environment's connections yourself; creating a connection, deleting one, and placing the secret value itself are done by your platform operator. The split is stated action by action below.

Features​

  • Saved connection records — each connection carries a label (unique per provider within your environment), a provider, an authentication scheme, a secret reference with its backend, a status, an allowed-features list, and non-secret connection details. Maturity: Active. Limit: the record holds a reference to the secret, never the value — saving is refused when a value-like entry is detected in the reference or the details.
  • Import wizard reads through saved connections — Coda and MySQL imports can run through a saved connection; background reads of a live source require one, because a background job cannot carry a one-time key. Maturity: Active. Limit: of the credentialed providers, the wizard reads source data only from Coda and MySQL.
  • Credential-only providers — Airtable and Notion connections can be stored and validated; the platform checks their status, feature scope, and authentication scheme, but the import wizard does not read source data from them. Maturity: Built. Limit: storing the connection registers it for credential checks only — there is no import path behind it.
  • Validate without using — a list action confirms that a stored reference still resolves to a secret, without using the credential: no usage is recorded and the secret is not kept. The outcome (time, result, and a failure class on error) is written to the connection. Maturity: Active.
  • Feature scoping — the allowed-features list names which platform features may use the connection; a feature is refused unless its key is listed. Maturity: Active.
  • Usage record — each real use stamps the connection's last-used time and increases its usage count; both are read-only on the form, alongside the last validation outcome. Maturity: Active.
  • Secret backends — environment variables and AWS Secrets Manager are read at use time; "No stored secret" is supported for federated schemes. Maturity: Active. Limit: HashiCorp Vault and GCP Secret Manager are selectable when saving, but the platform does not read secrets from them — validating such a connection reports it as unavailable.

Who does what​

ActionWho
View your environment's saved connectionsYou. The list shows only your own environment's connections.
Edit a connection — label, scheme, backend, reference, allowed features, details, statusYou, subject to your account's permissions.
Validate connectionsYou — the Validate selected credential references action on the list.
Create a new connectionPlatform operator. The screen offers no add control inside an environment.
Delete a connectionPlatform operator. Deletion is not offered inside an environment.
Place or rotate the secret value itself (a server environment variable, a cloud-stored secret)Platform operator — the value lives outside the platform.
Configure AI providersPlatform operator. AI features are configured at platform level, not through saved connections.

Reference​

The screen​

The saved-connections screen is titled External Service Credentials in your environment's admin. It does not appear in the admin sidebar; open it by its address, /admin/customers/externalservicecredential/. The list shows each connection's label, provider, authentication scheme, status, secret backend, usage count, last-used time, and last update, with filters for provider, scheme, status, and backend, and a search box that matches labels and secret references.

Connection details (host or socket, database, username, port, SSL) live on the connection as non-secret details; the secret reference supplies only the password, at run time. Authentication schemes​

Ten schemes are available. The form's guidance: prefer OAuth, OIDC, IAM, or federated schemes when the provider supports them; static tokens are the fallback.

SchemeNotes
Static API / bearer tokenThe default. The only scheme the Coda import check accepts.
Database username/passwordThe only scheme the MySQL live-import check accepts.
OAuth 2.0 authorization codeAccepted by the Airtable and Notion credential checks.
OAuth 2.0 client credentialsAccepted by the Airtable and Notion credential checks.
OIDC federationMay be saved with No stored secret.
SAML SSO / federationMay be saved with No stored secret.
AWS IAM role / STSMay be saved with No stored secret.
IAM database authenticationMay be saved with No stored secret.
KerberosMay be saved with No stored secret.
Service accountAccepted by the Airtable credential check.

Secret backends​

The backend names where the secret value lives. The connection's Secret ref field holds the pointer into that place — never the value.

BackendWhat the reference isRead at use time?
Environment variableThe name of an environment variable on the platform server — uppercase letters, digits, and underscores. The default backend. Saving is refused if the reference does not look like a variable name.Yes. Setting the variable's value is operator work.
AWS Secrets ManagerThe secret's identifier in AWS Secrets Manager. Optional non-secret details on the connection can select a region, a specific secret version, or one field inside a JSON secret.Yes, fetched server-side.
No stored secretNothing. Allowed only for the five federated schemes marked above, where the platform's own runtime identity carries authentication. Saving is refused for any other scheme.Resolves to no secret material.
HashiCorp VaultAn identifier in Vault.No — the platform does not read secrets from this backend; validation reports the connection as unavailable.
GCP Secret ManagerAn identifier in GCP Secret Manager.No — same as Vault.

Two further save-time guards apply everywhere: a reference may not embed a user:password@ address form, and the connection's details area refuses credential-like keys (passwords, tokens, API keys) outright — details are for non-secret values such as a host name or a region.

Status​

StatusMeaning
Needs reviewThe starting status of every new connection. Features will not use it, and validation reports it as not allowed.
ActiveThe only status features use.
DisabledKept on record; features will not use it.

Allowed features​

The Allowed features field is a list of feature keys, for example ["import_wizard_coda"]. A feature resolves a connection only when its key is listed — an Active connection with an empty list is usable by nothing and fails validation. The import feature keys:

Feature keyUsed by
import_wizard_codaCoda imports — background runs and source-row loading.
import_wizard_mysqlMySQL live-database imports.
import_wizard_airtableThe Airtable credential check (no import path).
import_wizard_notionThe Notion credential check (no import path).

Usability — how you use it​

  • Validate your connections: open the list, select the connections, and run Validate selected credential references. The result message reports how many resolved and how many failed; each connection's last validation time, outcome, and failure class are recorded on its form. Validation does not use the credential and does not count as usage.
  • Make a connection usable: a feature uses a connection only when all three hold — status is Active, the feature's key appears in Allowed features, and the scheme is one the feature accepts. A new connection starts at Needs review, so reviewing and activating it is your explicit step.
  • Run a live MySQL read in the background: with an Active MySQL connection in place, the import wizard's first step has a Saved MySQL connection for background reads field — enter the connection's label there. It is required only when reading a live database in the background; an inline read takes the credentials directly and does not keep them.
  • Run a Coda import in the background: a background Coda import requires a saved connection name — the wizard refuses to queue one without it. Inline Coda reads use a one-time API key instead. At final import and on re-import, when a saved connection is present the platform loads source rows through it.
  • Scope a connection narrowly: list only the feature keys the connection should serve. The wizard names the reason when a connection is refused — not active, not allowed for that import feature, or an unsupported scheme for that source.

Troubleshooting​

SymptomLikely causeFix
A connection your platform operator created for you fails validationNew connections start at Needs review; only Active connections resolveSet the status to Active, confirm Allowed features lists the right key, and validate again.
Validation result is "not allowed"The feature key is missing from Allowed features, or the list is emptyAdd the matching feature key from the table above.
Validation result is "unavailable"The environment variable is not set on the platform server, the cloud secret store could not be reached, or the backend is one the platform does not read (HashiCorp Vault, GCP Secret Manager)Contact your platform operator — the secret's storage place needs attention, or the connection should move to a supported backend.
Saving is refused: the reference "must reference an env var name … not a raw value"A secret value was pasted into Secret ref on an environment-variable connectionEnter the variable's name; ask your platform operator to set its value on the server.
Saving is refused: details "cannot persist credential-like keys"A password, token, or key was placed in the connection's details areaMove the secret behind a secret backend; keep only non-secret values (host, database, region) in the details.
The wizard says the import "supports these auth schemes only"The connection's scheme is not one that source acceptsCoda imports accept the static API / bearer token scheme only; MySQL live imports accept database username/password only. Adjust the connection's scheme.
A MySQL connection is refused over its detailsThe details must include a host (or socket) and a database nameAdd host (or unix_socket) and database to the connection's details; username, port, and ssl are optional.
There is no add or delete control on the screenCreating and deleting saved connections is operator-mediatedContact your platform operator.
A Coda or saved-database re-import fails with a credential errorThe connection's secret reference no longer resolvesSee the credential rows in Data Import Wizard troubleshooting; validate the connection here first to read the recorded failure class.
