Entry Surface Readiness

Audience: Tenant administrator. Last aligned with platform state: 2026-05-25 Platform version: V2 (pre-1.0)

Purpose​

Before your environment exposes a public Entry surface — the published-Entry layer researchers and external readers see — the readiness panel lets you review the facet and autocomplete controls that would be made public, record decisions about each one, and confirm or defer the launch. Read this when preparing for a public-Entry cutover, when an audit surfaces a compact-control warning, or when launching an additional public role.

The panel is a review surface, not an auto-apply surface. Recording a decision stores tenant-local review state; promoting a public control or ratifying the search profile remains a separate explicit step.

Features​

  • Readiness audit endpoint — /app/admin/entry-surface-readiness/; returns active public Entry roles, reviewed scalar facet/autocomplete slots, compact-control warnings, blockers, and stored decisions. Substrate: Spec 0011 (entry-surface-post-merge-hardening) Task 4 + atlomyapp/services/entry_surface_facets.py · Maturity: Active · Limit: staff-only Django auth gates the endpoint.
  • EntrySurfaceControlDecision persistence — durable tenant-local record of every review decision, with a required reason. Substrate: atlomyapp/migrations/0009_entrysurfacecontroldecision.py + atlomyapp/models.py · Maturity: Active · Limit: a decision is a review checkpoint; it does not mutate the public surface itself.
  • Stable decision actions — the audit returns a fixed action vocabulary the panel can record: review candidate before promotion; choose a shorter scalar or curated public label; defer the candidate or public control with a reason; acknowledge long-value exclusion before public promotion. Substrate: Spec 0011 Task 4 · Maturity: Active · Limit: free-text reasons are required; the action itself is constrained.
  • Request-derived tenant schema — the endpoint resolves your environment from the request; browser-provided schema values are ignored. Substrate: Spec 0011 Task 4 · Maturity: Active · Limit: hard isolation boundary; you cannot record decisions on another environment.
  • Refreshed readiness on POST — recording a decision returns a refreshed audit report including the stored decision; ratification_changed: false confirms the corresponding TenantSearchProfile was untouched. Substrate: Spec 0011 Task 4 · Maturity: Active · Limit: ratifying the search profile is a separate operation, not a side effect of recording a decision.
  • Public-reader preview substrate — supports the projection-first published Entry layer that the cutover is preparing. Substrate: ADR-019 + ADR-029 + Spec 0021 (real-renderer preview) + Spec 0022 (public-reader parity) · Maturity: Active (substrate); deferred (some downstream parity work) · Limit: cutover gates on parity validation and search/TCO ratification.

Usability — how you use it​

Open /app/admin/entry-surface-readiness/ as a staff user logged in to your environment's host. The panel renders the audit report inline; recording a decision is a CSRF-bearing POST from the panel component.

  • Review compact-control warnings: the audit flags scalar controls that are too long for the compact facet shape. Choose the appropriate stable action and provide a reason.
  • Record a deferral: when you decide a candidate should not promote yet, defer it with a reason. The deferral is durable; the next audit reads the stored decision.
  • Pre-promotion checklist: the audit lists active public Entry roles, reviewed scalar facet/autocomplete slots, blockers, and stored decisions. Walk it row by row; every durable decision requires a reason.
  • Cutover handoff: when the audit reads clean and your environment is ready, the platform team runs the actual public-Entry cutover. Recording a decision is not the cutover; it is the review checkpoint that gates it.

Validation errors return JSON with an error field so the panel surfaces the server-side message inline.

Troubleshooting​

SymptomLikely causeFix
The endpoint returns 403 ForbiddenStaff-only Django auth gate — your contributor lacks staff statusHave an admin contributor grant staff status, or perform the review under an admin role.
POSTing a decision returns a JSON validation errorThe decision is missing a required reason, or the action value is not in the stable action vocabularyRead the error field. Add a reason or choose a valid action.
The audit reads clean but the public Entry surface does not appear after the cutoverRecording decisions does not promote public controls or ratify the search profileConfirm with the platform team that the cutover step was run. The panel is a review surface only.
ratification_changed: false worried youThis is by design — decisions never mutate TenantSearchProfileRatification is a separate explicit operation. The response field exists so you can verify the search profile was untouched.
Browser console shows a schema parameter being ignoredThe endpoint deliberately derives tenant schema from the request and ignores browser-provided valuesThis is the hard isolation boundary; the behaviour is correct.
You need to undo a recorded decisionDecisions are durable review stateRecord a new decision that supersedes the previous one. The audit trail preserves both.
