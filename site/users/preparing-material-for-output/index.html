Preparing material for a paper, bibliography, or course

Purpose​

At some point your work leaves the knowledge environment: citations go into a paper, a set of records becomes a bibliography or an appendix, a slice of your corpus turns into a teaching handout, a colleague needs to see exactly what you found. This page sequences that workflow — narrow your records to a working set, get them out as clipboard rows, a file, or a link, and copy citations in your project's citation style. Read it when a deadline is close and your material needs to be somewhere else.

Features​

  • Row selection with a floating toolbar — select any number of rows in a table and a toolbar appears with the actions you can run on the selection. Maturity: Active.
  • Copy selected rows to your clipboard — the visible columns of the selected rows, with a header row of column labels, ready to paste into a spreadsheet or a document table. Maturity: Active. Limit: carries only the columns visible in the current view.
  • Export selected rows as a file — downloads the selected records as a JSON file, a structured data format for tools and scripts. Maturity: Active. Limit: JSON is the only file format; rows reach a spreadsheet through the clipboard copy instead.
  • Citations in your project's citation style — a published entry, and its draft preview, render citations ready to copy into a bibliography or footnote. Maturity: Active. Limit: how complete a citation reads depends on the fields filled in on the record.
  • Shareable search and view links — a search's address carries the whole search, and a saved view has its own link. Maturity: Active. Limit: whoever opens a link sees only what their own access allows.
  • Stable web addresses for published records — every published record keeps a stable address you can put in a syllabus, a slide, or a footnote. Maturity: Active. Limit: stability is per record; links to individual sections within a page are best-effort.

Usability — how you use it​

Decide what you are collecting​

Three common shapes, three routes:

  • Citations for a paper or a bibliography — you need formatted citation text. Work record by record in the reading view; see Copy citations in your project's style below.
  • A table of records for a handout, appendix, or analysis — you need rows and columns. Filter down to a working set, then copy or export the selection.
  • Something a colleague or a reader opens themselves — you need a link, not a copy; see Share by link instead of by copy.

Most projects mix all three: a saved view holds the working set, citations come from the reading view, and the finished records are shared by their public addresses.

Narrow to a working set — and save it as a view​

Use search and filters to get exactly the records you need in front of you: quick search to find records anywhere you can access, Search & Read for browsing with conditions on field values, and the table's filter builder for column conditions. Searching and reading covers each tool.

When the working set is right, save it as a view so you can return to it for the life of the project — see Save your table arrangement as a view. A view remembers your filters, visible columns, order, and sort. Views are shared with everyone working in your environment, so name it descriptively; to refine it without changing what collaborators see, duplicate it first and work in the copy.

Select rows, then copy or export​

  1. Click a row to select it. Hold Ctrl (Windows / Linux) or Cmd (Mac) and click to add rows one at a time, or hold Shift and click to select a range. A floating toolbar appears showing the count of selected rows.
  2. To paste rows into a spreadsheet or a document table, select Copy selected. The visible columns of the selected rows go to your clipboard as tab-separated values with a header row of column labels; a message confirms how many rows were copied. Switch to your spreadsheet and paste.
  3. To download a file, select Export selected. The selected records are saved as a JSON file in your usual downloads location.

Two differences between the routes are worth knowing before a deadline:

  • Copy follows your view; export does not. The clipboard copy carries the columns visible in the current view, in their current order — arrange the view first and the paste comes out right. The exported file carries the records' stored fields regardless of which columns the view displays.
  • The file is for tools, not for reading. JSON is structured data. If the destination is a spreadsheet or a handout, use Copy selected and paste.

A selection lives in the view where you made it: switching to another view or table clears it. The full selection mechanics, including keyboard paths, are in Copy or export selected rows.

Copy citations in your project's style​

Citations come from the reading view, not from the table:

  1. Open the published entry — or its draft preview, which shows the entry exactly as a reader will see it, references included, before anything goes live.
  2. Find the entry's References area. Rows of evidence carry their citations, and when your project has set up a citation for the record itself, it appears there as its own row. A media item with full citation details carries its own citation too.
  3. Select the citation text and copy it into your bibliography, footnote, or document.

Each citation is rendered in the citation style your project has adopted — set per collection by your environment administrator and defined in Citation Style Language, the same format reference managers such as Zotero use. Before the citation goes to a venue, check that the active style suits it: compare a rendered citation against the venue's style guide, and if it does not match, collect sample citations and send them to your environment administrator with a request. Citations you can trust explains what the platform guarantees about a citation once it is in print — including why a media item you cite should be a frozen Edition first — and walks through the style-change request. The short copying steps live in Copy a citation for a record or media item.

Share by link instead of by copy​

A link keeps the material live — whoever opens it sees the records as they are at that moment, filtered by their own access.

  • A search, for a colleague in your environment — run the search in Search & Read, then select Copy link below the search box. The link carries your search words, every filter condition, the sort, and the page. See Share a search.
  • A saved view, for your team — a saved view has its own link, from Copy current view link in the toolbar or Copy view link in the view's menu. The link points to the view itself: if the view is edited later, the link opens the edited version.
  • A single record, for a colleague — right-click the row and select Copy row link. The link points to that record in the workspace; the colleague must be signed in to the same knowledge environment.
  • A single record, for anyone — once the record is published, its public page has a stable web address that stays valid even if your project later reorganizes its pages. That address is the one for a syllabus, a slide, or a footnote — readers outside the project need no account. Public reader covers the path from draft to published page.

The limits, plainly​

  • From a table, the two batch outputs are the clipboard copy and the JSON file. There is no spreadsheet-file download (CSV or Excel); rows reach a spreadsheet by copy and paste.
  • No workspace control assembles a single bibliography file from many records at once. Citation text is copied per entry from each record's reading view. For reference managers, a published entry's citation is also available in a machine-readable form — see Citations you can trust.
  • The selection toolbar also shows Delete, Edit visibility, and Set row color. All three are labeled "Backend pending" — visible but not active; clicking them does nothing.

Troubleshooting​

SymptomLikely causeFix
Pasted rows are missing columns you expected.The clipboard copy carries only the columns visible in the current view.Unhide the columns — or switch to a view that shows them — then copy again.
A "Copy failed" message appears after Copy selected.Your browser blocked clipboard access for this site.Allow clipboard access in your browser's site settings for this environment, then copy again.
The exported file will not open as a spreadsheet.The export is a JSON file — structured data, not a spreadsheet format.Use Copy selected and paste the rows into your spreadsheet instead.
Your selection disappeared after switching views.Selections are per view and per session; switching views or tables clears them.Re-select your rows in the view you are working in.
A citation shows placeholders or looks incomplete.The fields the citation draws on are missing or only partly filled in on that record or media item.Open the record and complete those fields; the draft preview shows the corrected citation before publishing. See Copy a citation for a record or media item.
A colleague opens your search link and sees fewer results than you did.Results respect each person's access; collections outside their access are absent.This is expected. If they need access to a collection, contact your environment administrator.
