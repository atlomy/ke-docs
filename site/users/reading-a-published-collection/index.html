A reader's guide to published pages

Purpose​

This page is for reading a published knowledge environment from the outside — as someone who received a link, found a record through a search engine, or wants to browse a project's corpus without a workspace account. It walks through arriving at a page, reading a record, copying a citation, and moving between records. Read it if you are an external reader making sense of what you see, or if you are a researcher who wants to know exactly what a reader encounters once your project publishes.

What you see depends on how the project configured its published pages. The sections below describe how the reading layer works; a given project may use all of it or a subset. For the publisher's side of this — how a record becomes a published page, and how to preview before publishing — see Public reader.

Features​

  • Stable, citable URLs — every published record has a stable web address, so a link shared today still resolves to the same record later. Maturity: Active. Limit: stability is per record; links to individual sections within a page are best-effort.
  • Browsable indexes — beside searching, you can browse the whole corpus from an alphabetized index, and a project can publish more than one (for a multilingual corpus, often one by transliteration and one by original script). Maturity: Active. Limit: which indexes exist and what each row shows are set by the project.
  • Record pages with a side contents list — a published record reads as titled sections with a navigation list down the side that highlights where you are as you scroll. Maturity: Active. Limit: how fine-grained the contents list is depends on how the record is sectioned.
  • A references section — the evidence behind a record, one row per place the record is attested, rendered in the project's citation style. Maturity: Active. Limit: how rich each row reads depends on what the project catalogued.
  • Copyable citations — citations are rendered in the project's citation style, defined in Citation Style Language — the same format reference managers such as Zotero understand — ready to select and paste into a bibliography. Maturity: Active.
  • Attached media — a record lists its attached media, each item with its label and, where catalogued, a link to its source. Maturity: Active. Limit: only the media the project attached and published appears.
  • Several values shown together — where a record keeps more than one value in a single field (several translations of a term, a transliteration beside its original-script form), the page shows them together on one line. Maturity: Active. Limit: a project can instead choose to show one value per record for such a field; showing them all is the default.
  • Dark mode and reading-first layout — selectable text, a scholarly typeface, and a darker color scheme you can switch to, remembered in your browser. Maturity: Active.

Usability — how you use it​

Arriving at a published page​

There are two common ways in:

  • A shared link. Someone sent you the web address of a single record. Open it. The address is stable, so it keeps resolving to the same record even if the project later reorganizes its pages.
  • The browsable index. When you want to explore rather than land on one record, open the project's index — an alphabetized list of every published record. A project can publish more than one index; for a multilingual corpus, that often means the same records listed by transliteration or by original script, switchable from the controls at the top of the list. Each index row can show the transliterated form, the original-script form, and a short gloss together, so you can recognize a record without opening it, and a character rail jumps straight to a letter. See Browse entries by index.

Reading a record page​

A published record reads as a sequence of titled sections, with a Contents list down the side that highlights the section you are currently reading and lets you jump to any section. Below the sections, a record can carry:

  • Connections to other records, where the project published them.
  • A References section — the evidence behind the record. Each place the record is attested gets its own row, rendered in the project's citation style: author, work, locator, and any abbreviations as the field uses them. Where an occurrence cites both a modern and an earlier edition, the row bridges the two; where it carries a quote, the quote sits with its row. See Read the references section on a published entry.
  • A Media section listing each attached item with its label and, where the project catalogued it, a link to the item's source. Items such as 3D models open in their own viewer — see Exploring 3D models.

Where a field on the record holds more than one value — a term given in several languages, or a transliteration alongside its original-script form — the page shows those values together on one line, separated by a comma or a middot. A project may instead set such a field to show a single value per record; when it does, you see only that one. Either way, what you see is what the project entered — nothing is translated for display.

Copying a citation​

Citations appear in the record's References area, rendered in the project's citation style. Select the citation text and copy it to paste into a bibliography, footnote, or document. Because the style is defined in Citation Style Language — the same format reference managers understand — the copied citation is consistent with the conventions those tools use. A media item attached to a record can carry its own citation, separate from the record's, and it appears among the references the same way. See Copy a citation for a record or media item.

Moving between records and switching the view​

  • Follow connections. Where a record links to another, follow the link to that record's page; your browser's back button returns you.
  • Return to the index to pick another record, or switch to a different index where the project publishes more than one.
  • Switch to dark mode. A reading-first layout offers a darker color scheme, remembered in your browser for your next visit.

Why some content is not visible to you​

A published page shows only what the project chose to publish. A record's working notes, draft fields, or unpublished records are not on the public web at all — they live in the project's workspace, which a reader does not reach. If a record you expected is missing, it has most likely not been published yet rather than hidden from you specifically.

Troubleshooting​

SymptomLikely causeFix
A link someone shared returns a "not found" page.The record was withdrawn after the link was shared, or the address was mistyped.Re-check the address. If a record was deliberately withdrawn, the project may show a short notice in its place rather than the record. Ask the person who shared the link, or browse the index for the current version.
A citation reads roughly — punctuation or ordering looks off.The project's citation style for that collection is still being refined.Nothing to do as a reader; the citation is still usable. The rendering improves once the project applies a reviewed style.
A record is in the index but its page shows a placeholder where a citation should be.The fields the citation draws on are incomplete on that record.Nothing to do as a reader. The project completes those fields and the citation fills in on the next publish.
You browsed to a record you read last week and the contents list looks different.The project edited and republished the record.This is expected — published pages refresh when the project republishes. The record's web address stays stable across the change.
The index switcher shows only one index.The project publishes a single index.Use it as the entry point; more than one index appears only where a project publishes more than one.
