Searching and Reading

Audience: Researcher Last aligned with platform state: 2026-06-03 Platform version: V2 (pre-1.0)

Purpose​

This page covers two things that go together: how you search across your knowledge environment, and how you read what you find — including media, citations, and the public reader preview for records that are not yet published. Read it when search is not finding what you expect, when you need to copy a scholarly citation, or when you want to check what a published row will look like to a reader outside the project.

What is available depends on how your tenant administrator configured your project. The mechanics below describe what the platform supports; your environment may have all of it or a subset.

Features​

  • Workspace record search — top-chrome search panel for finding editable workspace rows across current table or all accessible workspace tables, with results grouped by table. Substrate: Spec 0037 (docs/superpowers/specs/0037-workspace-research-search-interface/), workspaceSearch GraphQL. Maturity: Active. Limit: depends on the tenant search index and your membership scope.
  • Cross-script current-table quick filter — toolbar box that filters already-loaded rows in the active table, including native script, transliteration, and translation fields where configured. Substrate: ADR-011 (docs/developer/architecture/adr/011-search-engine-opensearch.md) plus AG Grid quick filter. Maturity: Active. Limit: search coverage is bounded by loaded rows and tenant field configuration.
  • Compositional filters — Add filter for date ranges, categories, status, region, or whatever facets the project exposes; combinable with Quick search. Substrate: Spec 0028 (docs/superpowers/specs/0028-workspace-ui-parity-alignment/). Maturity: Active. Limit: facets must be declared in the tenant's workspace navigation manifest.
  • Cross-record-type top search — optional global search that returns matches grouped by record type. Substrate: Spec 0003 (docs/superpowers/specs/0003-tenant-workspace-navigation-manifest/). Maturity: Active (per-tenant). Limit: visible only if the tenant exposes the top-level search surface.
  • Details panel reading view — full record (fields, history), linked media, related records. Substrate: spa/src/apps/tenant_admin/workspace/WorkspaceDetailsView.tsx. Maturity: Active. Limit: visible fields are governed by the record-type configuration.
  • Media carousel with type variants — flip between 2D images, audio, video, 3D models, molecular visualisations attached to the same anchored point. Substrate: Spec 0016 (docs/superpowers/specs/0016-multi-media-expansion/), PRs #330 (variants), #334 (type metadata), #335 (3D viewer config rename), #336 (viewer config siblings). Maturity: Active. Limit: variants surfaced are those the tenant actually attached.
  • CSL-format citations — under every media item and source record, a structured citation in CSL (the format reference managers like Zotero understand). Substrate: Spec 0008 (docs/superpowers/specs/0008-citation-framework-csl/), PRs #331–#333. Maturity: Active. Limit: BibTeX / RIS export depends on tenant configuration.
  • Anchor-resolved provenance — citations on a row are built by tracing where each piece of the record came from (source manuscript, prior publication, contributor). Substrate: Spec 0008 anchor-resolution work (commit 9c3659b9). Maturity: Active. Limit: provenance fidelity depends on whether the tenant's data import declared the source links.
  • Public reader draft preview — in-workspace preview that renders exactly what a reader outside the project would see. Substrate: Spec 0021 (docs/superpowers/specs/0021-public-reader-preview-real-rendering/), Spec 0022 (docs/superpowers/specs/0022-atlomy-atlas-public-reader-parity/), draft-reader-preview (commit 0677fcbe). Maturity: Active. Limit: richer draft-state preview is per-tenant opt-in.

Usability — how you use it​

Searching across the workspace​

Use the top Search database... control when you are trying to find a row but do not already know which table or view contains it. The panel starts in Current table when a table is active and also supports All workspace. Results are grouped by table and open the editable workspace row route. This is the right search for "find this person/source/term anywhere I can access."

Filtering the current table​

Every workspace toolbar also has a current-table Filter visible rows box. Type a term in whichever script your project supports and press Enter. The table filters to matching loaded rows. If the project's data crosses scripts (Greek, Hebrew, Arabic, Syriac, and so on), search is typically configured to span:

  • Native script — what is written in the original.
  • Transliteration — a Latin-letter rendering of the same word (Greek "ἀνατομή" alongside "anatomē", for example).
  • Translation — the meaning in English or whatever the project's working language is.

So if the environment supports polytonic Greek, you can type either the Greek or the romanized form, with or without diacritics, and find the same records. If it supports Hebrew, you can search in Hebrew script or in a standard transliteration. The mapping is set up by your tenant administrator.

The toolbar search box covers loaded row fields the project marked as searchable — typically names, titles, primary identifiers, and main content. Less central fields (administrative notes, internal IDs) are not searched but remain visible when you open a row.

Combining search with filters​

Type a term in Quick search, then use Add filter to narrow further. You can also do filter-only browsing — no quick-search term, just filters — useful for surveying a slice of the corpus.

Searching across record types​

The workspace search panel covers accessible workspace tables and groups results by record type/table so you can see, for instance, that a name matches both a person record and a place record. If that panel is unavailable, the toolbar quick filter remains usable for the active table.

Reading a record's Details​

Click any row to open its Details panel. You see all fields (including ones the table does not display), linked media (each with a citation), related records, and history where available.

Working with media​

Records can have more than one kind of media attached. The Details panel's media carousel flips between variants for the same anchored point. If a single subject has a 2D drawing and a 3D model, the carousel surfaces both; you pick which to look at. Each media item is itself a record with its own metadata — when it was made, who made it, where it came from. Click into a media item to see its full provenance.

Copying citations​

Every media item in your environment carries a CSL-format citation underneath it — the same structured form Zotero and similar reference managers understand. Click to copy. If your environment is configured to export BibTeX or RIS, that path is available too. The same applies to source records: opening one shows you a citation you can reuse.

Previewing in the public reader​

If you have a row open in the workspace, click Preview in reader in the Details panel. A side panel renders exactly what an outside reader would see — same layout, same fonts, same citations, same media rendering — without making the row public. Read it, spot anything that looks wrong, close the panel.

Some tenants opt into a richer preview that lets editors see staged-but-unpublished drafts with a "draft" indicator across the top, for reviewing the final reader output before activation. See Public reader for the full lifecycle.

Troubleshooting​

SymptomLikely causeFixWhere to escalate
Quick search returns nothing for a record you know exists.The relevant field is not marked searchable in the tenant configuration.Open the row directly via its row identifier or via a known related record; ask your administrator to mark the field searchable.Tenant admin; ADR-011.
A transliterated search misses a record whose native-script form you know is there.Either the project does not have cross-script indexing configured for that field, or the transliteration mapping does not cover the form you typed.Try the native-script form; if that hits, the cross-script mapping needs work — flag with the administrator.Tenant admin; ADR-011.
The media carousel shows fewer variants than you expected.Only variants actually attached to the row appear; missing variants were never imported or linked.Add the variant from the row's edit surface, or ask whoever owns the media import to revisit.Tenant admin; Spec 0016.
A citation under a media item looks incomplete or shows placeholders.The underlying CSL fields are missing on the media record.Open the media record's Details and complete the citation fields.Tenant admin if the field requirements need adjusting; Spec 0008.
Preview in reader shows a "draft" banner you did not expect.Your tenant opted into the richer draft preview mode; the banner marks the preview as a draft view.This is intended — the banner makes it clear the row is not yet published.Tenant admin if the banner is wrong for your workflow.
The top-level cross-record-type search icon is not present.Tenant did not expose a global search surface for this project.Use per-workspace Quick search until the global surface is enabled.Tenant admin; Spec 0003.
The workspace search panel opens but shows no results while the table filter works.The whole-workspace search index may be unavailable or the row is outside your membership scope.Keep using the toolbar quick filter for the active table and ask an administrator to check search indexing/scope.Tenant admin; Spec 0037.
