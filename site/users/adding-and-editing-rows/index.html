Adding and Editing Rows

Purpose​

This page covers creating new records and editing existing ones in your workspace. The model is: a new row is created as a draft the moment you ask for one, every edit saves as you finish each field, and your draft stays in the table until you complete it. There is no Save button to forget. Read this when you create your first record, when you want to know what "draft" means for a new row, or when an edit is not behaving as you expect.

Features​

  • Create a row from the toolbar — one click adds a draft row to the current table and opens it for editing. Active.
  • Insert and duplicate — insert a row directly below an existing one, or duplicate a row to start a new one from its values. Active.
  • Autosave editing — every change saves when you finish the field. There is no Save button. Active.
  • Draft stage for new rows — a new row starts as a draft: visible to your project, never shown to public readers, and not yet linkable to other records. Active.
  • Editing in two places — the table cells and the Details panel edit the same record; a change made in one shows in the other. Active.
  • Linked-record fields — search the related record type and pick a match, directly inside the field. Active for records past the draft stage.
  • Row deletion from the workspace — not yet available. Deferred.

Usability — how you use it​

Creating a new record​

  1. Open the table you want to add to. New rows always belong to the table you are looking at.
  2. Click + New row in the toolbar. Your environment may label this button differently. The row is created right away as a draft: a notice confirms Draft row created, with a Review row button that takes you to it, and the row joins your table and opens for editing.
  3. Fill in the fields. Each field saves when you finish it — click out of a text field or press Enter, and the value is stored. Choices and checkboxes save the moment you pick them.
  4. Leave and return whenever you like. Your draft is a row in your table. Close the panel, navigate away, come back another day — your values are saved. Click the row to continue where you left off.

Required fields can stay empty while you draft. They must be filled before the row can leave the draft stage.

Two more ways to start a row:

  • Insert row below — right-click an existing row and choose Insert row below. In views you order by hand, the new row lands directly below that one; in sorted or filtered views, the active sort and filters decide where it appears.
  • Duplicate row — right-click a row and choose Duplicate row. This creates a new draft with that row's directly editable values copied in; derived and linked fields are skipped.

If + New row is unavailable, the button itself tells you why. Some views cannot accept new rows — for example, a view that combines or filters records rather than showing a single stored table.

What "draft" means​

A new row begins as a draft:

  • Your project sees it. Draft rows appear in the workspace table alongside everything else.
  • Public readers never see it. Only records that have been completed and published reach the public reading site.
  • It cannot be linked yet. The platform declines attempts to link a draft row to another record — the link is refused with a message rather than saved.
  • Required fields may wait. A draft saves with required fields empty; the row cannot become an active record until every required field has a value.

Once every required field is filled and the row passes its checks, it can leave the draft stage and become an active record — after that, links to other records save normally.

Editing an existing record​

You can edit in two places, and they stay in step:

  • In the table — edit a cell directly. The change saves when you confirm it or move on to another cell.
  • In the Details panel — click a row to open its Details panel. Click into a field, change the value, then leave the field or press Enter. The panel header shows Saving… and then Saved.

A value you did not change is not re-saved.

Not every field takes typed input:

  • Fields marked with a Read badge are not editable in place. These are derived fields (computed from other fields), media fields, and field types that do not have an in-place editor yet. To change a derived value, edit the fields it is computed from.
  • Relation fields show the linked-records editor instead: existing links appear as removable chips, and a search box lets you type part of a related record's name and pick a match to add a link. Click the × on a chip to remove a link.

If a save fails, an error message tells you what went wrong. The field returns to its stored value — re-enter your change after fixing the problem.

Removing a row​

Removing rows from the workspace is not yet available — the row menu shows Delete row as unavailable. If you created a row by mistake or need a record removed, contact your environment administrator.

Troubleshooting​

SymptomLikely causeFix
+ New row is unavailable.No table is selected, or the current view cannot accept new rows.Hover over the button to see the reason, or switch to a regular table view.
Creating or editing a row fails with a permission message.Your role includes read access but not edit access.Contact your environment administrator.
A field will not accept your edit and shows a Read badge.The field is derived from other fields, holds media, or has no in-place editor yet.Edit the fields it is computed from. If you believe the field should be directly editable, contact your environment administrator.
You cannot link another record from a new row.The row is still a draft. Records cannot be linked while either side is a draft.Fill in the required fields and complete the row first. If linking stays unavailable afterwards, contact your environment administrator.
A change did not save.The value failed a check, or the field never lost focus.Look for an error message near the field or panel. Click outside the field or press Enter to confirm the save, then re-enter the value if it reverted.
You need a row deleted.Row deletion from the workspace is not yet available.Contact your environment administrator.
A field you expected is missing from the form.The field is hidden in the current view, or it is not configured for this record type.Check the view's hidden fields first. Otherwise, ask your environment administrator to add the field.

A note on permissions​

What you can do in the workspace reflects your role in the project. Members with read access browse, search, and view Details; adding and editing rows requires edit access. If your role does not include editing, the platform declines the change with a permission message. Roles are assigned by your environment administrator; the permissions panel page describes what each role covers.
