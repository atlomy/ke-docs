Accessibility

Audience: Researcher Last aligned with platform state: 2026-05-25 Platform version: V2 (pre-1.0)

Purpose​

Your knowledge environment is built to work with keyboard navigation, screen readers, and adjustable display settings. This page walks through what is available, where to find it, and what is still on the way. Read it when you want to drive the workspace without a mouse, when you need to adjust how text is displayed, or when a control is not reachable or readable the way you expected.

Features​

  • Workspace keyboard navigation — Tab / Shift+Tab, Enter, Escape, Arrow keys, Space cover every interactive control. Substrate: spa/src/apps/tenant_admin/workspace/ (component layer). Maturity: Active. Limit: combinations are conventional; no custom-chord required.
  • Visible focus rings (keyboard-only) — clear outline on focused elements, drawn when navigating with the keyboard, suppressed for mouse clicks to keep the screen quiet for mouse users. Substrate: design-system tokens served by the workspace primitives (commit 2c072c9b). Maturity: Active. Limit: depends on the host-page CSS not overriding :focus-visible.
  • Inline editor keyboard parity — Tab into a field, type, Tab out (autosave on blur); Escape cancels current edit; arrow keys move through dropdown / lookup options; Enter selects. Substrate: spa/src/apps/tenant_admin/workspace/WorkspaceDetailsView.tsx, a11y fix (commit cda2f4cd, 2026-05-24). Maturity: Active. Limit: same focus contract as the table.
  • Backend-pending field hints with aria-disabled — fields whose editing surface has not shipped render a focusable, screen-reader-announced hint instead of a hidden control. Substrate: workspace Details panel. Maturity: Active. Limit: hints are intentionally not interactive — they describe state, not action.
  • Density toggle — Comfortable (roomier rows, larger touch targets) and Compact (more rows on screen); persists per saved view. Substrate: spa/src/apps/tenant_admin/workspace/DensityToggle.tsx. Maturity: Active. Limit: two density levels only.
  • Accessibility control panel — font scale, line height, font family, color presets, stored per researcher account so settings carry across devices. Substrate: spa/src/components/AccessibilityControlPanel/index.jsx, CSS variable wiring (commit d725ce39, 2026-05-09), visual parity restoration (commit 6e9348b5). Maturity: Active. Limit: presets are a small set; finer-grained color customization is deferred.
  • TipsPanel a11y (stable keys, focus management) — the inline tip panel is screen-reader-friendly with stable keys for focus retention across re-renders. Substrate: Spec 0030 Phase 6.B R2 absorption (commit 3b8488ab), spa/src/apps/tenant_admin/components/TipsPanel.tsx. Maturity: Active. Limit: per-panel; broader announcement coverage is ongoing.
  • Wizard Ask a11y polish — multi-step entry wizard's Ask flow polished for keyboard and screen reader use. Substrate: Spec 0017 (commit 304c2b66, 2026-05-21). Maturity: Active. Limit: Stage 3 only; other wizard stages on the same roadmap.

Usability — how you use it​

Driving the workspace from the keyboard​

  • Tab / Shift+Tab moves through interactive controls — toolbar buttons, filter chips, the search box, table cells, drawer fields.
  • Enter activates a button, opens a row's Details panel from a focused row, or commits an edit in a focused field.
  • Escape closes the active drawer, panel, or dialog.
  • Arrow keys move within the table grid and within menus (filter menu, column manager, saved views, density).
  • Space toggles checkboxes (for selecting rows in batch operations).

Focused elements have a visible focus ring — a clear outline showing where you are. The ring is keyboard-only by default; clicking a control with the mouse does not draw it.

Inline editing with the keyboard​

The Details panel's inline editor supports the same flow:

  • Tab into a field, type, Tab out — autosaves on blur.
  • Escape cancels the current edit without saving.
  • For fields with menus (dropdowns, related-record lookups), arrow keys move through options and Enter selects.

How "backend-pending" hints behave​

Some fields in the Details panel show a "this is not editable yet" hint instead of an inline editor. These hints are deliberately part of the keyboard tab order and announce themselves to screen readers with aria-disabled, so it is clear to assistive-tech users that the field exists and is intentionally not yet interactive. They are not skipped, not invisible, and they do not pretend to be editable.

Adjusting display​

The workspace toolbar has a density toggle (Comfortable / Compact) — choose whichever works for your eyes and workflow; the setting persists per saved view.

The accessibility control panel (typically reachable from a global header or settings menu) lets you adjust:

  • Font scale — make all text larger or smaller as a percentage of the base size.
  • Line height — increase line spacing for easier reading; particularly helpful for dyslexia and low vision.
  • Font family — switch between the default font and alternatives (typically including a high-readability option).
  • Color presets — a small set of color-scheme presets, useful for contrast and color-vision differences.

These settings are stored against your researcher account and carry across devices when you sign in.

Troubleshooting​

SymptomLikely causeFixWhere to escalate
A control is not reachable with Tab.A regression in focus order, or a custom widget in a tenant-configured surface not honouring the standard tab order.Try Shift+Tab from a known-reachable neighbor; if still unreachable, file a bug.Tenant admin → platform team. Accessibility regressions are bugs, not config.
Screen reader skips a backend-pending field.The aria-disabled hint failed to render, or the assistive tech is configured to skip disabled controls.Toggle the screen reader's "include disabled controls" setting; if hint is missing entirely, file a bug.Platform team.
Visible focus ring not drawn after Tab.Host CSS overrode :focus-visible, or you previously clicked with the mouse (focus ring is keyboard-only).Press Tab once more from a body region; if still invisible, file a bug.Platform team.
Font scale resets after sign-out.The accessibility setting failed to persist against your researcher account.Confirm you are signed in (not in a guest / share-link session); re-apply the setting.Tenant admin; AccessibilityControlPanel substrate.
Density change does not persist after saving a view.The saved view was not actually saved (no name confirmed), or the density widget did not receive the saved-view event.Re-open the saved-views menu and choose "Save changes to this view".Spec 0028 if reproducible.
Color preset still has poor contrast for your needs.Preset set is intentionally small in V2; finer-grained customization is deferred.Use the highest-contrast preset; flag the gap.Platform team — this is a known limit.
Inline editor will not commit on Tab.The field is read-only for your role, or validation failed (look for inline error).Confirm role; correct the value.Tenant admin for permissions.

What is there, what is still arriving​

  • Workspace keyboard navigation: Active.
  • Visible focus rings: Active.
  • Density toggle: Active.
  • Accessibility control panel (font scale, line height, font family, color presets): Active.
  • Inline editor keyboard parity in the Details panel: Active.
  • Discoverable backend-pending field hints with aria-disabled: Active.
  • TipsPanel a11y (stable keys, focus management): Active.
  • Wizard Stage 3 Ask polish: Active.

Additional ARIA labeling, screen-reader announcements for autosave confirmations, and improvements to color contrast are ongoing.

If something is not working for you​

Accessibility regressions are bugs, not configuration questions. If a control is not keyboard-reachable, a screen reader misreads a field, or a contrast issue is making text unreadable, let your tenant administrator know so it can reach the platform team.
