Narrow the current table with filters

The toolbar above your table has two filtering tools. They work together and are both only about the table in front of you — they do not search the rest of your workspace.

The filter box — quick narrowing as you type​

The Filter visible rows… box in the toolbar narrows the table as you type. It matches against whatever text is already loaded in the visible rows, in whatever script the text is written.

Type a term and the table immediately hides rows that do not contain it. Clear the box and all rows come back.

The filter box works on rows already loaded in the table. If the record you want lives in a different collection, it will not appear here — use the Search database… control at the top of the workspace instead.

This text is not saved with the view. When you navigate away and return, the filter box is empty. For a filter you want to keep, use the filter builder below and save the arrangement as a view.

The filter builder — conditions by column​

Click Filter in the toolbar to open the filter builder. Each filter condition targets one field. Pick the field, then set a value with a control suited to that field's kind:

Field kindWhat you set
TextA word or phrase, typed in a text box
NumberA number, typed in a number box
DateA date, picked with a date control
Choice (single or multiple)One of the field's option values, picked from a list

Any other field kind takes a word or phrase, matched against the value as it is displayed in the table.

A row stays visible when the field's displayed value contains what you set. Matching ignores letter case. Comparisons such as greater-than, before and after, or ranges are not available in the filter builder.

Date fields are the exception to the "contains" rule: when both the filter value and the row value are readable as dates, the table matches the same calendar date. A stored value with a time and timezone can still match the date you picked. A field that only looks like a date but is configured as Text keeps text matching until its field type is changed. Changing the type reports any stored values it converts or leaves for correction.

The table narrows as soon as you set a value, and the condition appears as a chip in the toolbar, shown after "filtering by". The chip names the field and the value, with a count of the rows that currently match, so you can see at a glance what is active.

Combining conditions​

Add more than one condition by picking another field in the filter builder. All active conditions must match a row for it to stay visible — the conditions work together. Each field carries one condition: setting a new value for a field replaces that field's earlier value.

The filter box and the filter builder also compose: you can apply column conditions and then type in the filter box to narrow further.

Removing a condition​

Click the × on any chip to remove that condition. The table widens to include rows that now match.

Click Clear — visible when at least one chip is active — to remove every condition at once.

Filter-only browsing​

You do not need a search term to use filters. If you want to survey a slice of your corpus — all records with a particular choice value, all rows that mention a particular place — open the filter builder, set your conditions, and browse the matching rows directly. No typing in the search box required.

Saving a filtered arrangement​

Filters set while a saved view is active are remembered on that view. Open or create a view, set your conditions, and the next time you open that view your filters are already applied. See What happens to saved views after a re-import for how saved filters behave when a field changes.

Troubleshooting​

SymptomLikely causeFix
The filter box does not find a record you expect.The box narrows rows already loaded in this table; the record may be in a different collection.Use the Search database… control at the top of the workspace to search across all collections you can access.
A filter condition I set is gone when I come back to the table.You set the condition using the quick filter box, which is not stored. Conditions from the filter builder chips persist only when a saved view is active.Set the condition in the filter builder, then save the view.
The filter box was matching rows, but a record I know matches is missing.The filter box works on text visible in loaded rows; a field that is not displayed as a column is not matched.Open the filter builder instead and target the specific field you want to filter on.
I cannot find the Filter button.In a narrow window the toolbar lays its controls out on more than one line.Widen the window, or look for the button on the toolbar's following line.
After I clear all chips, rows I expected do not reappear.The quick filter box may also have a term in it.Check the filter box in the toolbar and clear it.
The filter builder does not show the field I want to filter on.The filter builder lists the fields configured for your collection.Contact your environment administrator if a field you need is missing from the filter builder.
