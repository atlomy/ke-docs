Rename a field label

You can give any field in your collection a name that makes sense in your project's language — regardless of what the original source data called it. Your label is yours. Re-importing your source data never overwrites it.

Steps​

  1. Open the collection whose field you want to rename.
  2. Click Field Definitions in the toolbar or sidebar.
  3. Find the field in the list. Its current label appears in the Label column.
  4. Click the field's row to open its settings.
  5. Edit the Label field — type the name you want to use.
  6. Save.

The new label appears immediately in the table columns, in the record detail view, and in filters.

What the import sets and what you own​

When you first import a spreadsheet or data source, each field gets a label from your source — the exact column heading as it appears in the original file. For example, if your spreadsheet has a column called "Author full name", the label starts as "Author full name."

From that moment on, the label is yours:

What the import controlsWhat you control
The underlying field identity (which column this is)The label — what it is called in the workspace
The raw data valuesWhether the field is required
The field type detection (text, number, date…)Any notes or help text on the field

Re-importing the same source updates the data but does not touch your label. Even if the column heading changed in the source, your label is preserved. The import may tell you a column was renamed in the source (it will show as "new" + "removed" in the delta), but it will never silently overwrite what you typed.

Notes​

  • Your label has no length limit, but short and clear works best in table column headers.
  • Renaming a label does not change any data. Records are not affected.
  • Two fields in the same collection can share a label — the platform does not enforce uniqueness on labels. Unique field identities are managed internally.

Troubleshooting​

SymptomLikely causeFix
The Label field is not editable.Your role may not have permission to change field configuration.Ask a project administrator.
After renaming, the old name still appears in a filter chip.Filter chips may cache the name briefly. Refresh the page if the old name persists after a few seconds.Hard-refresh the browser (Cmd/Ctrl+Shift+R).
A re-import brought back the original source name.This should not happen: label is researcher-owned and never overwritten.If it did happen, it is a bug — please report it with the import project ID.
