What happens to saved views after a re-import

Your saved views are yours. A re-import never resets or overwrites a saved view. What you named it, which columns you included, how you sorted and filtered — all of that survives.

There is one exception: if a field that a view referenced is removed in the re-import (because it no longer exists in your source), the view adapts gracefully.

What survives a re-import​

A saved view stores:

  • Which columns are visible and in what order.
  • Column widths, pinning, and sort order.
  • Filter conditions and their values.
  • Row density setting.
  • The view's name.

All of this is preserved across re-imports. Data values may update (a field's value in a record changes to match the new source), but the view's layout and filters are not touched.

When a field is removed​

If your source data no longer includes a field that your saved view referenced — for example, you removed a column from your spreadsheet before re-importing — the platform handles it gracefully:

  • The view keeps working. The removed column is dropped from the display, but the rest of the view (its other columns, filters, sort) is unaffected.
  • The import delta tells you. The re-import summary names the removed field and lists which saved views were affected. You do not have to discover this by accident.
  • If the field comes back, a later re-import that includes the column again will restore it — and the view will include it again automatically.

What "graceful degradation" looks like​

If a saved view has a column that was removed:

  1. The view opens normally.
  2. The removed column is absent from the table.
  3. A notice at the top of the view (or in the views menu) indicates that one or more columns in this view are no longer available.
  4. Filters that reference the removed field are also suspended — the view does not try to filter on a field that no longer exists.

You can update the view (remove the reference to the missing column and save again) or leave it as-is and wait for the field to be restored.

Sharing a saved view with a colleague​

Sharing a saved view copies its URL. The recipient opens it with your layout and filters applied, subject to their own permissions. The URL does not embed data — it describes the view configuration only. See Share a search for how the URL encodes filter state.

Troubleshooting​

SymptomLikely causeFix
A column I pinned is gone from my view after a re-import.The field was removed in the re-import.Check the import delta summary for "removed" fields. Restore the field in your source and re-import, or update the saved view.
Filters in my saved view stopped returning results after a re-import.The field being filtered on was removed, or the value that was filtered on no longer exists in the updated data.Open the filter chips and verify each one; delete and re-create any that reference removed fields.
I see no notice about a degraded view but know a column is missing.The notice appears in the views panel; you may have dismissed it.Open the Saved views menu and look for any view marked with a warning indicator.
