Build a formula column

A formula column is computed from the row's other columns. You write the rule once; every row shows its own result, and the result follows the columns it reads — change a value in one of them and the formula's value changes with it. The column is read-only in the table: you edit the columns it reads, not the result.

Add a formula​

A formula is something a column has, not a separate kind of column. You can give one to a column you already have, or start a new column with one.

Give a formula to a column you already have

  1. Open the column's menu — Column actions on the column header, or right-click the header.
  2. Choose Add formula…. The column editor opens with the formula editor already showing.
  3. Build the formula (below). The preview under With your rows shows the result on five of the rows already loaded in your table, updating as you type.
  4. Click Save changes. The column becomes read-only in the table and shows a computed value in every row.

The column keeps the formatting it already had wherever the result can still use it — a money column whose formula returns a number is still shown as money, and a web-address column whose formula returns text is still shown as a link.

Start a new column with a formula

  1. Click + at the right end of the column headers (or Insert column… in a column's menu).
  2. Give the column a label, then open Change type… and pick Formula under Built from other fields. The card shows a sample formula and an Open the formula editor… button that takes you straight there.
  3. Build the formula and click Add column.

A linked-record column cannot take a formula. Its structure comes from the source it was linked from, so the menu shows Add formula… greyed out with the reason. Add a separate column for the formula instead.

Sentence mode: columns and text​

Sentence mode is for joining columns with text between them — a full name, a citation line, a label with a dash in it.

  • Type { where the column should go and pick it from the list that opens; the letters you type after { narrow the list. Or press Insert column at the end of the sentence to pick one for the caret. Chips move as one piece; a focused chip is removed with Backspace or Delete.
  • Type the text you want between chips straight into the sentence box.
  • When a column is empty, skip it — and the text glued to it (checked by default) drops the text next to a column when that column is empty in a row, so you do not get a stray dash after a missing translation.

Under Result the editor names what kind of value the formula produces — a sentence produces text.

Expression mode: functions and operators​

Switch the toggle to Expression to see the same formula written out — a sentence appears as Template("{column_key} — {other_key}", true) — and to go beyond what a sentence can say.

  • A column in the formula shows as a pill with the column's label (its key on hover). Typing { opens the list of columns to pick from, and the letters after it narrow the list. A pill is one piece: Delete or Backspace on a selected pill removes it whole. To swap a pill for another column, press Enter on it, double-click it, or press Backspace right after it — it reopens as text with the column list filtered to its label; Escape puts it back.
  • Text goes in double quotes; & joins pieces of text.
  • As you type a name, a list of matching columns and functions opens (columns first). Arrow keys move, Tab or Enter accepts, Escape closes; a function is inserted as Name( with the caret inside the parentheses, a column as a pill. After Link( the list offers your relation columns, after .Field( the linked table's columns, and after . the functions that apply to the value on the left.
  • Inside a function call a hint above the caret shows its signature with the argument you are on highlighted, plus a one-line description and an example. Functions below the box lists the whole catalogue with a search box.
  • The editor checks the expression as you type. The piece with a problem is underlined and the problem is explained under the box in words — "‘translatoin’ is not a column — did you mean Translation?" with a button that makes the replacement, or "Expected a comma or a closing parenthesis after Length(…)". While the expression has a problem the preview is empty, and the column cannot be saved until it is fixed.
  • Resting the caret on a piece of the formula (or hovering a pill) shows its value on the first preview row — a pill shows that row's cell, any other piece shows the whole formula's result for that row.

A formula that uses functions or operators the sentence cannot show stays in expression mode; the note "This formula uses functions the sentence cannot show" explains why the Sentence button is greyed out.

Some formulas produce a number, a date, or a yes/no value rather than text. Result names which, and the column is shown accordingly. Tick Store as text to keep the result as plain text instead.

Describe it instead of writing it​

If your project has drafting turned on and you are allowed to change columns, the editor offers Describe it — say what the column should show in your own words and get a formula back to check.

  1. Type the description under In your words, naming your own columns — for example "the title in capitals, then a dash, then the short summary".
  2. Click Draft it.
  3. The draft appears marked Proposed. Nothing is saved yet.
  4. Choose Use this to put the formula in the editor, Adjust by hand to edit it there, or Discard to drop it.

Sometimes there is no formula to choose between: if what you wrote left the platform with a question it cannot answer — a column it could not place, a rule it could not read — it comes back with the questions and no formula at all. Use this and Adjust by hand are not offered then, because there is nothing yet to use or edit. Answer what it asked by rewriting the description, and draft again.

A draft shows you four things:

  • the formula itself, not only a description of it — shown as column chips and the text between them when the draft is simple enough for the sentence view, and as the expression written out when it is not,
  • a sentence restating what it understood, in words,
  • how many of your columns it used and whether it found them all,
  • the result on your first rows.

Your column is not changed until you accept the draft and then save the column, so discarding one leaves the column exactly as it was. Each request does use part of the session's drafting allowance, and that is spent whether or not you keep the result — so a draft you discard is free of consequence for your data, not free of allowance.

A drafted formula is shown to you, not applied, and that matters when it names something your table does not have. The draft is returned as written — the unknown name still in it — with the problem stated as a question beside it, rather than quietly swapped for a guess. So a draft can carry a name that will not resolve until you change it.

That case also has no row results: the preview needs a formula the platform can read, so a draft naming something unresolved shows its questions and leaves the rows blank. Read the questions and the restating sentence, and where there are rows, read those too — a formula can be valid and still not be the one you meant.

If you do not see Describe it, either your account cannot change columns — which a project administrator can grant — or drafting is not turned on for your environment, which is set by the platform operator rather than from any project setting.

Comparing different spellings of the same word​

Formula comparisons are exact by default. That is useful when a spelling difference is part of the evidence, but it also means two visually similar forms can compare as different text.

Use Fold() on both sides when you want the comparison to behave like search:

  • Fold({Word}) = Fold({Variant})
  • Contains(Fold({Title}), Fold("βίος"))

Fold() follows the column's comparison setting. A column configured for exact comparison keeps its marks, so use an ordinary comparison there. Use Fold() inside a comparison rather than as the whole column value: it produces a search key, not display text. When an empty preview would gain answers from this change, the editor shows a notice with the number of affected rows.

Patterns​

Three functions, RegexMatch, RegexExtract and RegexReplace, take a pattern: a description of a shape of text rather than the exact text. RegexExtract({Citation}, "\d+") pulls the first run of digits out of a citation; RegexReplace({Note}, "\s+", " ") squeezes every run of spaces down to one.

Patterns here are written the way they are almost everywhere else, with these things worth knowing.

  • \w, \d and \s read whatever alphabet your text is written in. \w is a letter, digit or underscore in any script, so \w+ matches λόγος and café whole; \d is a digit in any numbering system, including ٤٢ and ४२; \s is any space, including the no-break space you get from pasted documents. \W, \D and \S are their opposites.
  • \p{Greek} names a script, and so do \p{Hebrew}, \p{Cyrillic}, \p{Han} and \p{Latin}; \p{L} is a letter in any of them. This is the dependable way to say "Greek letters"; a hand-written range like [Α-Ωα-ω] leaves out every accented form.
  • There is no \b. A word edge is refused rather than accepted, because the only kind available recognises A-Z, 0-9 and _ and nothing else: it would step straight over a word in Greek, Hebrew, Cyrillic or accented Latin and report that nothing was found. Write the edge as characters instead. To find or take out the word, (?:^|[^\w])(κόσμος)(?:[^\w]|$) hands back the word itself. To replace it, (^|[^\w])κόσμος([^\w]|$) with $1 and $2 in the new text, because the characters either side are part of what matched and would otherwise be replaced along with the word.
  • Replacing a word takes two passes when it can occur twice in a row. The character between two occurrences belongs to the first match, so a single replace resumes past the second and leaves it alone: RegexReplace("κόσμος κόσμος", "(^|[^\w])κόσμος([^\w]|$)", "$1λόγος$2") gives λόγος κόσμος. Feed that call into a second one with the same pattern and new text and every occurrence is replaced, however long the run. The RegexReplace entry in the function list shows the nested form to copy.
  • $ means the end of the value, not the end of a line. If a value ends in a line break, "ology$" will not match it; write "ology\n?$", or put (?m) at the front to make ^ and $ mean the start and end of each line. The value is searched exactly as it is stored, line breaks and all, so RegexReplace({Note}, "\s+$", "") takes a trailing line break off.
  • The flags you can set are (?i) to ignore case, (?m) for ^ and $ per line, and (?s) to let . match a line break.
  • (?i) reads the dotted and dotless I as one letter. I, i, İ and ı all match each other, so (?i)istanbul finds İstanbul and ıstanbul as well. Every other letter ignores case the way you would expect; this is the one pair where two scripts disagree about which capital belongs to which small letter, and ignoring case here joins all four. To keep them apart, leave (?i) off and write the letters you mean.
  • Write the pattern out in quotes. A pattern is part of the formula, not something read from a column, so RegexExtract({Citation}, {Pattern}) is refused as you type. A pattern taken from a column would be a different pattern in every row, which is both unknowable before you save and slow: on a preview of several rows it is seconds of preparing patterns before any searching starts.
  • A few things a pattern can do elsewhere are unavailable, so that no pattern can ever be slow on a large table: looking ahead or behind ((?=…), (?<=…)) and referring back to a group (\1). A pattern that uses one is refused as you type, in words, with what to write in its place. A pattern may be 500 characters long, searches at most 10,000 characters of a value, and a part in {} may repeat at most 1,000 times.
  • Those limits are not the only thing that can make a pattern too big. A part such as \w or \p{L} stands for every letter in every alphabet, so repeating one builds far more than its two characters suggest. A repeated \w reaches a few hundred rather than the full thousand, and a long run of such parts inside something that itself repeats can be refused as too large to build well before either published limit. The message says so, and the fix is smaller counts in {} or fewer parts. Nothing about \w+ or an unrepeated part is affected.

Change or remove a formula​

Open the column's menu and choose Edit formula… — the same editor opens on the formula the column already has.

To remove the formula, clear the expression in the editor and save. The column stops being computed and becomes editable again, keeping the kind of value it was producing: a formula that returned a number leaves a number column behind. Nothing is lost by removing it, because a formula's values were never stored — they were worked out each time the column was read.

A column that was created as a formula has no data path to fall back on, so clearing it cannot turn it into an ordinary column. The editor says so and asks you to add a new column instead. Columns that already held values before you gave them a formula are not affected.

In the table​

  • Cells of a formula column are read-only. To change a value, edit the columns the formula reads.
  • The column header names the kind of value it produces: Formula → text, Formula → number, and so on. The same line appears under Field key in the column's menu.

Publishing​

A formula column is published like any other column, with the value it holds at the time of publishing. Use Check before publishing (the Publish preflight experiment in Labs) to review what will be published before you do.

A published formula is only as open as the columns it reads. A formula carries the values of the columns it draws on, so publishing it would publish those values too — even where those columns are not public themselves. So the publish refuses instead.

If you publish a table whose public formula reads a workspace-only or private column, the receipt reads Published 0 · skipped … and every affected row is listed under … entries skipped — why. The entry for the formula names three things — the formula column, the visibility of the column it reads, and that column's name — with two buttons:

  • Make field public — raises the read column's visibility, resolving the block where you stand.
  • Remove from label — opens the Appearance settings, where what the published row is built from is declared. It moves you to the setting rather than changing it, so make the edit there and publish again.

The wording of these two buttons is written for a row's title rather than for a column. On a formula column they do what is described above, whichever noun they use.

Fixing the cause and publishing again is the whole remedy — nothing is partly published in the meantime, because a row that cannot publish cleanly is skipped whole.

The same refusal applies when the platform cannot work out what a formula reads: a formula it cannot analyse cannot be checked, so it does not publish until the formula is fixed.

Troubleshooting​

SymptomLikely causeFix
I want a formula on a column I already have.The formula lives on the column, so you do not need a new one.Open the column's menu and choose Add formula….
Add formula… is greyed out.The column is a linked-record column, whose structure comes from the source it was linked from.Add a separate column for the formula.
I cleared the formula but it will not save.The column was created as a formula, so it has no data path to become an ordinary column with.Add a new column of the kind you want, and delete this one.
The preview is empty.The expression has a problem (underlined, and explained under the box), or no rows are loaded in the table yet.Fix the problem named under the box; or load some rows and reopen the editor.
A column I typed as {key} did not become a pill.The caret is still inside the braces, or the braces are inside quotes — text in quotes is text.Move the caret past the closing brace; take the reference out of the quotes.
A dash or comma appears in a row where one of the columns is empty.The formula uses & in expression mode, which joins pieces as written.Use sentence mode with the skip-when-empty box checked, or write the formula so the empty case is handled.
The Sentence button is greyed out.The formula uses functions or operators the sentence cannot show.Keep editing in expression mode, or simplify the formula to columns and text only.
I cannot type in the column.Formula columns are computed, not entered.Edit the columns the formula reads; the result updates.
The editor says the formula is too long to read.A formula may be up to 10,000 characters. That is far more than any formula that can run: one is limited to 2,000 steps, and 2,000 steps written out is under 4,000 characters.Shorten the formula, or build the value across several columns and read one from the other.
A date formula says the pattern is too long.DateFormat and DateParse read a pattern of up to 200 characters, whether you write it out or read it from a column.Write the layout of a single date, such as DD/MM/YYYY. A pattern longer than this is not a date layout.
A number column shows blank and says the number is too large to record.Multiplying or adding two very large values makes a number past what the platform can store.Divide before you multiply, or scale the values down first, so the working numbers stay in range.
My pattern with \b in it is refused.The only word edge available recognises A-Z, 0-9 and _, so it would miss words in every other alphabet.Write the edge as characters instead. The form differs by function, so take it from the examples on RegexMatch, RegexExtract and RegexReplace in the function list, where each one is shown working.
My pattern is refused as too large to build, and it is well under 500 characters.A part such as \w, \d or \p{L} stands for every letter or digit in every alphabet, so repeating one many times builds far more than its length suggests.Use smaller counts in {}, or fewer repeated parts.
A formula is refused for a pattern that is in another column, not in what I wrote.A formula prepares the patterns of every column it reads as well as its own, and there is one allowance for all of them together. Several columns that each hold a large pattern are each fine on their own and too much to prepare at once.The message names the column whose pattern would not fit and the columns that used the allowance before it. Make one of those patterns smaller, or read fewer of those columns from one formula.
I put a column reference where the pattern goes and it was refused.A pattern is part of the formula. Read from a column it would differ in every row, so nothing about it could be checked before saving.Write the pattern out in quotes. If different rows need different handling, use one formula column per pattern, or use If on the result rather than on the pattern.
A pattern ending in $ matches nothing, on values that look right.The values end in a line break, and $ is the end of the value.Write \n?$ instead of $, or put (?m) at the front of the pattern.
