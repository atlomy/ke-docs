Color rows by rule

A row color rule belongs to one column. You pick a value and a color, and every row whose field holds exactly that value shows a stripe of that color at the left edge of the row, next to the row number. The row itself is unchanged — the stripe lets your eye pick out the matching rows while every column stays readable.

You can give several values of the same field their own colors — "Reviewed" in moss green, "Needs attention" in rose — and set rules on more than one column at the same time.

Create a rule​

  1. Click the ⋯ (Column actions) button on the column's header. Right-clicking the header opens the same menu.
  2. Select Conditional format.
  3. Under Color rows where value is, pick the value you want to highlight. For a choice field, the list offers the field's options; for other fields, it offers values found in the rows already loaded in the table.
  4. Select a color: Rose, Amber, Moss, Steel, Violet, or Graphite.

The stripes appear on the matching rows, and Saved with view shows next to the panel title. To color another value of the same field, pick it in the same list and choose its color.

See which rules are active​

  • The stripes themselves: a colored edge on a row means at least one rule matches it.
  • In a column's menu, the Conditional format entry reads Saved when that column has a rule.
  • Inside the Conditional format panel, the color marked with a check is the one assigned to the value shown in the list.

Rules are kept per column, so to review them, open each column's menu. A row shows one stripe color even when it matches rules on more than one column.

Remove a rule​

Open Conditional format on the column:

  • Clear value removes the color from the value currently shown in the list.
  • Clear this column's rules removes every value and color on that column. The button is there only while the column has a rule.

Changing or clearing color rules is a view change like any other: the Undo view change arrow in the toolbar restores what you cleared, and Redo view change re-applies it.

Rules are remembered by your views​

Color rules are part of the view, alongside filters, sort order, and column layout. They are stored on whichever view is active as you work, and they are waiting for you when you return. Duplicating a view copies its color rules; each view keeps its own set. See Save your table arrangement as a view.

Views are shared with everyone working in your environment. A color rule you add or clear on a view reaches your collaborators too — to highlight rows for your own work without changing what your team sees, duplicate the view first and set the rules in the copy.

Troubleshooting​

SymptomLikely causeFix
The value I want to color is not in the list.The list offers a choice field's options plus values found in rows already loaded in this table. A value no loaded row holds does not appear, and when a column holds many distinct values, the list offers only the first ones found.Check that at least one row in the table holds the value, then reopen the column menu.
The panel says no values are loaded yet.The column has no data in the rows loaded for this table.The value list appears once the column has data in the active table.
A row I expect to be colored shows no stripe.The rule matches the value exactly as it is displayed. The row's value may differ — a different option, extra wording, or another spelling.Compare the row's value with the value named in the rule, and add a rule for the variant if both forms are in use.
I colored a value, but a row shows a different color.The row also matches a rule on another column — a row shows one stripe color even when several rules match.Open the other columns' menus and clear the rule you no longer want.
My rules disappeared after switching view tabs.Each view keeps its own color rules.Switch back to the view where you set them, or set rules on the view that is now active.
My rule changes are not kept when I come back.Changes are stored on the active view — if your role is read-only on this table, the view cannot be changed.Ask your environment administrator for editing access.
