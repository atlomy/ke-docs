Workspace Walkthrough

Purpose​

The workspace is the table of records of one type — figures, terms, manuscript editions, anything your project tracks — wrapped in a toolbar, a left sidebar, and a set of view tabs. This page walks through what is on the screen, what each control does, and what a typical session looks like. Read it when you first open the workspace, when a control is doing something you did not expect, or when you want to set up a view you can come back to.

Features​

  • Workspace layout (Active) — every table opens in the same shell: a left sidebar listing your tables, a top bar with search and the command palette, a toolbar of table controls, and view tabs that switch between Table, Details, Relations, and Publish.
  • Workspace search (Active) — a quick search panel that finds records across the workspace, grouped by table. Results respect your permissions. When search cannot run, the panel says workspace search is unavailable rather than showing empty results.
  • Search & Read section (Active) — a full search page with a typeahead, an advanced field-condition filter, paged results, and a reading pane that opens a record beside the list. The page address encodes the whole search, so it can be shared or bookmarked.
  • Rows named by your display field (Active) — record labels in the table, the record panel, and search results use the display field your source declared, with a sensible fallback when none is declared.
  • Sidebar organizer and command palette (Active) — pin tables, create named groups, collapse or expand groups, see your recently opened tables, and reset the sidebar to its defaults. The command palette reaches all of these without leaving the keyboard.
  • Current-table quick filter (Active) — a toolbar box that narrows the rows already loaded in the active table. It is not a whole-workspace search.
  • Filters (Active) — composable filter conditions per field. The filter options match the field's type: text fields match typed text, number and year fields take a number, Date fields open a date picker, and choice fields offer their options. Active filters appear as removable chips.
  • Column manager (Active) — reorder, show or hide, search columns, and choose the display column; resize by dragging column edges in the table, and pin columns from the column header menu.
  • Saved views (Active) — named tabs that remember filters, sort, column layout, density, and row colors. Views belong to the table and are shared with everyone who works in your environment. Per-view sharing permissions are not yet available.
  • Density toggle (Active) — compact, cozy, or comfortable row height, remembered per view.
  • Record panel (Active) — open any record to see every field with its editor, related records, and a preview of the saved public page. Fields composed from other fields are labeled read-only — they cannot be edited directly.
  • Clipboard and batch actions (Active) — copy one cell, a rectangular cell range, targeted individual cells, or selected full rows. Selected rows can also be exported as CSV or raw JSON. Buttons labeled "Backend pending" — such as batch delete and batch visibility — are visible but not yet available.
  • Copy view link (Active) — copies a URL that opens the same view for a collaborator, subject to their own permissions.

Usability — how you use it​

Your knowledge environment has a sidebar listing the record types you can work with. Click one and you land in its workspace at /app/workspace/<record-type>/. You can bookmark and share the URL. If your project has several record types, each has its own workspace.

The default flow: search, filter, open, edit​

  1. Find a record across the workspace. Click Search database… in the top bar, or press Ctrl/Cmd+Shift+F. Type at least two characters. Choose Current table when you know the table, or All workspace when you do not — and in workspace scope you can still narrow to one table with the Table selector. Results are grouped by table; move with the arrow keys and press Enter, or click a result to open that record. The panel's Filter current table button hands your search words to the table's quick filter instead. When you want to browse and read many records at once, Open full Search & Read in the panel — or Search & Read in the command palette — opens the full search page, carrying your words over; see Searching and reading.
  2. Organize the left sidebar. Pin the tables you use most, gather tables into named groups, and collapse the groups you are not using. Recent lists the tables you opened last. Useful shortcuts: Ctrl/Cmd+K opens the command palette, Ctrl/Cmd+B collapses the sidebar to an icon rail, Ctrl/Cmd+Shift+G creates a group, and Shift+S pins or unpins the current table. Reset sidebar to default groups in the command palette puts everything back.
  3. Filter the table in front of you. Use the toolbar Filter visible rows box when you only need to narrow rows already loaded in the active table. This quick filter is transient and is not stored with the view.
  4. Add filters to narrow. Click Filter and pick a field. The options match the field's type — type a word for text fields, type a number for numeric fields, pick a calendar date for Date fields, or pick options for choice fields. A Date filter matches stored timestamps that fall on the same calendar date; a field that only looks like a timestamp but is still configured as Text keeps text-style matching. The match count updates as you set the condition. Filter chips appear in the toolbar after the "filtering by" lead-in. They compose. Remove a chip by clicking its ×; remove all of them with Clear.
  5. Tidy the columns. Click Columns to open the column manager: drag entries to reorder, uncheck columns to hide them, search by label or field key, and choose the display column. Resize a column by dragging its edge in the table itself. Pinning and wrap-text controls live in each column's header menu.
  6. Save the arrangement as a view. Views are the tabs above the table. Click + Add view, give it a name like "18th-century figures with manuscript citations", and it starts from your current arrangement. From then on, changes you make while that view is active — filters, sort, columns, density — are stored on the view as you go. The toolbar's Undo and Redo step view changes backward and forward.
  7. Open a record. Click the row's Open details button (at the row's actions end) and the record panel opens over the table: every field with its editor, related records, and a preview of the saved public page. Close it with the × in its header, with Escape, or by clicking outside it.
  8. Edit in the table. Double-click a cell to edit it. Short values save when you press Enter or move away; larger editors — long text, formatted text — have their own Save and Cancel buttons. Empty cells show empty so blanks are visible without looking like punctuation. Date fields use a date picker and display readable dates; text fields that contain timestamp-shaped strings stay raw text until the field type is changed or converted. If a value cannot be saved, the workspace tells you rather than silently dropping it.

Reading records side by side​

Switch to the Details tab. It splits the screen: a list of the table's records on one side and the full record on the other. Click through the list and the record pane follows; the list can be narrowed with its own filter box, so you can audit a slice or fact-check a draft against its neighbors without losing your place.

Batch operations​

Focus a row and press Space to select it. Use Ctrl/Cmd+Space to add or remove the focused row, and Shift with the arrow keys to extend the selection through a range. A batch toolbar appears showing the count. Copy TSV puts the rows on your clipboard, ready to paste into a spreadsheet. Download CSV downloads the selected records as a spreadsheet file, and JSON exports the raw row payload for technical workflows. Buttons labeled "Backend pending" are not yet available. Clear the selection with the toolbar's × or with Escape.

For cells rather than full rows, click a cell, drag or Shift-extend a rectangle, or turn on Target cells for non-adjacent cells. Cell copy and row copy are different: a cell range copies only cell values, while row copy includes the visible column labels for the selected records.

Sharing a view with a collaborator​

Click Copy link in the toolbar, or Copy view link in a view tab's menu. Paste the URL into chat or email. Your collaborator opens it and lands on the same view, subject to their own permissions.

What saved views remember (and how they are shared)​

A saved view remembers filters and their values, sort order, column layout (order, widths, pinning, hidden columns), row density, and row color rules. It does not remember the quick-filter text — that stays per-session so you do not accidentally land on yesterday's search.

Views belong to the table, not to you alone: everyone working in your environment sees the same view tabs, and changes to a view reach your collaborators too. Each view's tab menu offers Rename, Duplicate, Pin view, Set as default (the view the table opens with), Copy view link, and Delete view. Deleting a view removes it for everyone, so agree with your collaborators first — Duplicate is the safe way to experiment on a shared view.

Troubleshooting​

SymptomLikely causeFixWhere to escalate
A control mentioned here is missing or grayed out.The control depends on your role, or on a capability not yet available — grayed controls often say "Backend pending".Hover the control; its tooltip states the reason.Contact your environment administrator.
Columns you arranged reverted later.The changes were made outside a saved view, so nothing stored them.Click + Add view, name it, and arrange columns while that view is active — changes then stick.n/a
Search returns matches in an unexpected language or script form.The field stores several language or script forms, and search matches any of them.This is the intended behavior; see Searching and reading.Contact your environment administrator if matching is wrong for your project.
The top search finds a row but the toolbar box does not.They are different tools: the top search looks across the workspace, while the toolbar box only filters rows already loaded in the current table.Open the result from the top search, or switch to the right table before using the toolbar filter.n/a
The search panel says workspace search is unavailable.Your role does not include workspace search, or the search request failed.Try the search again; in the meantime, use the toolbar quick filter on the current table.Contact your environment administrator.
Editing a cell does nothing.The field is read-only — composed fields, for example, cannot be edited directly — or the value was rejected.Open the record panel and check the field there; rejected values show a message instead of saving silently.Contact your environment administrator about permissions.
The record panel will not close.A confirmation dialog is open and is catching the Escape key.Dismiss the dialog first, then press Escape.n/a
