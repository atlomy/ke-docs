Platform Monitoring

Audience: Super admin / platform operator Last aligned with platform state: 2026-05-25 Platform version: V2 (pre-1.0)

Purpose​

The platform monitoring surface is the operator's read-only window into how the platform is running across all tenants. It rolls up Import Wizard health, AI-assist call patterns, capture-failure incidents, recommender quality, tip rollups, and DPIA enablement audit rows into a single tabbed surface at /admin/monitoring/platform/, gated by require_platform_staff(...). Read this when you are paged, when you are running a routine health sweep, or before any change to platform telemetry posture. The surface is operational — nothing here mutates tenant state, and nothing here displays tenant payload.

Features​

Ordered by operational frequency — the first three are what most operator shifts touch.

  • Operations tab — ?tab=operations carries the capture-failure incident timeline, Bedrock invocation logging health card, and DPIA refresh trigger audit rows. Substrate: Spec 0018 Sprint C PRs #314, #315, #322 · Maturity: Built · Limit: read-only; ack contract is append-only.
  • Incident timeline — CaptureFailureIncidentCard cards with append-only ack contract, density preference persisted at the telemetry root, and PaPostureModal Esc + click-outside dismissal. Substrate: Spec 0018 PRs #401-#404 · Maturity: Built · Limit: ack is append-only; un-ack creates a new row.
  • Import Wizard operations — queued / running / stale counts, retry pressure, latest scheduler round, retention cleanup outcomes, parse / propose success-failure split, load probe evidence links. Substrate: PRs #344, #346, #350 + management commands run_import_wizard_jobs, inspect_import_wizard_jobs, cleanup_import_wizard_artifacts, probe_import_wizard_jobs · Maturity: Built · Limit: cross-tenant view shows opaque tenant refs only.
  • Recommender metrics tab — ?tab=recommender carries stratum-wide rejection-rate dashboards, low-prior shape-count lists, escalation timeline. Substrate: Spec 0018 PR #319 (US-C.6) + PR #322 (US-C.7.3 payload-level schema-name obfuscation) · Maturity: Built · Limit: K-anonymity floor (K=11 default per ADR-016 §A5) — cohorts below the floor are suppressed entirely. See recommender-metrics.md.
  • Tip rollup view — weekly PlatformEvent.EventType.TIP_ROLLUP aggregates, auto-pause transitions per tip family, TIP_ROLLUP_MIN_K setting honoured with a non-LOCALHOST code-level clamp. Substrate: Spec 0030 Phase 6.C/D PR #422 + R3 (TIP_ROLLUP_MIN_K) + R4 (clamp in atlomy/settings.py) · Maturity: Built · Limit: cohorts below TIP_ROLLUP_MIN_K are suppressed; the clamp only raises the floor, never lowers it. See tip-auto-pause.md.
  • Public rollup freshness — inspect_import_wizard_telemetry_rollups --json reports stale rollup lanes, failure-rate warnings, and missing expected import_wizard_* commands with opaque tenant refs. Substrate: management command + Spec 0018 telemetry rollups · Maturity: Built · Limit: public-schema aggregate; no payload-adjacent detail.
  • Vocabulary startup linter — guard against tenant vocabulary in platform code, fires during Django startup. Substrate: Spec 0018 PR #321 · Maturity: Built · Limit: structural guard — does not catch runtime concatenations.
  • Receipt audit records — Stage 6 receipt and Stage 3 applied-card receipt audit-trail integration. Substrate: Spec 0018 PR #320 · Maturity: Built · Limit: receipts are aggregate; not a copy of the underlying decision payload.

Usability — how you use it​

Routine shift sweep​

  1. Open /admin/monitoring/platform/?tab=operations. Scan the incident timeline for any open capture-failure cards. Triage each via the ack contract — see incident-operations.md for the ack workflow.
  2. Check the Bedrock invocation logging health card. If logging is degraded, the AI-assist surfaces still function but tenant-local telemetry will undercount; flag in the next handoff.
  3. Confirm the DPIA refresh trigger log shows no unacknowledged new-enablement rows. Any new row means a tenant just toggled DecisionEvent capture and the DPO needs to refresh that tenant's DPIA before the captured stream is treated as DPA-covered.
  4. Switch to ?tab=recommender. Scan the escalation timeline for stratum-wide rejection-rate spikes. Any spike past the calibration threshold is an operator-incident under ADR-035 §4.1.1.1.
  5. Open the tip rollup view. Note any tip family that auto-paused since the last sweep; check the admin-review PlatformEvent row for the transition rationale.
  6. Run python manage.py inspect_import_wizard_telemetry_rollups --json from the django_app container. Stale rollup lanes or missing expected commands surface as warning entries; route to the owner per the opaque tenant ref.

Pre-flight before changing capture posture​

Do not toggle TELEMETRY_CAPTURE_ENABLED (global) or any per-tenant TELEMETRY_CAPTURE override without:

  1. Confirming the DPIA refresh trigger audit path is live (?tab=operations shows a recent entry from a known prior toggle, not blank).
  2. Confirming PaPostureModal is reachable — the posture-acknowledgment modal must intercept the toggle.
  3. Confirming the hash chain on monitoring.PlatformEvent is intact — the integrity check should report ok since the most recent integrity audit.

Red lines — what the platform-tier UI must not display​

These rules are load-bearing. They are repeated and referenced from incident-operations.md, recommender-metrics.md, tip-auto-pause.md, and dpia-operations.md. Do not weaken or relocate them.

  • No source rows, no filenames, no staged paths, no source identifiers.
  • No document or table names, no job ids, no schema names.
  • No credential names, no secret_ref values, no tokens, no URL userinfo.
  • No raw prompts, no raw queries, no raw GraphQL or debug error payloads.
  • Tenant identification is via opaque tenant ref only — never tenant name, never schema name.
  • Cohorts below the K-anonymity floor are suppressed entirely; they do not render with an asterisk, they do not render at all.

The public-schema aggregate layer must not become a shortcut around tenant isolation. If an operator needs payload-adjacent detail, they must enter the tenant boundary and use the tenant-local telemetry or import ledger.

Troubleshooting​

  • Symptom: Workspace search shows "Search isn't enabled for this workspace yet." (server-side: UnratifiedSearchEngineError). Likely cause: the tenant's TenantSearchProfile.is_ratified is False — the ADR-011 production gate requires recorded Gate-1 / load / TCO evidence before a search engine serves production queries. This is the DESIGNED state for any tenant whose engine selection has not completed Task-8 ratification (as of 2026-06-10: every tenant). Fix (production): run the engine re-evaluation per docs/runbooks/adr011-task8-engine-reeval.md and ratify with evidence — never set is_ratified by hand. Fix (local dev only): set KE_SEARCH_ALLOW_UNRATIFIED=1 in the environment (committed default OFF; read at process boot — restart the app). Also verify the tenant has an active TenantMembership for the user carrying the can_review_proposals capability — the search resolver checks membership and capability BEFORE the ratification gate, and freshly recreated tenants may lack seeded memberships (tenant-lifecycle gap, board Active item).

  • Symptom: Incident timeline shows a capture-drop card with rising event count, no obvious tenant signal. Likely cause: Per-tenant TELEMETRY_CAPTURE override toggled mid-flight, or redaction Lambda lag. Fix: Acknowledge the card with class posture-toggle (if the audit row matches) or redaction-lag (if Bedrock logging health is also degraded). Open the matching DPIA log row to confirm the toggle. Escalate: see incident-operations.md — integrity-warning class escalates to the security on-call.

  • Symptom: Recommender tab shows a stratum-wide rejection-rate spike but no escalation row was written. Likely cause: The cohort fell below the K-anonymity floor mid-window — the spike is real but the cohort is now suppressed. Fix: Confirm by running the inspect command with an opaque tenant filter and checking whether the cohort count crossed K. If a tenant composition change is responsible, the escalation will fire on the next rollup window. Escalate: file under Spec 0018 §A.4 if recurring; the ADR-035 §4.1.1.1 path is the formal route.

  • Symptom: inspect_import_wizard_telemetry_rollups --json reports stale lanes for an opaque tenant ref. Likely cause: The tenant's scheduler round is wedged or the rollup command did not run in the last window. Fix: Enter the tenant boundary and run inspect_import_wizard_jobs to confirm the wedge, then run_import_wizard_jobs to clear. Escalate: if the wedge persists past two scheduler rounds, page the Import Wizard owner.

  • Symptom: Hash-chain integrity warning row appears in the incident timeline. Likely cause: An attempted mutation of an append-only row on monitoring.PlatformEvent was detected by the chain verifier (ADR-016 §3). Fix: Do not attempt to clear the warning. Capture the row reference and escalate immediately — this is an indicator of either a privileged-process bug or unauthorized DB access. Escalate: security on-call; do not push code changes touching monitoring/ until cleared.

  • Symptom: DPIA refresh trigger log shows an enablement row but no acting admin user id. Likely cause: Audit row was written from a background management command rather than the admin UI — should not happen in normal flow. Fix: Verify the per-tenant TELEMETRY_CAPTURE override audit (Spec 0018 H.8); if the audit row is also missing the acting admin, treat as an integrity event. Escalate: security on-call.

  • Symptom: Tip family auto-paused but sample_n < 5. Likely cause: Auto-pause policy violation or stale read on the rolling window. Fix: See tip-auto-pause.md troubleshooting — this is a known invariant violation. Escalate: Spec 0030 AC-11 owner.
