Recommender Metrics

Audience: Super admin / platform operator Last aligned with platform state: 2026-05-25 Platform version: V2 (pre-1.0)

Purpose​

The recommender metrics tab at /admin/monitoring/platform/?tab=recommender is the calibration channel's operator debugging surface. Read this when investigating low-confidence prediction patterns, a stratum-wide rejection-rate spike, or a rare-archetype shape that needs escalation review. The tab does not display tenant payload; all cross-tenant reads go through K-anonymized aggregates and opaque tenant refs.

Features​

  • Stratum-wide rejection-rate dashboard — acceptance vs rejection over time per stratum (archetype × slot-type × confidence band per ADR-033). Substrate: Spec 0018 PR #319 (US-C.6) · Maturity: Built · Limit: stratum cohorts below the K-anonymity floor are suppressed; they do not render with an asterisk, they do not render at all.
  • Low-prior shape-count lists — per-shape LOW_PRIOR_CONFIDENCE flagged-lists across tenants, rolled up to opaque-tenant-ref granularity. Substrate: Spec 0018 PR #319 · Maturity: Built · Limit: K-anonymity floor enforced; rare-archetype tail mitigated by payload-level obfuscation (see below).
  • Escalation event timeline — chronological list of stratum-wide rejection-rate spikes, prior-drift events, and anomaly detections that fire the ADR-035 §4.1.1.1 operator-incident workflow. Substrate: Spec 0018 PR #319 + ADR-035 §4.1.1.1 · Maturity: Built · Limit: entries are written to monitoring.PlatformEvent (hash-chained, append-only); operator cannot mutate.
  • Payload-level schema-name obfuscation — for rare-archetype edge cases where the small population shape itself would distinguish a tenant, the rollup layer obfuscates payload-derived schema-identifying tokens before they reach the aggregate. Substrate: Spec 0018 PR #322 (US-C.7.3) · Maturity: Built · Limit: the floor is no-schema-names, period — this is not a license to show schema names "lightly obfuscated" in any view.
  • Export gate — recommender metrics export gated by the can_export_recommender_metrics capability. Substrate: Spec 0018 §A.4 · Maturity: Built · Limit: export honours all red-line constraints; payload-adjacent detail is excluded by construction.

Usability — how you use it​

Investigating a rejection-rate spike​

  1. Open /admin/monitoring/platform/?tab=recommender and scroll the escalation timeline. Spikes that crossed the calibration threshold appear as rows; expand for detail.
  2. Cross-reference the stratum with the rejection-rate dashboard for that window. If the stratum is suppressed, the cohort has fallen below the K-anonymity floor (default K=11 per ADR-016 §A5) — see Troubleshooting below.
  3. If the spike correlates with a prior-drift event in the same window, the underlying archetype distribution has shifted across the platform; coordinate with the calibration channel owner per ADR-033 §11.2.
  4. If the spike correlates with a single opaque tenant ref's LOW_PRIOR_CONFIDENCE count rising, the issue may be tenant-local — file under the recommender's tenant-local diagnostics path; do not enter the tenant boundary from this tab.

Reviewing low-prior shapes​

  1. Open the low-prior shape-count list. Sort by count descending — high-count shapes are stable; tail shapes are the calibration risk surface.
  2. For any tail shape that distinguishes a single tenant by population (rare-archetype edge case), verify the payload-level obfuscation layer is active by spot-checking that no schema-identifying tokens appear in the rendered list. If a token slips through, treat as a red-line violation.

Pre-flight before exporting​

  • Confirm you carry the can_export_recommender_metrics capability.
  • The export inherits the K-anonymity floor and the no-schema-names red line; do not post-process the export in a way that would lower either guarantee.

Red lines​

Compact restatement of the canonical block from platform_monitoring.md (see there for the full list):

  • No schema names, no filenames, no source rows, no document or table names.
  • No raw prompts, no raw queries, no raw GraphQL or debug error payloads.
  • No credential names, no secret_ref values, no tokens, no URL userinfo.
  • Tenant identification is via opaque ref only — never tenant name, never schema name.
  • Cohorts below the K-anonymity floor (K=11 default per ADR-016 §A5) are suppressed entirely.

If payload-adjacent detail is required, enter the requesting tenant's boundary and use tenant-local telemetry. The public-schema aggregate layer is not a shortcut around tenant isolation.

Troubleshooting​

  • Symptom: A stratum-wide rejection-rate spike is visible in the time series but no escalation row was written. Likely cause: The cohort fell below the K-anonymity floor mid-window — the spike is real but the cohort is now suppressed from rendering and the ADR-035 §4.1.1.1 escalation did not fire. Fix: Wait for the next rollup window; if the cohort recovers above the floor, the escalation will fire then. If the cohort is structurally below the floor (rare archetype), use the calibration channel's tenant-local diagnostics rather than the platform tab. Escalate: ADR-033 §11.2 calibration owner.

  • Symptom: Low-prior shape-count list renders a token that looks like a schema name. Likely cause: Payload-level obfuscation regression — PR #322 did not catch this token shape, or the renderer bypassed the obfuscation layer. Fix: Do not screenshot or quote the token. Capture the row reference. Escalate: security on-call — this is a red-line violation; file under Spec 0018 US-C.7.3.

  • Symptom: Recommender tab returns an empty escalation timeline but the underlying monitoring.PlatformEvent table has recent rows. Likely cause: Either the GraphQL query is filtering by a stale capability check, or the hash-chain verifier is blocking reads pending reconciliation. Fix: Confirm can_export_recommender_metrics and the read capability are both granted; check the integrity check status on monitoring.PlatformEvent. Escalate: file under Spec 0018 §A.4 if the empty result reproduces after capability confirmation.

  • Symptom: Export download returns UnratifiedSearchEngineError upstream. Likely cause: The recommender export path is delegating a profile lookup to the search profile registry, and the requested profile is not ratified. Fix: Confirm the export request did not include an unratified profile parameter; the registry rejects unratified profiles by design. Escalate: search profile registry owner.

  • Symptom: A new stratum appears in the dashboard with implausibly high cohort count. Likely cause: A new archetype was promoted and the stratification is now folding previously-distinct cohorts. Fix: Cross-reference the recommender rollup window against archetype promotion events; the spike is structural, not behavioral. Escalate: ADR-033 §11.2 calibration owner if the structural shift was unannounced.
