Tip Auto-Pause

Audience: Super admin / platform operator Last aligned with platform state: 2026-05-25 Platform version: V2 (pre-1.0)

Purpose​

The tip recommendation engine surfaces in-product tips to researchers during workspace flows. To prevent researcher fatigue and structurally suppress low-quality tip families, the platform rolls up tip acceptance ratios on a weekly K-anonymized window and auto-pauses any family whose acceptance ratio falls below a quality floor. Read this when reviewing a recently auto-paused family, when configuring the K-floor setting in a new environment, or when an auto-pause transition was unexpected. The rollup never carries tenant-identifying payload.

Features​

  • Weekly tip rollup — PlatformEvent.EventType.TIP_ROLLUP rows on the public hash-chained monitoring.PlatformEvent ledger, each covering an opaque tenant ref × tip family × week window with acceptance / rejection / dismissal counts and the derived ratio. Substrate: Spec 0030 Phase 6.C + recommendations/services/tip_rollups.py · Maturity: Built · Limit: append-only; hash-chained per ADR-016.
  • Auto-pause policy — a tip family is auto-paused for a tenant when the rolling acceptance ratio is < 0.20 over 28 days AND the per-tenant rolling sample_n ≥ 5. Substrate: Spec 0030 Phase 6.D + AC-11 + recommendations/services/tip_auto_pause.py · Maturity: Built · Limit: below sample_n = 5 the family is not paused — the signal is too sparse to act on.
  • TIP_ROLLUP_MIN_K setting — environment variable that sets the K-anonymity floor for the TIP_ROLLUP cohort; default 5 per Spec 0030 AC-7. Substrate: Spec 0030 R3 absorption · Maturity: Built · Limit: this is a deliberately lower floor than the ADR-016 §A5 default of K=11 for general aggregates, justified by the per-family signal shape.
  • K-anonymity floor clamp — TIP_ROLLUP_MIN_K can only raise the floor, never lower it. In any non-LOCALHOST environment the production floor of 5 is clamped at code level in atlomy/settings.py. Substrate: Spec 0030 R4 absorption + atlomy/settings.py · Maturity: Built · Limit: a misconfigured staging or pilot .env cannot leak single-tenant identifiable telemetry into the immutable ledger; local dev (LOCALHOST=1) keeps full flexibility.
  • paused_at GraphQL filter — exposes auto-paused families to the platform telemetry queries. Substrate: Spec 0030 Phase 6.D · Maturity: Built · Limit: filter returns aggregate pause state per family; no per-user sequences.
  • Admin-review PlatformEvent on transition — every auto-pause transition writes an admin-review row so the operator can review and, if warranted, manually override. Substrate: Spec 0030 Phase 6.D · Maturity: Built · Limit: override is itself logged.

Usability — how you use it​

Reviewing an auto-paused family​

  1. Open the platform monitoring panel's tip rollup view (under /admin/monitoring/platform/). Find the family flagged paused — the admin-review PlatformEvent row for the transition carries the opaque tenant ref, the family identifier, the rolling acceptance ratio at transition, and the sample_n at transition.
  2. Confirm the policy invariant: acceptance_ratio < 0.20 AND sample_n >= 5. If both hold, the auto-pause is a correct application of policy.
  3. If the family should remain paused, no action — pause persists until the family is manually re-enabled or the policy is amended.
  4. If the family should be unpaused (operator judgment overrides the signal), use the admin override — the override writes an explicit admin-review row.

Configuring TIP_ROLLUP_MIN_K in a new environment​

  1. The default is 5; do not lower it. The clamp in atlomy/settings.py will reject any value below 5 in non-LOCALHOST environments.
  2. To raise the floor (more conservative K-anonymity), set TIP_ROLLUP_MIN_K=N where N > 5 in the environment's .env. The setting applies on next process restart.
  3. In LOCALHOST=1 development, the clamp is bypassed — local dev may set any floor for testing purposes. Do not propagate the local .env to staging or pilot.

Red lines​

Compact restatement of the canonical block from platform_monitoring.md (see there for the full list):

  • Tip rollups carry counts and ratios only — never tip text, never user ids, never per-user sequences.
  • No schema names, no filenames, no source rows.
  • Tenant identification is via opaque ref only.
  • Cohorts below TIP_ROLLUP_MIN_K (default 5; clamped non-LOCALHOST) are suppressed entirely.
  • The hash chain on monitoring.PlatformEvent prevents silent scrubbing — which is exactly why the K-floor clamp matters: a leaked single-tenant row cannot be removed after the fact.

Troubleshooting​

  • Symptom: Tip family auto-paused but sample_n < 5. Likely cause: Auto-pause policy invariant violation — either a stale read on the rolling window or a bug in the threshold comparator. Fix: Capture the admin-review row reference and the rollup window. Do not unpause without confirming the invariant — the underrun may be a transient artifact of window boundary. Escalate: Spec 0030 AC-11 owner; file under recommendations/services/tip_auto_pause.py.

  • Symptom: Django startup logs warn that TIP_ROLLUP_MIN_K was clamped. Likely cause: The .env set a value below 5 in a non-LOCALHOST environment. The clamp is functioning as designed — startup proceeds with the floor at 5. Fix: Update the .env to remove the under-floor value or set it to 5+. Escalate: not required — this is the R4 absorption working as intended; document the corrected .env in the environment handoff.

  • Symptom: paused_at GraphQL filter returns families that were not actually paused. Likely cause: The filter is reading from a stale cache of the public ledger, or the filter is matching on a transition row that was followed by an admin override unpause. Fix: Confirm by reading the latest TIP_ROLLUP rows for the family — the truth is on the ledger, not the cache. Escalate: Spec 0030 Phase 6.D owner if the cache is reproducibly stale.

  • Symptom: Weekly rollup window did not produce TIP_ROLLUP rows for an opaque tenant ref. Likely cause: The tenant fell below TIP_ROLLUP_MIN_K for the family in question and was suppressed at rollup time. Fix: This is correct behavior — sub-K cohorts do not produce ledger rows. If the suppression is unexpected, check whether the family had any acceptance events in the window. Escalate: only if a cohort that should pass K is missing.

  • Symptom: Admin override unpause did not write an admin-review row. Likely cause: The override path bypassed the audit write — either a direct DB mutation (forbidden) or a regression in the admin action. Fix: Do not push further overrides through this path. Verify with a fresh admin override that the audit row writes correctly. Escalate: security on-call if a direct DB mutation is suspected — the hash chain on monitoring.PlatformEvent will detect attempts.
