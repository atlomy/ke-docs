Incident Operations

Audience: Super admin / platform operator Last aligned with platform state: 2026-05-25 Platform version: V2 (pre-1.0)

Purpose​

The platform-tier incident dashboard at /admin/monitoring/platform/?tab=operations is where the operator triages, acknowledges, and closes capture-failure incidents across all tenants. Capture-failure incidents fire when a tenant's telemetry capture path drops events (DecisionEvent capture flag toggled mid-flight, redaction Lambda lag, SCP misconfiguration, hash-chain integrity warning). Read this when you are paged with an open card, when an acknowledgment did not register, or when running the routine shift sweep covered in platform_monitoring.md. Tenant payload never leaves the tenant boundary; the dashboard reads only K-anonymized aggregates and opaque tenant refs.

Features​

  • Incident timeline — chronological list of CaptureFailureIncidentCard cards. Substrate: Spec 0018 PR #401 (A — primitives + incident card) · Maturity: Built · Limit: read-only; cards sourced from monitoring.PlatformEvent.
  • Append-only ack contract — acknowledgments recorded as new PlatformEvent rows carrying the acting super admin id, incident reference, and ack reason class. Substrate: Spec 0018 PR #402 (B — backend ack contract + density preference) · Maturity: Built · Limit: append-only — un-ack creates a new row, never mutates the prior row; hash chain per ADR-016 §3 protects against silent rewrites.
  • Density preference — compact / comfortable timeline density, persisted at the telemetry root and shared across incident, recommender, and operations tabs. Substrate: Spec 0018 PR #402 · Maturity: Built · Limit: resets only on explicit user action.
  • PaPostureModal interaction polish — Esc dismisses, click-outside dismisses, confirm is keyboard-reachable and announces via aria-live. Substrate: Spec 0018 PR #403 · Maturity: Built · Limit: modal intercepts every posture toggle — do not bypass.
  • e2e coverage — Playwright pins render, ack, density toggle, modal dismissal paths. Substrate: Spec 0018 PR #404 (C — wire-up + CaptureFailureIncidentCard e2e) · Maturity: Validated · Limit: e2e covers the contract paths; novel incident classes need fresh coverage.

Usability — how you use it​

Triaging an open card​

  1. Open /admin/monitoring/platform/?tab=operations. Cards render newest first; open class filter is open by default.
  2. Click a card to expand. Each card carries the opaque tenant ref, incident class (capture-drop, redaction-lag, integrity-warning, posture-toggle), first-seen / last-seen timestamps, current event count, ack state, and last actor.
  3. Choose the ack reason class that matches the root cause. The five classes are: posture-toggle (audit row confirms a DecisionEvent capture toggle), redaction-lag (Bedrock invocation logging health degraded), infra-incident (matches an active infrastructure ticket), false-positive (confirmed via the inspect commands), and escalated-security (integrity warning routed to security on-call).
  4. Click Acknowledge. The ack writes a new PlatformEvent row; the card moves to the acknowledged swimlane.
  5. Close the card when the underlying cause is resolved. Close writes another append-only row.

Pre-flight before changing global capture posture​

  • Do not toggle TELEMETRY_CAPTURE_ENABLED (global) without confirming the PaPostureModal is reachable.
  • Do not bypass the modal — the posture-acknowledgment is the record of operator intent.
  • Confirm a recent integrity check on monitoring.PlatformEvent reports ok before any capture-posture change.

Red lines​

This page inherits the canonical red-lines block from platform_monitoring.md. No source rows, no filenames, no staged paths, no schema names, no credential names, no secret_ref values, no tokens, no URL userinfo, no raw prompts, no raw queries, no raw GraphQL or debug error payloads. Tenant identification is via opaque ref only. If incident detail requires payload-adjacent inspection, enter the requesting tenant's boundary and use tenant-local telemetry.

Troubleshooting​

  • Symptom: Acknowledged a card but it still appears in the open swimlane. Likely cause: The ack row was written but the timeline cache has not refreshed, or the ack reason class did not match the incident class invariant. Fix: Refresh the tab; if still open, run the integrity check on monitoring.PlatformEvent — a chain anomaly will block the ack from rendering. Escalate: security on-call if the integrity check reports anything other than ok.

  • Symptom: PaPostureModal does not appear when toggling capture posture. Likely cause: The modal intercept was bypassed by a programmatic toggle (e.g., a management command run with the wrong flag), or the SPA bundle is stale and missing the PR #403 intercept. Fix: Reload the admin page; if still absent, check the SPA build date and re-deploy. Escalate: if the audit row landed without a modal interaction, this is a contract violation — file under Spec 0018 H.8.

  • Symptom: Integrity warning card with rising event count. Likely cause: Detected attempt to mutate an append-only PlatformEvent row, or a hash-chain mismatch on the latest verifier sweep. Fix: Do not attempt to ack-and-close. Capture the row reference and the verifier output. Escalate: security on-call immediately; do not push code touching monitoring/ until the chain is reconciled.

  • Symptom: Density preference reverts to default on every page load. Likely cause: Telemetry root context is not persisting the preference — either the SPA bundle is stale (pre-PR #402) or local storage is being cleared by a browser extension. Fix: Confirm the SPA build includes PR #402; try a different browser profile to rule out extension interference. Escalate: file under Spec 0018 PR #402 if reproducible in a clean profile.

  • Symptom: CaptureFailureIncidentCard displays a tenant name rather than an opaque ref. Likely cause: Severe — the card payload bypassed the obfuscation layer. Fix: Capture the card reference, do not screenshot or quote the tenant name in any escalation artifact. Escalate: security on-call immediately — this is a red-line violation.
