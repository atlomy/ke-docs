Secrets Management

Audience: Super admin / platform operator Last aligned with platform state: 2026-05-25 Platform version: V2 (pre-1.0)

Purpose​

The platform never stores raw third-party API keys, OAuth tokens, database passwords, or other static credentials in tenant tables or committed env files. The ExternalServiceCredential substrate stores tenant-owned references to a backing secret backend (environment variable, AWS Secrets Manager, or a no-secret federated marker). Raw secret material is resolved server-side at request time and is never written back to the database, job payloads, telemetry, or operator-facing surfaces. Read this when adding, validating, rotating, auditing, or revoking those references — and before any change that might cause resolved secret material to enter a log, payload, or response.

Features​

  • ExternalServiceCredential model — row carries tenant, provider, auth_scheme, secret_backend, secret_ref, allowed_features, non-secret metadata, status, plus usage counters (usage_count, last_used_at) and validation telemetry (last_validated_at, last_validation_status, last_validation_error_class). Substrate: customers/models.py + customers/services/external_credentials.py · Maturity: Built · Limit: row is reference-only; resolved secret bytes never persist.
  • Server-side resolution — resolve_external_service_credential(...) dispatches on secret_backend. Substrate: customers/services/external_credentials.py · Maturity: Built · Limit: raw secret crosses process memory only; never serialized into logs, payloads, or HTTP responses by the resolver.
  • AWS Secrets Manager backend — first live cloud backend; references via secret name or full ARN. Substrate: Spec 0011 / ADR-017 Phase 2.A external-credential substrate · Maturity: Built · Limit: scope IAM policies to specific ARNs, never *.
  • Validate admin action — updates last_validated_at, last_validation_status (ok / not_allowed / unavailable), and last_validation_error_class. Substrate: customers/admin.py ExternalServiceCredentialAdmin · Maturity: Built · Limit: validation does not increment usage_count and does not persist resolved secret or provider error payload.
  • Status-based revocation — status = disabled cuts access immediately; resolver only matches status = active. Substrate: model + resolver · Maturity: Built · Limit: background jobs holding a resolved secret in process memory are bounded by their lock timeout.
  • Auth schemes supported today — api_token, database_password, oauth2_auth_code, oauth2_client_credentials, oidc_federation, saml_sso, aws_iam_role, iam_database_auth, kerberos, service_account. Substrate: enum on ExternalServiceCredential · Maturity: Mixed — api_token and database_password are live in production; OAuth flows are wired at the model layer but provider callback handlers remain in design.

Usability — how you use it​

Adding a new credential reference​

  1. Navigate to /admin/customers/externalservicecredential/ — the model is registered via customers/admin.py.
  2. Fill in: tenant, name (e.g. coda-primary), provider, auth_scheme, secret_backend, secret_ref, and allowed_features (JSON list of feature keys, e.g. ["import_wizard_coda"]).
  3. Provide non-secret metadata only — the model rejects credential-like keys. For AWS Secrets Manager this is where region_name, endpoint_url, version_id, version_stage, or value_field (JSON path inside the secret payload) belong.
  4. Status defaults to needs_review. Run the admin Validate action. The row updates last_validated_at, last_validation_status, and last_validation_error_class.
  5. Promote status to active once validation reports ok.

AWS Secrets Manager — operational notes​

  • IAM permissions required for the platform's principal: at minimum secretsmanager:GetSecretValue on the specific secret ARN(s) referenced by secret_ref. For rotation workflows that surface to the operator, secretsmanager:DescribeSecret is useful but not required by the resolver. Scope IAM policies to the specific ARN, never *.
  • Reference format in secret_ref: either the secret name (resolved in the principal's default region) or the full ARN. If the secret is JSON, set metadata.value_field to a dotted path (e.g. bearer.token) to extract a single scalar field.
  • Region / endpoint: provide metadata.region_name and optionally metadata.endpoint_url; otherwise boto3 falls back to the principal's ambient configuration.
  • Resolve failure: any BotoCoreError, ClientError, missing SecretString / SecretBinary, empty value, or invalid JSON path raises ExternalCredentialUnavailable; validation records status unavailable and the exception class name only. Callers fall back to documented failure modes — no silent degradation.
  • Rotation: rotate at AWS. Because secret_ref is the ARN or name, the platform reference does not change; re-run admin Validate to confirm ok.

Revoking access​

  • Preferred: set status = disabled on the row. The resolver only matches status = active, so disabling cuts access immediately and preserves a clear audit trail.
  • Also valid: revoke or delete the backing secret (rotate the AWS-SM secret, unset the env var). Future resolves return unavailable.

OAuth posture​

OAuth auth schemes (oauth2_auth_code, oauth2_client_credentials, oidc_federation, saml_sso) are wired at the auth_scheme enum but provider callback handlers are still in design. New OAuth providers must go through the third-party integration auth checklist before any client-id, client-secret, or refresh-token storage path lands. Do not short-circuit the checklist by storing OAuth client secrets as api_token.

Red lines​

The platform must not, in any operator-facing surface, telemetry row, log, or job payload:

  • Display resolved secret values, raw tokens, raw passwords, OAuth refresh tokens, URL userinfo, OAuth callback URLs, or userinfo payloads.
  • Display full AWS Secrets Manager ARNs or full backend provider error payloads — operator validation surfaces report only ok / not_allowed / unavailable plus the exception class name.
  • Carry resolved secret bytes in the public-schema aggregate layer. The public schema may carry opaque tenant refs and credential counts only, never secret_ref values or resolved material.
  • print() or log resolved credentials anywhere in the codebase. Pre-commit enforcement is currently by code review pending a dedicated lint alongside lint_no_tenant_vocabulary.py.
  • Reflect a backend's raw error payload back to the operator. The validation flow stores only status[:32] and error_class[:100] — preserve that contract in any new resolver.

Troubleshooting​

  • Symptom: ExternalCredentialUnavailable raised at request time after a recent AWS Secrets Manager rotation. Likely cause: The secret was rotated at AWS but the operator did not re-run admin Validate, so the row still reports a stale last_validation_status. The resolver succeeds in fetching the new value but the rotation may have changed the JSON shape, the value_field path, or the principal's IAM access. Fix: Re-run admin Validate; check last_validation_error_class for the exception class name. If value_field no longer resolves, update metadata.value_field. Escalate: AWS account owner if the IAM scope is the cause.

  • Symptom: Validation returns not_allowed despite the IAM principal having secretsmanager:GetSecretValue on the ARN. Likely cause: The allowed_features JSON list does not include the requesting feature key, or the row's status is not active. The not_allowed status is a feature-gate result, not an IAM result. Fix: Update allowed_features to include the feature key (e.g., ["import_wizard_coda"]) and confirm status = active. Escalate: not required; this is a configuration issue.

  • Symptom: IAM policy scoped to * triggered an audit finding. Likely cause: An ARN-scoped policy was widened to * for convenience. The red lines require ARN-specific scoping. Fix: Narrow the IAM policy to the specific secret ARN(s). Escalate: security on-call if the wildcard was deployed to production.

  • Symptom: OAuth client secret was stored as auth_scheme = api_token. Likely cause: An operator short-circuited the third-party integration auth checklist. Fix: Set status = disabled on the row immediately. Rotate the OAuth client secret at the provider. Re-onboard the OAuth flow under the correct auth scheme once the callback handler design lands. Escalate: security on-call.

  • Symptom: A telemetry row or log line appears to carry a resolved secret value or URL userinfo. Likely cause: Severe red-line violation — a new code path bypassed the resolver discipline. Fix: Capture the row or log reference. Do not screenshot or quote the resolved material. Set the originating credential row to status = disabled and rotate the backing secret. Escalate: security on-call immediately.

  • Symptom: usage_count is incrementing on a disabled row. Likely cause: A background job is holding a resolved secret in process memory and continues to log usage. Fix: Wait for the job's lock timeout to expire; revocation propagates within one resolver round. If the increments persist past the lock timeout, treat as an integrity event. Escalate: security on-call if the increments do not stop.

Provider scope today​

Live and shipped: Coda (api_token over env or aws_secrets_manager), MySQL live connection (database_password or iam_database_auth; staged-dump uploads need no credential), AWS Bedrock (aws_iam_role preferred, token-backed fallback), AWS Secrets Manager (backend, live), Wikidata and PeriodO (no-secret federated; secret_backend = none with a federation-capable auth_scheme).

Planned, not yet shipped: HashiCorp Vault, GCP Secret Manager, Azure Key Vault, full OAuth callback handlers for oauth2_auth_code / oauth2_client_credentials.
