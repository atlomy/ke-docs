Django Template Resolution Conflicts: Unfold vs. Tenant-schemas

This document details the issues encountered when integrating django-unfold with django-tenants (or django-tenant-schemas) and the patterns used to resolve them.

The Problem​

When django-tenants is used, it MUST be the first app in INSTALLED_APPS to properly intercept requests and route tenants. However, django-tenants provides its own admin templates (specifically admin/index.html and potentially others) to support tenant-specific features.

Because django-tenants is loaded first, its templates take precedence over django-unfold's templates, effectively "masking" the Unfold UI elements.

Symptoms​

  • Missing Sidebar: The admin/nav_sidebar.html is resolved to django-tenants (or standard admin) version, which may yield an empty result or one incompatible with Unfold's CSS/JS.
  • Partial Unfold UI: You might see Unfold's dashboard widgets (if you've customized dashboard_callback) but wrapped in the old Django frame.
  • Header Issues: The header may lack Unfold's specific toggle buttons or user menu styling.

Diagnosis Pattern​

To confirm this issue, use a script to check template resolution order:

from django.template.loader import get_template
t = get_template('admin/index.html')
print(t.origin.name)
# If this points to django_tenants/templates/... instead of unfold/templates...
# then you have a conflict.

The Fix: Local Template Overrides with Explicit Inheritance​

The robust solution is to create local overrides in your project's templates/admin/ directory that explicitly force the use of Unfold's base templates.

1. Force index.html Inheritance​

In templates/admin/index.html:

{% extends 'unfold/layouts/base.html' %} 
{# Do NOT extend 'admin/base.html' or 'admin/base_site.html' if they resolves to the wrong parent #}

{% block content %}
    {# Your dashboard content #}
    {% include "unfold/helpers/dashboard.html" %}
{% endblock %}

2. Force Sidebar Loading​

In templates/admin/nav_sidebar.html: Bypass the resolution mechanism by locally providing the Unfold code. This ensures {% include "admin/nav_sidebar.html" %} calls your file, which contains the correct Unfold logic.

Critical Tweak: If AlpineJS or CSS hiding logic conflicts (e.g., sidebar stays hidden), you may need to strip the visibility classes:

<div class="relative z-60">
    <!-- Removed 'hidden' and restrictive x-bind classes to ensure permanent visibility -->
    <div class="fixed xl:relative xl:block w-[288px] ...">
        {% include "unfold/helpers/navigation.html" %}
    </div>
</div>

Summary​

In a multi-tenant setup:

  1. Priority: App order matters. Tenant apps must come first.
  2. Conflict: Early apps "win" template names like admin/index.html.
  3. Resolution: Local project templates (in DIRS) win over all apps. Use local templates to explicitly {% extend %} or {% include %} the specific library templates you want (e.g. unfold/...), bypassing the ambiguous standard names.
