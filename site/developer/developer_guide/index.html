Overview​

This guide covers three major systems:

  • Sync Pipeline: Bi-directional data synchronization between Django ↔ retired external no-code surface
  • Platform Monitoring: Cross-tenant metrics, alerts, and observability
  • Testing Infrastructure: Production-grade pytest suite

V2 telemetry note (2026-05-15): this guide is historical for the retired sync/monitoring substrate. Current V2 telemetry lives in ADR-016 and docs/product/v2/features/telemetry.md. Import Wizard metrics use tenant-local telemetry_ingestion_run rows and sanitized run_metrics behind TELEMETRY_CAPTURE_ENABLED; they do not use the older PlatformMetric sync collector path described below. Tenant-admin and superadmin metrics UI tasks are tracked in Spec 0011 F0b-telemetry.

Key Features​

✅ Async Processing - Non-blocking webhooks via Celery ✅ Idempotency - Timestamp validation prevents data overwrites ✅ Conflict Resolution - Automatic + manual strategies ✅ DLQ - Failed tasks quarantined for inspection ✅ Auto-Cleanup - Celery Beat manages retention ✅ Platform Metrics - Cross-tenant monitoring (superuser)

Data Flow​

retired external no-code surface Webhook → Django View → Celery Task Queue → Worker
                                      ↓
                                SyncLog (audit)
                                      ↓
                           Django Model (tenant schema)
                                      ↓
                          Signal Handler (if bidirectional)
                                      ↓
                           Push to retired external no-code surface (idempotency check)

Core Components​

1. Webhook Receiver​

Endpoint: /admin/retired external no-code surface/webhook/ Security: HMAC signature verification

2. Celery Tasks​

File: retired external no-code surface/tasks.py

Tasks:

  • handle_retired external no-code surface_webhook_task - Process incoming webhooks
  • sync_table_data_task - Bulk sync operations
  • cleanup_old_sync_logs - Auto-cleanup (30d/90d retention)

Retry Logic:

  • Max 3 retries
  • Exponential backoff (60s, 120s, 240s)
  • DLQ after final failure

3. Sync Service​

File: retired external no-code surface/services/sync.py

Functions:

sync_record(mapping, event_type, data)
  └─> should_apply_update()  # Idempotency check

push_to_retired external no-code surface(instance, mapping, event_type)
  └─> should_push_update_to_retired external no-code surface()  # Bi-directional idempotency
  └─> detect_conflict()  # Concurrent update detection

transform_django_to_retired external no-code surface(instance)  # Generic field mapping
transform_retired external no-code surface_to_django(data)      # Reverse mapping

Idempotency Rules:

if incoming_timestamp >= existing_timestamp:
    apply_update()
else:
    reject_update()  # Log as "Skipped: existing data is newer"

4. Signal Handlers​

File: retired external no-code surface/signals.py

Signals:

  • post_save → sync_to_retired external no-code surface_on_save
  • post_delete → sync_to_retired external no-code surface_on_delete

Loop Prevention:

_sync_context = local()  # Thread-local storage

@receiver(post_save)
def sync_to_retired external no-code surface_on_save(sender, instance, **kwargs):
    if is_syncing_from_retired external no-code surface():
        return  # Prevent infinite loop

### Multi-Tenant Testing Patterns

**1. Tenant Awareness (`TenantAPIClient`)**:
Standard `APIClient` will fail with 404 because it doesn't set the `HTTP_HOST`.
```python
class TenantAPIClient(APIClient):
    def generic(self, method, path, data='', **extra):
        # Must match the Domain object created in test_tenant fixture
        extra['HTTP_HOST'] = 'tenant.example.com'
        return super().generic(method, path, data, **extra)

2. Schema Context Safety: Always wrap tenant creation in public schema context to prevent leaks.

from django_tenants.utils import schema_context

@pytest.fixture
def test_tenant(db):
    with schema_context('public'):  # CRITICAL
        tenant = Client.objects.create(...)
        Domain.objects.create(tenant=tenant, domain='tenant.example.com')
        return tenant

3. Signal Isolation: Disconnect retired external no-code surface provisioning signals during tests to avoid async race conditions.

@pytest.fixture(autouse=True)
def disable_retired external no-code surface_signals():
    # Disconnect
    signals.post_save.disconnect(provision_retired external no-code surface_workspace, sender=Client)
    yield
    # Reconnect
    signals.post_save.connect(provision_retired external no-code surface_workspace, sender=Client)

Troubleshooting​

Sync Issues​

Problem: Records not syncing Check:

  1. Celery worker running? celery -A atlomy status
  2. Table mapping active? Check is_active=True
  3. Sync direction correct? Check sync_direction field
  4. Webhooks received? Check SyncLog entries

Problem: Old data overwriting new Solution: Check UpdatedAt timestamps in logs → Idempotency working

Problem: Celery tasks failing Check:

  1. DLQ entries: /admin/retired external no-code surface/synclog/?retired external no-code surface_id__exact=DLQ
  2. Error messages in SyncLog
  3. Celery worker logs

Monitoring Issues​

Problem: No platform metrics Check:

  1. Logged in as superuser?
  2. On public schema?
  3. Celery Beat running? Check collect-platform-metrics schedule

Problem: Metrics not updating Solution: Run manually: from monitoring.collectors import collect_all_metrics; collect_all_metrics()

Common Errors​

SyncLog matching query does not exist → No table mapping for this retired external no-code surface table. Create mapping in admin.

AttributeError: 'NoneType' object has no attribute 'retired external no-code surface_id' → Django model missing retired external no-code surface_id field. Add migration.

django.db.utils.OperationalError: relation does not exist → Run migrations for all schemas: python manage.py migrate_schemas

Frontend & API Architecture (Sprint 12-13)​

Authentication (JWT)​

The platform uses djangorestframework-simplejwt for secure, stateless authentication.

Endpoints:

  • POST /api/token/: Obtain access & refresh tokens
  • POST /api/token/refresh/: Refresh expired access token

Frontend Hook (useAuth): Automatically handles token storage (localStorage) and rotation, intercepting 401s to refresh tokens transparently.

React SPAs​

Standalone React 19 apps embedded via Django templates:

  1. Knowledge Explorer: spa/src/apps/knowledge_explorer (Search & Browse)
  2. Data Import: spa/src/apps/data_import (AI-Assisted CSV Import)
  3. Database Visualizer: spa/src/apps/db_visualizer (Schema Design)

Integration Pattern:

  • Django serves index.html template.
  • React app mounts to root div.
  • App communicates via REST API /api/v1/ using JWT.

Data Import API​

Unified endpoint for AI-assisted data ingestion:

  • POST /api/v1/import/upload/: Analyze CSV & Suggest Mapping (LLM)
  • POST /api/v1/import/templates/auto_detect/: Match CSV headers to saved templates
  • POST /api/v1/import/confirm/: Execute import (Create Lemma/Reference objects)

Performance Optimization​

Sync Pipeline​

  • Async Processing: Webhooks return 202 in <10ms
  • Batch Operations: sync_table_data_task for bulk sync
  • Indexing: SyncLog indexed by created_at, mapping, success

Monitoring​

  • 7-Day Retention: Auto-cleanup prevents table bloat
  • 5-Min Collection: Balance between freshness and DB load
  • Aggregation: Pre-computed metrics reduce query time

Database​

  • Connection Pooling: Configured in settings.DATABASES
  • Read Replicas: Separate monitoring queries (future)
  • Partitioning: Time-based for SyncLog (future)

Security Considerations​

  1. Webhook Signatures: HMAC verification required
  2. Superuser Only: Platform dashboard restricted
  3. Schema Isolation: Tenants can't access others' data
  4. API Tokens: Stored encrypted (future enhancement)
  5. DLQ Inspection: Manual review of failed data
