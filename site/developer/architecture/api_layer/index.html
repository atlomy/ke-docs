Architecture: API & Authentication Layer

Overview​

Atlomy Atlas utilizes a Dual-Layer API Strategy to support both legacy server-side rendering and modern single-page applications (SPAs).

Authentication Strategy​

We employ a hybrid authentication model to cater to different client types while maintaining security.

1. Dual Authentication Classes​

Configured in settings.REST_FRAMEWORK, the system accepts both:

  • SessionAuthentication: For Django Admin, server-rendered views, and legacy features. Uses standard Django session cookies.
  • JWTAuthentication (rest_framework_simplejwt): For React SPAs (e.g., Knowledge Explorer) and external clients.

2. JWT Configuration​

  • Library: djangorestframework-simplejwt
  • Access Token: Short-lived (60 minutes) for security.
  • Refresh Token: Long-lived (7 days) with rotation enabled. usage of a refresh token issues a new one, preventing replay attacks.
  • Endpoints:
    • POST /api/token/: Obtain pair.
    • POST /api/token/refresh/: Refresh access token.

REST API Design (/api/v1/)​

The REST API is built with Django Rest Framework (DRF) and follows these standards.

Versioning​

  • Strategy: URL Path Versioning.
  • Namespace: /api/v1/.
  • Rationale: Allows for breaking changes in future v2 without disrupting existing clients.

ViewSets & Resources​

We use ReadOnlyModelViewSet for most data access, ensuring safe, browsable APIs.

  • Lemmas: /api/v1/lemmas/
    • Supports full CRUD (restricted by permissions).
    • Includes custom actions like /stats/.
  • References: /api/v1/references/
    • Read-only access to citation data.

Filtering & Search​

We use django-filter for robust, URL-parameter based filtering.

  • FilterBackends: DjangoFilterBackend, SearchFilter, OrderingFilter.
  • Faceted Search:
    • ?language=ar: Exact match filtering.
    • ?search=term: Full-text search across multiple weighted fields (lemma, definition, etc.).
    • ?ordering=-id: Dynamic sorting.

Pagination​

  • Class: LimitOffsetPagination.
  • Default: 50 items per page.
  • Client Control: Clients can request specific pages via ?limit=N&offset=N.

Future Considerations​

  • GraphQL: Planned for complex, graph-like queries (e.g., relationships between lemmas and models).
  • Throttling: To be implemented if public API access is enabled.
