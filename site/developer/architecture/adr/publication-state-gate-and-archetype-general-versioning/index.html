ADR 047: Publication-State Gate for Public Reads + Archetype-General Post-Publish Versioning

  • Status: Accepted (ratified 2026-05-28, with R1-absorption amendments folded in — see § "R1 NotebookLM Absorption — Ratified Amendments")
  • Date: 2026-05-28
  • Deciders: Premshay (platform owner, ratifying Builder), assistant
  • Context source: GraphQL anonymous-exposure security pass (fix/graphql-search-authz), decision-log 2026-05-28, devlog 2026_w22/2026-05-28_1209_codex-review-request-graphql-search-authz.md

Ratification note (2026-05-28). Phase 1 shipped and merged (PRs #430/#431). The R1 NotebookLM absorption + standards research produced four amendments, now ratified by the platform owner. They are authoritative where they refine the original Context/Decision below. Specifically, the ratified amendments supersede (a) the Context's framing of post-publish versioning as "academic-standards-compliance critical" — the standards research corrected this to optional editorial policy above a platform-canonical compliance floor (amendments #1, #3); and (b) Decision §4's wholesale generalization of ADR-022's MEDIA REVISION/EDITION pattern — amendment #2 disaggregates it. The original Context/Decision/Alternatives are retained unedited as the historical record of what was known at decision time.

Context​

The GraphQL hardening pass surfaced that the public Entry Surface reader does not enforce the publication boundary that Spec 0009 already decided. The Task-1 contract (publication-readiness-contracts.md, Accepted 2026-05-12) defines two orthogonal axes: publication_state (draft / published / unpublished / tombstoned) is the public-visibility decision (only published is "Included"); projection_status (pending / current) is build-readiness. ADR-029 frames the boundary identically.

The implementation diverged: every public read gates on projection_status=CURRENT and never filters publication_state — _base_queryset (search/index/autocomplete), EntryRouteResolver._resolve_projection (entry_detail, which filters neither axis), and _materialized_index_rows. EntryProjectionBuilder.rebuild_role builds CURRENT projections leaving publication_state at its DRAFT default; only EntryProjectionService.publish_first sets published, and the reader ignores it. The divergence entered via the 73edb9eb "integrate entry surface and import wizard baselines" merge — an integration artifact, not a deliberate decision. Net effect: draft/unpublished content is reachable by anonymous callers once any tenant's search profile is ratified for production.

Separately, the platform owner set the durable requirement: post-publish versioning for citation integrity. Once something (model, term, any archetype) is published and possibly cited, a later change must not break the reference — a citation to version N must still resolve to version N's state. Pre-publish versioning is convenience; post-publish is academic-standards-compliance critical. The platform is greenfield (no production tenants; all tenants onboard by importing), so there is no data to migrate — only doors to keep shut.

Decision​

Adopt one publication model across the platform:

  1. publication_state=published is the operative public-visibility gate for every public read — EntryProjection-based (_base_queryset, EntryRouteResolver, _materialized_index_rows) and entity/attestation-based (the public 3D-viewer queries entities, term_detail, media_artifact_review_summary). projection_status stays the build-readiness axis. This restores the accepted Task-1 contract.
  2. Publish is a deliberate action, distinct from build. rebuild_role (and import-time reindex) BUILD projections; a publish action sets publication_state=published. Nothing is public until published. Greenfield ⇒ no backfill.
  3. Entity-level publication for non-projection public reads: an entity is public iff it has a publication_state=published EntryProjection; the 3D-viewer resolvers gate on that.
  4. Post-publish versioning + citation integrity is archetype-general: generalize ADR-022's ArtifactVersion REVISION/EDITION pattern (with EDITION-immutability) beyond MEDIA to all archetypes, composed with ADR-023 persistent identifiers and the Spec-0009 named-snapshot mechanism. A cited published version is preserved; post-publish changes create a new version without orphaning prior citations. Pre-publish (draft) edits are mutable and non-citation-bearing.

Alternatives considered​

  • Keep projection_status=CURRENT as the public gate (treat the divergence as the real design). Rejected: it contradicts the accepted Task-1 contract and ADR-029, and leaks draft authoring rows — CURRENT means "a projection was built," not "this is published."
  • Make rebuild_role set published (build == publish). Rejected: conflates building a derived artifact with the deliberate, citation-bearing act of publishing; defeats post-publish versioning and the "hidden until final" workflow.
  • Media-only versioning (leave ADR-022 scoped to MEDIA). Rejected: the citation-integrity requirement applies to terms and every archetype, not just 3D models.
  • A bespoke default-deny GraphQL extension / allowlist for the reader. Rejected earlier in this arc: the publication boundary is a data-filter concern, not an endpoint-auth concern; SECURITY_PRINCIPLES.md warns against a parallel security architecture.

Consequences​

Positive​

  • Closes the draft/unpublished anonymous leak by construction (greenfield, no backfill); aligns implementation with the accepted contract.
  • Citation integrity for published versions, archetype-general.
  • One publication discipline for all public reads; defensible by the structural security-gate test.

Negative​

  • The reader-gate change breaks existing entry-surface tests that build via rebuild_role and expect public visibility without publishing — they must add a publish step (mechanical migration).
  • Entity-level publication for the 3D-viewer reads needs an entity↔published- projection relation (or denormalized flag) — more than a one-line filter.
  • The archetype-general versioning layer is substantial; it should land phased, not big-bang.

Neutral​

  • publish_first already sets publication_state=published; the publish action exists and is the integration point.

Implementation notes​

Phased; F3 reader gate is Phase 1 and unblocked by this ADR:

  1. Phase 1 (F3, security): filter publication_state=published in _base_queryset, EntryRouteResolver._resolve_projection (all branches), and _materialized_index_rows. Migrate entry-surface tests to publish before asserting public visibility (add a shared build_and_publish_role helper). Test that proves it: a DRAFT projection is never returned by any public read; a published one is.
  2. Phase 2: entity-level publication gate for entities / term_detail (the public 3D viewer) — entity public iff it has a published projection, and the resolver serves the frozen public_payload, not the live entity. media_artifact_review_summary is a separate R2 security item because it has no entity/projection relation; it is gated as a reviewer/workspace summary via tenant role. (Amendment #5: at Phase 2 the per-site filter is centralized via published_public_projection_qs() — already shipped in spec 0033 / PR #431 — so the new public surfaces reuse the single helper.)
  3. Phase 3 (Fix 2) — RATIFIED form (amendment #4): add a published signal to each document on the one shared per-tenant index (get_tenant_indexer) and filter it in the public search profile's queries + aggregations so counts/facets reflect only published entries. This is NOT a second / published-only index, and NOT "published-only materialization" — the workspace profile legitimately needs the full corpus (drafts included). It is the single-index, profile-scoped published signal downstream of Phase 1's definition. Gate: a tenant TenantSearchProfile may not be ratified for production until this lands (see decision-log 2026-05-28 Task-8 blocker #3).
  4. Phase 4 (versioning) — DISAGGREGATED (amendment #2):
    • Phase 4a — universal citation-stable snapshots: cheap, all archetypes, via the Spec-0009 named-snapshot / EntrySnapshot mechanism. Optional, editorial-policy-gated (amendment #1) — Phase 1 already serves a standards-conformant live row + accessed-date; 4a wires the cite link to a frozen named-release for tenants whose policy needs version-stable cites.
    • Phase 4b — archetype-specific rich versioning: per-archetype semantics. Do NOT generalize ADR-022's MEDIA REVISION/EDITION wholesale (a term typo-fix ≠ a 3D-model vertex move; substantive-vs-trivial granularity is editorial policy). Composes with ADR-023 PIDs and ADR-031 source-versioning as separate deliverables, not one bundle.
    • Compliance floor (amendment #3, platform-canonical — applies to both): every citable artifact, regardless of tenant policy, meets (a) a persistent identifier + persistence commitment; (b) tombstone, never hard-delete (ROR inactive/withdrawn+successor; PROV Invalidation; BIBFRAME Status); (c) provenance/change tracking. Above-floor granularity is tenant/archetype editorial policy via a citable_versions capability on TenantArchetypeFormConfig.

R1 NotebookLM Absorption — Ratified Amendments (2026-05-28)​

A NotebookLM Round-1 critique (current-work + cross-arc; absorption devlog docs/devlogs/2026_w22/2026-05-28_1800_f3-r1-nlm-absorption.md) stress-tested this ADR, followed by standards research (Atlomy-Standards-Identifiers / -LOD notebooks). It surfaced no current Phase-1 regression (the async-rebuild→404 concern was verified benign — no code writes PENDING to a published projection today). The standards research reframed the critique's headline "live-row citation gap": a stable link to a live, in-place-updated record plus an "Accessed [date]" note is standards-conformant (DOI/ISO-26324: a stable identifier resolves to an updatable record; CSL provides accessed precisely to cite dynamic resources). Fixed-version citation is a stronger, optional, editorial-policy guarantee — backed by PROV's general-entity + immutable-specialization model, which maps onto the existing EntrySnapshot named-release machinery. The v1 cite feature (spa/.../Citation/index.jsx, APA/MLA/Chicago via citation-js → live page URL + accessed-date) is therefore conformant; ClaimCluster does NOT pin cited state.

The following are RATIFIED (2026-05-28) and are authoritative over the original Decision/Context where they refine it (see the Ratification note at the top). They do not change merged Phase-1 code. Items A1 + A5 are already IMPLEMENTED (spec 0033, PR #431, merged 7c51f7e7); items #1–#4 govern the now-schedulable deferred phases (sequenced on roadmap/board.md).

  1. Optional citable-version feature (NOT a release blocker). Phase 1 serves the live published row; per standards that is acceptable (stable link + accessed-date). For tenants/ archetypes whose editorial policy needs version-stable citations, add a mint a citable release action that freezes an immutable EntrySnapshot named-release and resolves the cite link to it. The machinery exists; the gap is wiring the cite link to the snapshot. Optional, editorial-policy-gated — earlier framed as a blocker; downgraded on standards grounds.
  2. Disaggregate Phase 4. Split into (i) universal citation-stable snapshots (cheap, all archetypes, named-snapshot mechanism) and (ii) archetype-specific rich versioning (per-archetype semantics). Do NOT generalize ADR-022's MEDIA REVISION/EDITION wholesale — a term typo-fix is not a 3D-model vertex move, and standards leave the substantive-vs-trivial granularity to editorial policy (DOI/Crossref/DataCite are silent on the threshold). Avoid bundling versioning + PIDs (ADR-023) + source concurrency (ADR-031) into one deliverable.
  3. Separate canonical visibility from tenant/archetype citation policy, above a standards floor. publication_state (visibility) is platform-canonical. Citation-versioning granularity is tenant/archetype editorial policy — but it sits above a platform-canonical compliance floor (not "purely the tenant's call"): (a) a persistent identifier + a persistence commitment; (b) tombstone, never hard-delete (ROR inactive/withdrawn + successor; PROV Invalidation; BIBFRAME Status); (c) provenance/change tracking (CIDOC events / PROV revision). GDPR erasure reconciles by erasing content, keeping the citable shell + status/ redirect. Drive the above-floor policy via a config capability (e.g. citable_versions on TenantArchetypeFormConfig), optionally rolled out via the ADR-038 federated preset registry.
  4. Phase 3 = a published signal on the ONE shared index (not a second index). There is a single per-tenant search engine (get_tenant_indexer), built public-reader-first and reused by workspace Query.search; it indexes the full corpus. Close the facet/aggregate-count volume leak by adding a published signal to each indexed document and filtering it in the public search profile's queries + aggregations (the workspace profile does not). This makes counts leak-proof on the index already paid for — a separate published-only index is wasteful and was rejected. Block production search-profile ratification until this lands. (Filter-context on an indexed boolean restricts via posting lists; it does not re-scan the corpus per query.)
  5. Harden the gate tests + centralize the read queryset — IMPLEMENTED (PR #431). published_public_projection_qs() is now the single source of the public-read two-axis gate (8 inline sites → 1), and an AST-based behavioral guard fails CI if an IN_BODY_GATED_FIELDS resolver loses its require_* call. The PublicReadResolver-base option was not needed.

Import-onboarding note (A6): the DRAFT default keeps imported rows hidden (not leaked), but the bulk/import-wizard path must set publication_state explicitly and offer an admin "bulk publication review" affordance; a dirty-audit substrate already exists (epistemic/services/publication_audit.py). Tracked with the import-wizard arc (Spec 0017/0023).

Standards basis: DOI/ISO-26324, CSL accessed, PROV (specialization / revision / invalidation), ROR (tombstone + successor), BIBFRAME Status, PeriodO editorial notes; CIDOC-CRM / Linked Art are silent on immutable record versions (change is modeled as events on the object). IIIF was absent from the standards corpus (gap to fill before relying on it for media-annotation versioning).

R2 NotebookLM Absorption — clarifications (2026-05-29, post-acceptance)​

A Round-2 critique (prescriptive + open + debate; absorption devlog docs/devlogs/2026_w22/2026-05-29_0145_adr047-r2-nlm-absorption.md) found no current regression. It produced the following clarifications. These refine wording/scope; they do not change the ratified Decision or the five amendments above.

  • New Phase-2 security item — media_artifact_review_summary is NOT "safe-because-out-of-scope". Spec 0035 lists this resolver as out of scope (no entity/projection relation). Verified (schema.py:4222, media_review.py:52): it is anonymous + has no publication filter and returns internal review/mapping state (counts + per-attestation edge_id/anchor_durable_id). "Out of scope" ≠ "closed." Treat as a tracked Phase-2 security item: verify the SPA consumer, then gate — its "bulk-view review summary" purpose suggests require_tenant_role (a reviewer tool), which closes the leak without needing the deferred media-linking model. (Severity moderate; greenfield ⇒ no live exposure.)
  • Amendment #4 reconciliation with ADR-029 (no CQRS regression). A published signal on the one shared index honors ADR-029: ADR-029 mandates projection-first hydration ("Public reads consume rebuilt projections… Search engines return IDs/evidence; detail/card rendering hydrates from projection/canonical data, not from search-engine document JSON", ADR-029 §Decision) — not a physically separate public-only index (ADR-011 = one shared per-tenant engine). Hydration stays routed through published_public_projection_qs(); the index is the ID/evidence layer ADR-029 describes. Phase-3 implementation must also cover autocomplete + pagination edges and avoid a timing oracle; a decoupled public-count aggregation/edge-cache is an option to evaluate.
  • Amendment #3 scope clarification (the compliance floor binds published/citable artifacts only). The floor (persistent id + tombstone-not-delete + provenance) applies to artifacts that have been published / are citable. Pre-publication workspace drafts remain freely mutable and hard-deletable — accidental-publish-then-delete and high-churn workspace iteration (e.g. daily field photos, hourly model drafts) are NOT subject to tombstoning. (is_citable is effectively publication_state; no new toggle needed.)
  • Amendment #2 precondition for Phase 4b. The versioning tier model (universal snapshots vs archetype-specific rich versioning) must be validated against ≥1 non-anatomy exemplar (e.g. a text corpus's semantic versioning) before ratification — do not ratify the tiers on the anatomy case alone.
  • Amendment #1 UX note. Version-stable citation stays optional (live link + accessed-date is conformant); surface the "mint a citable release" option at publish time so a tenant makes an informed choice. Not a default-on mandate (that would contradict the standards basis).
