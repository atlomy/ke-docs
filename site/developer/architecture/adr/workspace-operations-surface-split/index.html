ADR-036: Workspace and Operations Surface Split

Status: Accepted (2026-05-19 user ratification) Date: 2026-05-19 Deciders: User; architecture team (Codex consultation) Related: ADR-001 (Epistemic vs Operational Separation), ADR-005 (React Integration Pattern), ADR-015 (Tenant Admin Shell — substrate ownership), ADR-028 (Plate Editor for v2), ADR-029 (Projection-First Published Entry Layer), ADR-035 (Tenant Contributor Permission Model) Supersedes: nothing Scope-narrows: ADR-015 (now governs operations admin substrate only) Companion specs: docs/design/2026-05-19_design-coverage-review-and-extension.md §11 (friction analysis + Option B reasoning), docs/design/claude-design-prompt-pack.md (operational prompt pack bound to this split)

TL;DR​

Split the KE frontend into two surfaces with different chrome models:

  • Workspace at /app/workspace/<archetype>/ — daily researcher experience. Native React chrome (sidebar, topbar, command palette). DB Views (Table / Board / Gallery / Calendar / Map / Timeline / Registry), Row Detail Drawer with split editor + live <PublicPreview>, search, edits.
  • Operations at /admin/... — admin chrome. Django + Unfold pages hosting React islands. Imports, permissions, audit, telemetry, platform ops, super-admin shell.

Both surfaces share auth, design tokens (/docs/design/system/), GraphQL, tenant switcher, <RowDetailDrawer>, and <PublicPreview>. /app/admin/ retracted per ADR-015 (2026-05-08 amendment) is not revived; this ADR introduces a new path (/app/workspace/) with a different conceptual scope.

Context​

ADR-015 (2026-05-04, amended 2026-05-08) governs the tenant admin substrate. Its trajectory:

  • 2026-05-04 original: standalone Native React shell at /app/admin/ to retire the external no-code path.
  • 2026-05-08 amendment: reverse embedding direction. React islands mount inside Django + Unfold pages. /app/admin/ deprecated; sidebar links route to /admin/....

Two arcs of evidence accumulated between 2026-05-08 and 2026-05-19 that the amendment is correct for some surfaces but wrong for others:

Evidence the embed-in-Unfold model is right for operations:

  • Researchers reported the /app/admin/ shell felt "like a separate beta" (the original divergence pain that motivated retiring the external no-code surface). Operations chrome belongs in admin chrome.
  • Imports, permissions, audit, telemetry are operational tooling shaped like Django admin: list / detail / form / action. Django + Unfold renders these well; React islands cover the surfaces that need rich interaction (grids, slot editors).
  • Super-admin (Spec 0018 Sprint C) is operator IA — incident timelines, K-anon rollups, capture posture matrices. Admin chrome is right.

Evidence the embed-in-Unfold model is wrong for daily researcher workspace:

  • The 2026-05-19 design-coverage review identified Pass-2 workspace ergonomic targets that strain Unfold's chrome:
    • Coda.io-style multi-view per archetype (Table / Board / Gallery / Calendar / Map / Timeline)
    • Per-view filters, density, color tagging, row drag-reorder, saved views
    • User-organizable sidebar with custom groups, favorites, recent
    • Cmd-K command palette
    • Drawer-as-default-edit overlay (not Django change_form modal)
    • Plate-makeover polish (Notion/Coda/Linear-tier editor chrome)
  • Researchers spend most of their time in the workspace; tenant admins spend most of their time in operations. The two audiences and workflows are distinct.
  • The chrome cost of Unfold (breadcrumbs, app labels, admin nav) leaks into a surface meant to feel like a research workspace, not a database admin.
  • AG Grid Community can deliver workspace Table-view ergonomics with polish (sort, filter, edit, reorder, density, color, multi-row select all Community-tier; only row grouping is Enterprise). The substrate decision is settled; the chrome decision is what changes.

The 2026-05-19 design-coverage review §11 enumerated three options:

OptionDescription
A — Stay-and-polishKeep all surfaces embedded in Unfold; invest in Unfold theming to lift chrome perception
B — Hybrid (this ADR)Workspace at /app/workspace/ native React; operations stays embedded in Unfold
C — Full-SPA againRevert ADR-015 amendment; build a parallel React shell for everything

Option C re-creates the divergence pain. Option A invests in fighting Unfold's chrome constraints on a research surface. Option B preserves the 2026-05-08 amendment's benefit for operations and reclaims native React freedom for workspace.

Decision​

Split KE's frontend into two surfaces:

Workspace surface — /app/workspace/<archetype>/​

  • Audience: daily researcher contributor.
  • Chrome: native React. Sidebar (user-organizable groups per UserSidebarPreferences — design landed via claude-design-prompt-pack.md §6.2), topbar (tenant switcher, global search, user menu), command palette (Cmd-K).
  • Surfaces: DB Views per archetype (Table + per-archetype non-table views: Board, Gallery, Calendar, Map, Timeline, Registry). Row Detail Drawer with split editor (left) + live <PublicPreview> (right). Search, facets, saved views.
  • Mount: React app at spa/src/apps/workspace/ (new), served via Django template at /app/workspace/<archetype>/. Tenant context from URL + session. Same auth as operations.
  • Component substrate (installed, in production today): AG Grid Community v35 for Table; Plate.js for rich text; react-hook-form 7 + zod 3 for forms; /docs/design/system/ tokens for chrome.
  • Planned substrate (installation gated by the consuming surface entering active scope, after dependency / security / KE-scale-fit review): dnd-kit for Board lanes + sidebar drag-reorder + row drag-reorder; @tanstack/react-virtual for Gallery virtualization (note: 2026-05 TanStack npm incident affected Router/Start, not Table/Virtual, but raises the bar for adding new TanStack packages); FullCalendar or a custom component for Calendar; Leaflet or MapLibre for Map (Pleiades pin data wiring is the natural first PLACE consumer); custom horizontal-scroll component for Timeline. These are the directional library picks; installation lands when the surface ships, not earlier.
  • Permissions: per ADR-035 capability-flag model; UI degrades per can_edit / can_view / scope.

Operations surface — /admin/...​

  • Audience: tenant admin, platform super-admin, operator.
  • Chrome: Django + Unfold. Sidebar driven by TenantArchetypeTable + admin app entries.
  • Surfaces: imports (Django admin pages + Spec 0017 wizard bridge), permissions (Spec 0018 US-C.1 panel + ADR-035 substrate), audit (Spec 0018 US-C.3), telemetry (Spec 0018 US-C.4), platform super-admin shell (Spec 0018 Sprint C — /admin/monitoring/platform/).
  • Mount: Django views + Unfold templates host React islands via embed_*.tsx pattern (per ADR-015 amend 2026-05-08, unchanged). New surfaces continue this pattern.
  • Permissions: per ADR-035 capability gating + require_platform_staff for super-admin tier.

Shared substrate​

Both surfaces share — and consume identically:

  • Auth: Django session + JWT dual-mode; tenant routing via subdomain + TenantMainMiddleware.
  • Design system: /docs/design/system/tokens.css, components.css, page.css, brand/. Repo-root home (see 2026-05-19 design folder refactor).
  • GraphQL: same schema, both surfaces hit it. Workspace consumes entities, term_detail, tenant_form_config, mapping_proposals. Operations hits the same + admin-scoped queries.
  • Tenant switcher: lives in workspace topbar (read-write); appears as read-only mirror in operations admin chrome.
  • <RowDetailDrawer>: shared component. Used in workspace as default-edit overlay; used in operations as opt-in detail expansion.
  • <PublicPreview>: shared production component (per claude-design-prompt-pack.md §4.B). Used as workspace drawer right pane; used as wizard Stage 3 preview replacement; used as public reader.

/app/admin/ deprecation policy​

  • Status: deprecated per ADR-015 (2026-05-08 amendment); not revived by this ADR.
  • The new /app/workspace/<archetype>/ paths are not a revival of /app/admin/. Conceptually:
    • /app/admin/ was a parallel React shell for everything tenant-admin-related. Researchers experienced it as "a separate beta."
    • /app/workspace/ is the researcher's daily home. It is not a shell-of-the-admin; it is the workspace. Admin tasks (imports, permissions) live at /admin/... with appropriate operator chrome.
  • Removal trigger for /app/admin/: one full sprint after /app/workspace/ ships v0 (Table view + Row Detail Drawer for at least TERM archetype) without regressions.

Cross-link contract​

The two surfaces must compose, not duplicate:

FromToPattern
Workspace rowOperations admin detail"Open in admin" backlink in Row Detail Drawer overflow menu (deep link to /admin/epistemic/epistemicentity/<id>/change/)
Operations admin rowWorkspace row"View in workspace" link (deep link to /app/workspace/<archetype>/<id>)
Operations import receiptWorkspace newly-materialized rowsStage 6 receipt links to workspace filtered by created_by_project=<id>
Workspace post-apply edit markerOperations audit-trail viewerDrawer audit chip links to /admin/audit/?entity=<id>
Cmd-K command palette (workspace)Operations surfacesReturns admin actions ("Start import," "Review imports," "Manage permissions") that navigate to /admin/...
Operations sidebarWorkspaceTop-level "Workspace" entry routes to /app/workspace/ index
Tenant switcherBothSingle switcher in workspace topbar mutates a shared cookie; admin chrome reads the cookie read-only

Auth pivots smoothly: same session works across both URL prefixes. Tenant boundary is enforced at the resolver layer, not the URL layer.

Implementation​

Phase 1 — Foundational (sequential)​

  1. This ADR ratified (2026-05-19, complete with this commit).
  2. Production <PublicPreview> component built at spa/src/apps/public_preview/ per claude-design-prompt-pack.md §4.B. Required before workspace v0 ships. ~2 weeks engineering.
  3. Scope-narrowing note added to ADR-015 at top: this ADR governs operations admin substrate only; workspace is ADR-036.

Phase 2 — Workspace v0 (parallel after Phase 1)​

  1. New React app at spa/src/apps/workspace/. Reuse Shell.tsx pattern from existing apps. Mount via Django template at /app/workspace/<archetype>/.
  2. AG Grid Table view polish pass per claude-design-prompt-pack.md §5.3. ~3–4 weeks.
  3. Sidebar re-organizability per §6.2 — new UserSidebarPreferences model + GraphQL CRUD + dnd-kit. ~2–3 weeks parallel.
  4. Row Detail Drawer production reproduction with <PublicPreview> right pane and react-hook-form outer form. Region contract via data-region selectors (per ADR-015 historical pattern in tenant-admin/term-form.jsx).

Phase 3 — Multi-view (parallel after Phase 2)​

  1. Per-archetype non-table views per claude-design-prompt-pack.md §6.3. Board (dnd-kit), Gallery (@tanstack/react-virtual), Calendar (FullCalendar or custom), Map (Leaflet), Timeline (custom). 1–2 weeks per view.

Phase 4 — Operations surfaces (parallel with Phase 2/3, separate work stream)​

  1. Super-admin shell at /admin/monitoring/platform/ per claude-design-prompt-pack.md §5.1. Spec 0018 Sprint C.
  2. Permissions panel per claude-design-prompt-pack.md §5.2. Spec 0018 US-C.1.

Phase 5 — Retraction​

  1. Retire /app/admin/: one full sprint after workspace v0 ships without regressions. Remove deprecation banner, remove routes, redirect to /app/workspace/.

Non-goals​

  • Not a full SPA migration. Operations surfaces stay in Django + Unfold permanently for the operator-shaped IA.
  • Not a re-introduction of /app/admin/. The new /app/workspace/ paths are conceptually different (researcher's daily home, not a parallel admin shell).
  • Not a TanStack Table migration. AG Grid Community v35 remains the Table-view engine. TanStack Table is a future narrow coexistence option only if row grouping becomes mandatory and Enterprise license is rejected.
  • Not a chrome-redesign of Django + Unfold. Operations chrome stays as-is; this ADR doesn't prescribe a new admin theme.
  • Not a public reader redesign. Public reader (per ADR-029) continues as its own track. Workspace <PublicPreview> is the same component, but the public reader's surface evolution is governed by ADR-029.

Alternatives considered​

AlternativeWhy rejected
Option A — Stay-and-polish in UnfoldThe Coda-ergonomic targets (multi-view, custom sidebar, drawer-as-default, command palette, Plate polish) fight Unfold's chrome at every step. Investment in Unfold theming partially solves visual cost but not IA cost (breadcrumbs, app labels, admin-shaped nav). Net: more work, worse outcome.
Option C — Full-SPA again (revert ADR-015 amend)Re-creates the original "separate beta" divergence pain. Operations surfaces (imports, audit, super-admin) genuinely fit admin chrome; making them React-only loses Django Unfold's value for operator workflows.
Keep /app/admin/ and rename to /app/workspace/Mechanical rename without addressing IA scope. Researchers would still see "tenant admin" framing in a surface that's actually their daily research workspace.
Embed researcher workspace as a single page within Unfold's Knowledge Graph nav sectionDoesn't solve the chrome cost; still inside admin breadcrumb/topbar/app-label scaffolding. Worse: forces every workspace surface through Django view boilerplate.

Consequences​

Positive​

  • Researcher chrome matches researcher work. Workspace can adopt Coda-tier ergonomics (multi-view, group, density, drag-reorder, Cmd-K) without fighting admin chrome.
  • Operations chrome matches operator work. Imports, audit, telemetry, super-admin keep coherent admin presentation; React islands handle rich interactions where needed.
  • Cross-link contract is auditable. Both surfaces hit the same GraphQL + same auth; deep links work in both directions; no fork in data model.
  • /app/admin/ deprecation completes cleanly. This ADR doesn't revive it; the new /app/workspace/ is a different concept, not a rebrand.
  • Substrate decisions hold. AG Grid Community, react-hook-form, Plate.js, dnd-kit, Leaflet, /docs/design/system/ all stay; no engine churn.
  • Future surfaces have a clear placement rule. Researcher daily work → workspace. Operator / admin / cross-tenant → operations.

Negative​

  • Two surfaces to maintain. Workspace and operations both consume the same substrate but render different chrome. Component reuse (<RowDetailDrawer>, <PublicPreview>, AG Grid wrapper, Plate editor) mitigates duplication, but the two surfaces' top-level shells diverge.
  • Cross-link contract requires discipline. Forgetting to deep-link from a workspace row to its admin detail (or vice versa) creates dead ends. Must be enforced in code review.
  • Tenant switcher coupling. One switcher in workspace topbar, mirror-only in admin. Implementation requires a shared cookie/store contract; not technically hard, but a coordination point.
  • Workspace v0 takes 6–10 weeks before researchers see meaningful difference from current shipped state. During that period, both surfaces coexist; researchers continue using the embedded-island operations pattern.

Mitigations​

  • Shared substrate is non-negotiable. Auth, tokens, GraphQL, <RowDetailDrawer>, <PublicPreview>, tenant switcher are explicitly shared (this ADR §"Shared substrate"). Forking is treated as a violation.
  • Cross-link contract is documented in this ADR and enforced in code review. Deep-link helpers should be shared utilities, not per-surface inline.
  • Sequencing limits exposure. Phase 1 (foundational) lands before Phase 2 (workspace v0). Production <PublicPreview> is a hard prerequisite. Workspace v0 starts with one archetype (TERM); horizontal expansion validates the pattern incrementally.
  • /app/admin/ deprecation banner stays until workspace v0 ships. No revival; no parallel maintenance of three shells.

Compliance​

This decision must:

  1. Align with ADR-001 (Epistemic vs Operational Separation): workspace is the researcher-facing epistemic surface; operations is the operational tier. The split is the architectural expression of ADR-001's separation principle applied to UI.
  2. Align with ADR-005 (React Integration Pattern): both surfaces are React (workspace as native React app; operations as embedded React islands). Standalone-SPA prescription applies to workspace; ADR-015's 2026-05-08 amendment governs operations admin embedding.
  3. Align with ADR-015 (now scope-narrowed): operations admin substrate decisions (capability-flag→component mapping, free-tier libraries, AG Grid Community, react-hook-form) remain valid for both surfaces. ADR-015 governs the substrate; ADR-036 governs the mount split.
  4. Align with ADR-028 (Plate Editor): Plate.js is the canonical RTE in both surfaces. Workspace embeds it via <PlateFullEditor> inside Row Detail Drawer; operations uses it inside change-form overlays per ADR-015 amend.
  5. Align with ADR-029 (Public Reader): the shared <PublicPreview> component is the same one the public reader uses. Workspace's drawer right pane and the public reader are not parallel implementations.
  6. Align with ADR-035 (Permission Model): capability gating applies in both surfaces. Workspace honors can_edit / can_view / scope; operations adds can_manage_permissions, require_platform_staff for super-admin.
  7. Honor lint-no-tenant-vocabulary: platform code stays general; tenant-specific vocabulary lives in TenantArchetypeFormConfig + voice_overrides.
