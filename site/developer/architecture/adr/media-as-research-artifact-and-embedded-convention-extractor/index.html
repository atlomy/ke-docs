ADR-021: Media as research artifact + embedded-convention extractor pattern

Date: 2026-05-08 Status: Superseded by ADR-022 (2026-05-08, same day — Round-16 absorption surfaced four amendments + two user-driven reframings that warranted a fresh ADR rather than in-place edit). Original status was Proposed (stub). Superseded by: ADR-022 — Media architecture v2: Anchor + ArtifactVersion + ClaimCluster + media as attestation_walk source-type. Deciders: Atlomy Account, assistant Related: ADR-001 (Epistemic / Operational separation), ADR-002 (Hybrid Ontology), ADR-006 (Archetype Capability Contracts), ADR-017 (Slot Config Manifest), ADR-019 (V1 SPA reads from EpistemicEntity), ADR-020 (Attestation Walk + Platform-Canonical Projection Principle). Supersedes: nothing — opens scope deferred from ADR-019 §H5 (Reference / Model retirement) and ADR-020 §item 5 (3D viewer rewire). Folds the 3D-specific work into the broader media-as-research-artifact principle.

Why ADR-022 supersedes this​

Round-16 NotebookLM absorption (2026-05-08, eeb04c8f-b718-435f-b484-b1c43cc2ec36 open critique audio) + user-driven reframings produced four substantive amendments to the architecture in this stub:

  • C1 (twice-amended): original §B was about to embed platform-internal UUIDs into media artifacts. Audio caught two failure modes (Blender silently strips extras; cross-tenant collision on shared assets). User then sharpened: a media artifact is a CATALOGUED, CITABLE, SHAREABLE research output; embedding platform-internal data is a sensitive-data leak. Final fix in ADR-022 §A.4: strict three-layer identity model with NO platform writes to artifacts.
  • C2: walks fundamentally cannot synthesize novel cross-artifact-type researcher propositions. Fix in ADR-022 A.1: ClaimCluster thin junction primitive in v1.
  • C3: selector vocabulary is intrinsic to the Anchor table; splitting it across ADRs creates blocking ratification dependency. Fix in ADR-022 §A.3: full W3C selector schema lives in ADR-022; ADR-024 rescoped to UI/integration only.
  • C4 (twice-amended): audio framed Phase 0 retirement as production-grade atomic switchover; user reframed as greenfield-dev, no production transition. Fix in ADR-022 phasing: Phase 0 retirement is normal codebase evolution; design discipline + regression test only.

ADR-022 also reframes the architecture as an EXTENSION OF ADR-020's attestation_walk (with media as a source-type alongside textual sources) rather than a parallel system, introduces ArtifactVersion as a new primitive (Hybrid Revision/Edition), and opens four sibling ADRs (023-026) that were folded into the original ADR-021 scope.

The full reasoning chain lives in docs/superpowers/specs/2026-05-08-media-architecture-design.md. The Round-16 absorption devlog is at docs/devlogs/2026_w19/2026-05-08_1257_round16-absorption.md.

The Phase 0 reference implementation (atlas GLB extractor, commit d539764b) stays in production unchanged through the ADR-022 sprint until Phase 3 lifts its parser logic into the platform delimited_split parser. Existing 18 atlas edges remain valid; no migration needed.

The original ADR-021 text below is preserved verbatim for historical context. Do not act on ADR-021's recommendations directly; refer to ADR-022 for the current architecture.

Context​

What ADR-019 + ADR-020 left open​

ADR-019 retired the V1 Lemma table and Sprint 0004 ran end-to-end. The follow-up rewire (commit abb8b408) replaced the V1 ModelLemma join with EntityRelationship(rule_name='three_d_model') walks from TERM to MEDIA archetype rows. That much is shipped.

What ADR-019/020 explicitly deferred:

  • Researcher-facing UX for creating / editing the TERM↔MEDIA edges.
  • Replacement for the legacy ModelMapping admin tab that hand-mapped lemmas to 3D models.
  • MEDIA archetype slot config for atlas (currently zero TenantArchetypeFormConfig rows; the Django admin overlay silently skips rendering).

What surfaced when the 3D viewer rewire was being investigated​

Two findings the user named explicitly during 2026-05-08 follow-up:

1. Media is not an attachment — it is a research output and process.

"Knowledge environments often mean media-rich research, where it isn't an attachment but a research output and process. In this case — each 3D model is a scientific recreation of how the ancients saw and understood the human body at the time. It 'brings to life' texts that are hard to understand, since they are trying to describe what they see, feel, smell."

— User, 2026-05-08

A 3D model of Aristotelian respiratory anatomy is not a JPEG attached to a record. It is:

  • A scholarly argument: this is what Aristotle saw / felt / inferred from dissection + Hippocratic case notes + lived observation.
  • Authored: a researcher modeled it, citing primary texts.
  • Versioned: revisions track changing interpretations (e.g., later finding that πλεύμων referred to a different organ-set than initially assumed).
  • Internally structured: 28 named meshes, grouped into anatomical systems (Cardiovascular, Digestive, Respiratory, Skeletal, Other).
  • Outbound-bound: each mesh corresponds to a Greek lemma + transliteration + English gloss.

The same is true for other media types in other tenants: an annotated IIIF manuscript image is a paleographic argument; a video of an excavation is an archaeological record; a spectrogram is a phonetic analysis. All carry internal structure that binds outward into the research substrate.

2. The Atlomy lab's GLB convention is a tenant-specific instantiation of a generalizable platform principle.

"The object naming convention was developed in the Atlomy lab in order to automatically relate body parts to lemmas instead of manually mapping, but it's a convention that other tenants may build differently, if at all. Plus other media types will have more or other conventions and needs."

— User, 2026-05-08

Inspecting the Aristotle Respiratory System GLB shows the convention concretely. The 28 mesh nodes follow:

<Greek lemma>;/<transliteration>/;<English gloss>;text

Examples:

καρδία;/kardia/;heart;text
πλεύμων;/pleumōn/;lungs;text
λάρυγξ;/larynx/;larynx;text
φλέψ;/phlebes/;vessels;text

Plus anatomical-system parent nodes: Cardiovascular, Digestive, Respiratory, Skeletal, Other.

The convention exists inside the GLB file because that's where the modeler edits it (Blender). The file is the source of truth; the legacy ModelMapping Django table was a redundant Django-side mirror of what the GLB already encodes.

The principle generalizes:

Why this is platform-load-bearing​

If the platform commits to media as a first-class research artifact + a generic embedded-convention extractor framework, every tenant gets:

  • One canonical MEDIA archetype with versioning, provenance, internal-structure metadata, derivative renders.
  • One platform-shipped extractor framework that runs tenant-declared parsers against media internal structure.
  • One materialization pathway: extractor output → EntityRelationship edges with provenance metadata.
  • One researcher-UX layer: review / approve / amend / strip extracted edges, with manual edges as overrides (not primary editor).
  • One way to handle the "modeler edits Blender → re-run extraction → edges refresh" workflow that the legacy ModelMapping tab tried to handle by manual data entry.

If the platform doesn't commit, every tenant onboarding repeats: build a tenant-specific admin tab to hand-map media → research substrate, then watch it desync from the source media file the moment the modeler / image-annotator / TEI-encoder makes their next edit.

Decision (proposed) — two-part​

Part A — Platform principle: media as first-class research artifact​

Media is a research output and process, not an attachment. The platform-canonical MEDIA archetype carries:

  • Identity + provenance: who created the artifact, when, against what source-texts / data, in what tool.
  • Versioning: explicit version chain (revision history) — replaces the legacy "I'll just overwrite the file" pattern.
  • Internal structure metadata: declared mime-type, declared internal-structure schema (e.g., "GLB with named meshes"), extracted-bindings count.
  • Derivative renders: thumbnails, search images at multiple sizes, transcoded variants — all canonically nested, not free-floating.
  • Outbound bindings: EntityRelationship edges to other archetypes, materialized from internal-structure extraction OR researcher manual edits, with provenance distinguishing the two.

Atlas's "3D model" is one instance of MEDIA; biology specimen images, IIIF manuscripts, audio recordings, paleographic facsimiles are siblings. The slot config for MEDIA is platform-canonical (declares the universal fields above); the interpretation of internal structure is tenant-specific.

This honors the platform-canonical-projection principle from ADR-020 §A: platform code carries no convention vocabulary; tenant config declares the convention.

Part B — Embedded-convention extractor pattern​

Adopt a platform-shipped extractor framework that runs tenant-declared parsers against media internal structure. Sketch:

// Tenant config (atlas example)
{
  "media_extractors": [
    {
      "extractor_id": "atlas-glb-anatomy-v1",
      "applies_to_mime_types": ["model/gltf-binary"],
      "internal_structure_walker": "gltf_node_names",
      "convention_parser": {
        "kind": "delimited_split",
        "delimiters": [";", "_"],   // primary + fallback
        "fields": [
          { "index": 0, "role": "lemma_greek" },
          { "index": 1, "role": "transliteration", "strip": "/" },
          { "index": 2, "role": "english_gloss" }
        ],
        "tag_field": { "index": 3, "expected": "text" }
      },
      "binding_target": {
        "archetype": "TERM",
        "lookup_field": "Lemma Word",        // atlas-domain vocabulary, in tenant config
        "fallback_lookup_fields": ["Alternative Spelling"],   // handles πλεύμων↔πνεύμων
        "edge_rule_name": "three_d_model"
      },
      "binding_metadata": {
        "internal_id_field": "node_name",
        "system_grouping": "parent_node_name"   // captures "Respiratory" / "Cardiovascular"
      }
    }
  ]
}

A tenant in paleography declares an iiif-region-walker extractor with a different parser; a JPP TEI tenant declares a tei-corresp-attribute extractor. Same framework, different conventions, no platform code changes.

The extractor framework runs in two phases:

  1. Internal-structure walker (platform primitive): gltf_node_names, iiif_canvas_annotations, tei_xml_corresp, darwin_core_metadata. Each ships a single function: media file → list of structured items.
  2. Convention parser (platform primitive): delimited_split, regex_capture, xml_attribute_lookup, key_path_extract. Tenants declare which parser + how, in their config.

The parsed bindings get materialized to EntityRelationship edges via a single platform mgmt command (idempotent, with REPORT/APPLY modes following the backfill_entity_identity_ledger pattern from ADR-017 Phase 2.B).

Researcher UX layer — overrides, not primary editor​

The legacy ModelMapping admin tab put researchers in the role of primary editor: hand-add row, hand-link Lemma to Model. That model fights the workflow because the modeler edits the GLB in Blender and the manual mappings drift.

The replacement reframes researchers as reviewers / overriders:

  • Bulk view: "MEDIA Aristotle Respiratory System has 25 extracted bindings; 22 mapped to existing TERMs; 3 unmapped (lemma not in DB or spelling variant)."
  • Per-edge review: approve / strip / amend the extractor's proposed edge; the researcher's action is recorded as metadata.researcher_override = true with timestamp + actor.
  • Manual add: researcher can add an edge that the extractor missed, recorded as metadata.source = 'researcher_manual'.
  • Re-run extraction: when the modeler updates the GLB, re-run the ingestion command; researcher overrides persist (the materialization rule preserves any edge with researcher_override=true); auto-extracted edges are refreshed.

This is the same pattern AI-in-the-loop work uses (status: AI_PROPOSED → HUMAN_REVIEW → APPROVED). Extractor-proposed edges go through the same review surface as AI-proposed edges. ADR-021 unifies them.

Consequences​

Positive:

  • Media stops being a second-class data structure. Researchers gain a workflow that respects the artifact's research-output nature.
  • The legacy ModelMapping desync problem disappears. Source-of-truth lives in the media file (where the modeler edits); Django edges are derived; researcher edits live alongside as marked overrides.
  • Cross-tenant generalizability. JPP gets TEI extractor; Visionis gets IIIF extractor; future biology tenants get Darwin Core extractor; all share the same framework + UX.
  • AI-in-the-loop convergence. Extractor-proposed edges + AI-proposed edges flow through the same review surface; researcher review discipline accumulates across both kinds of proposal.
  • Atlas's GLB convention is reusable. Other 3D-modeling tenants (medical anatomy education, archaeological reconstruction) can adopt atlas's convention or declare their own; either way, no platform-code change.

Trade-offs:

  • One-time platform investment is significant. Extractor framework + walker primitives + convention parser primitives + materialization mgmt + researcher review UX is a multi-week sprint, not a side-quest.
  • MEDIA slot config schema is load-bearing. Getting it right requires field-by-field analysis across at least 3 tenant cases (atlas 3D, JPP TEI, Visionis IIIF) before locking — same risk profile as ADR-020 §B's cross-discipline mapping.
  • The 3D viewer rebuild stays deferred until the framework is in place. Researchers see the model card on lemma pages but click-through lands on the placeholder. That's a real UX regression vs V1.

Honest constraint (per ADR-020 §B's Round-15 calibration):

This decision is plausible from first principles but has sample size = 1 (atlas GLB) for the embedded-convention extractor part. Locking Part B as Approved without a second-tenant validation repeats the ADR-020 §B premature-codification risk Round-15 stress-tested. Keep Part B in Proposed status until at least one non-atlas extractor (likely IIIF for Visionis or TEI for JPP) lands.

Phasing (proposed — not yet committed)​

  1. Phase 0 — atlas GLB ingestion as reference implementation (this commit)

    • Tenant-scoped atlomyapp/management/commands/ingest_3d_model_glb.py parses GLB nodes with the atlas convention; creates EntityRelationship(rule_name='three_d_model') edges via EpistemicEntity lookup with Alternative Spelling fallback.
    • NOT the platform-canonical extractor framework — this is the seed implementation that proves the pattern is real and gives the eventual ADR-021 sprint a concrete reference to generalize from.
    • Scoped to atlomyapp/ per "platform code carries no tenant vocabulary" rule.

  2. Phase 1 — MEDIA archetype slot config + admin overlay (future)

    • Define platform-canonical MEDIA TenantArchetypeFormConfig schema (provenance, versioning, internal-structure metadata, derivative renders).
    • Wire the admin overlay so Django MEDIA pages render the slot form instead of skipping silently.
    • Re-cast atlas's existing 3 MEDIA records (Aristotle Respiratory System + future models) under the new schema.

  3. Phase 2 — Extractor framework: internal-structure walkers + convention parsers (future)

    • Platform-shipped walkers: gltf_node_names, iiif_canvas_annotations, tei_xml_corresp, etc.
    • Platform-shipped parsers: delimited_split, regex_capture, xml_attribute_lookup.
    • Tenant config schema for declaring which combinations to use.

  4. Phase 3 — Materialization mgmt + provenance discipline (future)

    • REPORT / APPLY mgmt cmd that runs the tenant's declared extractors, materializes edges, preserves researcher overrides on re-run.
    • Provenance metadata on every edge: source: extracted | researcher_manual | ai_proposed, extractor_run_id, researcher_override: bool.

  5. Phase 4 — Researcher review UX (future)

    • Bulk view: "MEDIA X has N extracted bindings, M unmapped".
    • Per-edge approve / strip / amend with provenance trail.
    • Re-run extraction with override preservation.

  6. Phase 5 — 3D viewer (and parallel viewers for image / audio / TEI / specimen) as consumers (future)

    • Un-stub spa/src/pages/three_d_model_placeholder and rebuild the viewer against the canonical MEDIA shape.
    • Parallel viewer components for IIIF region annotation, TEI prosopographic markup, etc.

  7. Phase 6 — Second-tenant validation + §B promotion (future)

    • Implement at least one non-atlas extractor end-to-end (likely Visionis IIIF or JPP TEI).
    • On success: promote Part B from Proposed to Approved.

Alternatives considered​

Alternative A — Build a researcher-facing admin tab to hand-edit TERM↔MEDIA edges​

Rejected — re-creates the legacy ModelMapping desync problem. The modeler edits the GLB in Blender; the admin-tab edges drift the moment the modeler renames a node. Source of truth lives in the file; admin tabs that mirror file-internal structure desync.

Alternative B — Build the 3D viewer NOW against the existing schema; defer media architecture to later​

Rejected — the existing schema is under-specified (MEDIA archetype has zero slot config; get_model / get_sub_models are stubs returning {} / []). Building the viewer first commits to a data shape before the architecture is designed. Round-15 stress-tested this exact pattern (synthetic-fixture-passes-but-real-data-shape-is-wrong); building viewer-first repeats it.

Alternative C — Keep ModelMapping table, just port to v2​

Rejected — ModelMapping was retired in ADR-019 Phase 4 because it conflated operational truth (Lemma table that gets dropped on re-import) with epistemic interpretation (the lemma↔mesh mapping that's a research claim). The conflation is what ADR-001 separates.

Alternative D — One canonical extractor per media type, no tenant declaration​

Rejected — atlas's <Greek>;/<translit>/;<English>;text convention is not what JPP / Visionis / future biology tenants will use. Forcing a canonical convention forces tenants either to refactor their existing media or to fight the platform. The convention layer must be tenant-declared.

Open questions​

  1. Internal-structure walker registry — do walkers ship as Python plugins discoverable by entry-points, or as declarative config that the platform interprets directly? The plugin model is more flexible; the declarative model is more constrained but easier to lint + validate.
  2. Researcher override conflict resolution — when a re-run of extraction proposes an edge that the researcher previously stripped, does the system silently re-strip, surface for re-review, or refuse to overwrite? (Opinion: surface for re-review with a "reaffirm strip" button; never silently overwrite human intent.)
  3. Versioning model — does MEDIA versioning use ADR-017's EntityIdentityLedger substrate, or a separate MediaVersionChain model? The ledger handles the source-system → platform-uuid stability, not the version-of-the-file evolution.
  4. Cross-tenant extractor reuse — if Visionis adopts atlas's delimited_split parser with a different separator, do they share the parser kind or duplicate? (Opinion: share; tenant-config picks the parameters.)
  5. MEDIA file storage substrate — is it inline binary (impractical for 70MB GLB), filesystem-mounted (current ad-hoc atlomy_3d_assets/), or S3-backed? Production needs S3-class durability; dev needs dirt-cheap. Likely a switch by environment.
  6. Source-operations product surface — commit ded020f5 added tenant admin /app/admin/source-sync/ for Coda TERM/PASSAGE/DOCUMENT refresh, with Preserve edits refresh vs Full refresh modes. Media source sync intersects with this surface but is not just another table refresh. Candidate framing: keep /app/admin/source-sync/ as the umbrella source-operations surface, then split into source-type sections such as tabular data sources and media artifacts. Shared concepts: preview, run, destructive confirmation, source counts, last sync, preserved researcher edits. Media-specific concepts: extracted bindings, derivative renders, embedded-convention parser status, unmapped nodes/regions/timecodes, and override conflicts. Research should decide whether media belongs under that umbrella or gets a dedicated workspace linked from it.

What this ADR is NOT​

  • Not a 3D-only decision. The 3D viewer rewire is one downstream consumer of the MEDIA archetype + extractor framework. Image, audio, video, TEI, IIIF, manuscript-facsimile, specimen-image, spectrogram all share the same machinery.
  • Not a researcher-discretion-only decision. Extractor-proposed and AI-proposed edges flow through the same review surface as researcher-manual edges. The researcher's role is reviewer / overrider, not primary editor.
  • Not a scope grab. Phase 0 (atlas GLB ingestion as reference implementation) ships now to capture the user's framing before scope drift; Phases 1-6 are explicitly DEFERRED to a media sprint. The 3D viewer stays "Unavailable" in the SPA placeholder until Phase 5.

Phase 0 reference implementation — shipped 2026-05-08​

Tenant-scoped (atlas only):

  • atlomyapp/services/glb_lemma_extractor.py — pure-Python parser for atlas's <Greek>;/<translit>/;<English>;text GLB node convention. Returns normalized BindingCandidate objects.
  • atlomyapp/management/commands/ingest_3d_model_glb.py — REPORT / APPLY cmd. REPORT shows which lemmas resolve, which fall back to Alternative Spelling, which are unmapped. APPLY creates EntityRelationship(rule_name='three_d_model') edges with provenance metadata {source: 'glb_extractor_phase0', glb_node_name, anatomical_system, transliteration, english_gloss}.
  • tests/integration/test_glb_lemma_ingest.py — extractor unit tests + end-to-end test against the Aristotle Respiratory System GLB (28 nodes; 22-25 expected lemma matches; 3-5 unmapped; system grouping detected).

Phase 0 explicitly does NOT generalize. It exists to:

  1. Replace the 3 hand-created edges from commit abb8b408 with the full ~25-edge extraction.
  2. Give Phases 1-6 a working concrete reference (the convention parser logic, the Alternative Spelling fallback, the EntityRelationship provenance shape).
  3. Surface the πλεύμων↔πνεύμων variant-spelling problem as concrete data, not hypothesis.

Phase 0 is acknowledged as tenant-specific code. When ADR-021 Phase 2 extractor framework lands, Phase 0's parser logic moves into a platform-shipped delimited_split parser kind, and atlas declares the per-field config in its tenant manifest. The lift from Phase 0 to Phase 2 is the convention parameterization, not a rewrite.
