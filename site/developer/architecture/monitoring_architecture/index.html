Sprint 7: Platform-Wide Monitoring & Observability

Goal​

Implement comprehensive monitoring, metrics, and alerting for all platform operations including sync pipelines, AI services, and tenant health in the public schema for cross-tenant visibility.

Architecture Principles​

1. Public Schema Monitoring​

  • All platform metrics stored in public schema
  • Cross-tenant aggregation and comparison
  • Admin-only access (superuser)

2. Multi-Tenant Aware​

  • Track metrics per tenant
  • Identify problematic tenants
  • Resource usage attribution

3. Real-Time + Historical​

  • Live dashboards for current state
  • Historical trends for capacity planning
  • Anomaly detection

Proposed Changes​

Phase 1: Platform Metrics Model (Public Schema)​

[NEW] monitoring/models.py​

class PlatformMetric(models.Model):
    """
    Store platform-wide metrics in public schema
    """
    metric_type = CharField  # 'sync', 'ai', 'performance', 'error'
    tenant = ForeignKey(Client, null=True)  # Null = platform-wide
    metric_name = CharField  # 'sync_success_rate', 'ai_calls_total'
    value = FloatField
    metadata = JSONField  # Additional context
    timestamp = DateTimeField(auto_now_add=True)
    
    class Meta:
        db_table = 'platform_metrics'
        indexes = [
            Index(fields=['metric_type', '-timestamp']),
            Index(fields=['tenant', 'metric_name', '-timestamp']),
        ]

Phase 2: Metrics Collection​

Sync Pipeline Metrics​

  • Success/failure rates per tenant
  • Average sync duration
  • DLQ size
  • Conflict rate

AI Pipeline Metrics​

  • LLM call count and latency
  • Token usage per tenant
  • Schema adaptation success rate
  • Error rates by provider

Platform Health​

  • Database connection pool usage
  • Redis queue depth
  • Celery worker count
  • Memory/CPU usage

Phase 4: Alerting System​

[NEW] monitoring/alerts.py​

class Alert(models.Model):
    alert_type = CharField  # 'critical', 'warning', 'info'
    message = TextField
    tenant = ForeignKey(Client, null=True)
    acknowledged = BooleanField(default=False)
    created_at = DateTimeField(auto_now_add=True)

# Alert triggers:
- Sync success rate < 90% for 1 hour → WARNING
- DLQ > 10 items → CRITICAL  
- AI error rate > 5% → WARNING
- Tenant sync disabled automatically → INFO

Phase 5: Performance Benchmarking​

Sync Performance Tiers​

  • Excellent: <100ms per record
  • Good: 100-500ms
  • Acceptable: 500ms-2s
  • Poor: >2s

AI Performance Tiers​

  • Excellent: <2s per schema adaptation
  • Good: 2-5s
  • Acceptable: 5-10s
  • Poor: >10s

Auto-scaling Recommendations​

  • Detect when Celery workers are overwhelmed
  • Recommend Redis memory increases
  • Identify slow tenants for optimization

Best Practices​

Metric Retention​

  • Real-time: 24 hours (1-minute granularity)
  • Recent: 7 days (5-minute granularity)
  • Historical: 90 days (1-hour granularity)
  • Archive: 1 year (daily aggregates)

Data Privacy​

  • Never log sensitive data (PII, tokens, passwords)
  • Aggregate metrics only (no individual record data)
  • Tenant isolation (can't view other tenants' metrics)

Performance​

  • Async metric collection (don't block requests)
  • Batch writes to reduce DB load
  • Use materialized views for complex aggregations
