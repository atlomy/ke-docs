Sprint 13 Preparation Guide: Archetype Definition

Status as of 2026-05-12: Historical/deferred context, not current sprint state. Sprint 13 was deferred/diverged; later V2 work continued while treating the current archetypes as a provisional frozen baseline. Use this guide when reopening the archetype-definition / ADR-006 unfreeze work. For current focus, read docs/context/state.md, roadmap/board.md, and active specs such as docs/superpowers/specs/0009-v2-ke-entry-surface/.

Purpose: Essential reading and context before defining archetype contracts.

Required Reading (In Order)​

1. Core Architecture Documents​

Platform Principles (MUST READ FIRST)​

📁 docs/developer/architecture/platform_principles.md

Key sections:

  • Foundational Principle (lines 9-25)
  • The Four Pillars (lines 28-76)
  • Epistemic-Canonical Lifecycle (lines 78-146)
  • Canonical Models and Multi-Tenancy (lines 188-214)
  • When Do We Add a New Archetype? (lines 297-318)

Key takeaways:

  • "Canonical structure is shared; interpretation is tenant-specific"
  • Archetypes are rare (~1-2/year)
  • AI cannot approve structural changes
  • Models are never tenant-specific

ADR-002: Hybrid Ontology​

📁 docs/developer/architecture/adr/002-hybrid-ontology-relational-json.md

Key takeaways:

  • Tables define what can exist (archetypes)
  • JSON defines how it's expressed (tenant data)
  • Governance fields must be relational

ADR-004: Tenant Ontology Mapping​

📁 docs/developer/architecture/adr/004-tenant-ontology-mapping.md

Key takeaways:

  • Tenants map labels to archetypes
  • One tenant's "Book" = another's "Source" = DOCUMENT archetype
  • TenantOntology table structure

Archetype Strategic Planning (NEW - CRITICAL)​

📁 docs/developer/architecture/archetype_strategic_planning.md

Key sections:

  • Pattern A vs B comparison (lines 11-57)
  • Three-layer capability structure (lines 122-168)
  • RELATIONSHIP governance (lines 217-274)
  • Hardened Non-Archetype list (lines 202-216)
  • Consultant refinements (lines 406-448)

Key takeaways:

  • Semantic vs Platform vs Permission capabilities
  • Relationship types must be declared
  • Non-Archetype list creates architectural memory

Key Decisions to Make in Sprint 13​

1. Archetype Inventory (6-8 total)​

Confirmed:

  • DOCUMENT
  • TERM
  • ENTITY
  • EVENT
  • MEDIA
  • RELATIONSHIP

To Decide:

  • COLLECTION? (grouped entities)
  • ANNOTATION? (comments, glosses)

2. For Each Archetype, Define:​

{
    'name': 'ARCHETYPE_NAME',
    
    # Three-layer capabilities
    'semantic_capabilities': set(...),
    'platform_capabilities': set(...),
    'permission_flags': set(...),
    
    # Schema
    'required_fields': dict(...),
    'optional_fields': dict(...),
    
    # Relationships
    'allowed_relationships': [
        RelationshipRule(...),
    ],
    
    # Governance
    'forbidden_operations': set(...),
    'promotion_rules': dict(...),
    'invariants': list(...),
}

3. Non-Archetype List​

Explicitly forbid:

  • Book, Source, Manuscript, Reference, Text → DOCUMENT labels
  • Person, Place, Thing, Agent → ENTITY labels
  • Lemma, Term, Concept, Word → TERM labels
  • Historical Event, Timeline Entry → EVENT labels

4. RELATIONSHIP Rules​

Define allowed relationship types:

  • DOCUMENT_CITES_DOCUMENT
  • DOCUMENT_MENTIONS_ENTITY
  • ENTITY_PARTICIPATES_IN_EVENT
  • etc.

Knowledge to Bring​

From Sprint 12​

  • AI can detect archetypes with high confidence
  • Tenant ontology mapping works
  • GraphQL schema suggestion flow functional
  • Approval UI exists

From Consultant​

  • Three-layer capabilities prevent conflation
  • RELATIONSHIP needs strictest governance
  • Junior Engineer Test: Can enforce without understanding AI?
  • Boring Test: Archetypes should feel boring when done

From Architecture​

  • Canonical models are shared, never tenant-specific
  • LLMs reference contracts, never define them
  • Archetypes are law, not implementation
  • "Can run with LLMs off" litmus test

Pre-Sprint Checklist​

Before starting Sprint 13:

  • Read all architecture docs above
  • Understand existing model → archetype mapping
  • Review current ARCHETYPE_CHOICES in code
  • Study three-layer capability structure
  • Understand RELATIONSHIP governance importance
  • Review consultant refinements
  • Confirm Kill Switch: No code until contracts finalized

Questions to Answer in Sprint 13​

  1. Which archetypes? Final list of 6-8
  2. What capabilities? Semantic, platform, permission for each
  3. What relationships? Explicitly allowed types
  4. What's forbidden? Non-Archetype list with examples
  5. How do we promote? Rules for retired external no-code surface → archetype mapping
  6. How do we enforce? Validation rules and invariants

Sprint 13 is foundation work.
Get this right, and everything else becomes easier.
Rush this, and you'll fight drift for years.
