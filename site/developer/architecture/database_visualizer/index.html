Database Visualizer Architecture

Component: spa/src/apps/database_visualizer/ Backend: atlomyapp/graphql/schema.py

Overview​

The Database Visualizer is an interactive graph exploration tool that allows users to understand the "Epistemic Schema" of the Atlomy Atlas platform. Unlike a standard ERD, it focuses on the semantic relationships between research entities, filtering out operational noise.

1. Backend: Resolving the Graph​

The graph data is provided by a localized GraphQL endpoint (/graphql/).

Filtering Strategy​

To maintain a tidy, epistemic-focused view, the resolver explicitly excludes "Operational" or "System" models related to platform internals rather than research data.

Excluded Models:

  • Job, Configuration, Feedback, LogEntry (System)
  • ElasticSearchModel (Search Index)
  • User, Group, Permission (Auth)

Archetype Detection​

Each node is assigned an archetype (e.g., TERM, EVENT, PERSON) based on simple heuristic matching or metadata. This drives the color-coding in the frontend.

2. Frontend: React Flow Implementation​

The frontend uses reactflow for the canvas and dagre for auto-layout.

Component Structure​

  • App.tsx: Main entry. Fetches data via useSchemaGraph, computes layout (Dagre), and manages state.
  • TableNode.tsx: Custom node component.
    • Optimization: Renders a maximum of 5 fields by default to reduce DOM complexity and improve render speed.
    • "Show More": A toggle allows users to expand large tables (like Lemma).
    • Animation: Uses framer-motion (v11) for smooth entry/hover effects.

Performance Considerations​

  • Field Truncation: Essential for tables with 50+ fields. Without this, React Flow's re-rendering became sluggish.
  • Memoization: TableNode is wrapped in React.memo to prevent unnecessary re-renders during pan/zoom.

3. Developer Workflow​

To work on the Visualizer:

  1. Run docker exec -it django_app npm run watch --prefix spa
  2. Edit spa/src/apps/database_visualizer/components/TableNode.tsx
  3. Refresh browser.
