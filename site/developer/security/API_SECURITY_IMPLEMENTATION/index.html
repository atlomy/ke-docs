API Security Implementation Guide

Status: Draft, active checklist Date: 2026-05-12 Related: SECURITY_PRINCIPLES.md, TENANT_ISOLATION.md, Spec 0009

Scope​

This guide turns the high-level security principles into concrete rules for the current Django + React SPA + django-tenants stack.

It covers:

  • GraphQL resolvers and mutations;
  • DRF and function-based API views;
  • tenant context and role checks;
  • frontend API calls;
  • media and infrastructure disclosure;
  • regression tests expected as development continues.

Current Architecture Mapping​

The external Zero Trust proxy pattern maps to KE as follows:

Zero Trust concernKE implementation rule
Trusted proxy injects identityDjango auth/session/JWT establishes request.user; tenant middleware establishes request.tenant.
Backend rejects arbitrary client identityResolvers and views derive tenant/user from request context, never from client schema_name, tenant_id, user_id, or actor.
All frontend calls use one API layerSPA calls go through a shared same-origin REST/GraphQL client.
Internal secret protects backendNot currently part of this monolith path; same-origin, CSRF/JWT, Django permissions, and tenant middleware are the active controls.
Sensitive APIs are role-gatedMutations and write views require tenant role/platform role checks before writes.

Request Context Rules​

Use these server-owned values:

  • tenant: request.tenant;
  • schema: connection.schema_name inside django-tenants implementation code;
  • user: request.user;
  • JWT/session auth state from Django/DRF;
  • role: TenantMembership or platform staff/superuser checks.

Do not authorize from these client-owned values:

  • schema_name;
  • tenant_id;
  • user_id;
  • actor;
  • role;
  • internal filesystem/object-storage paths;
  • command flags.

When a legacy endpoint still accepts one of these fields, treat it as an input to validate against server-owned state, not as authority.

GraphQL Rules​

Baseline​

Every mutation must:

  1. accept info: Info;
  2. resolve request from info.context;
  3. require authentication;
  4. require the appropriate tenant or platform role;
  5. derive tenant context from request.tenant / connection.schema_name;
  6. reject or ignore client-supplied authority fields;
  7. record an audit trail for security-relevant writes.

Queries must be classified as public read, authenticated read, or operator read. Public queries may be anonymous only when they expose published/read-model data or explicitly public legacy data.

GraphQL CSRF/Auth Contract​

Do not expose one CSRF-exempt endpoint that mixes browser-session mutations and public anonymous reads indefinitely.

Acceptable target shapes:

  • split public read-only GraphQL from authenticated mutation GraphQL; or
  • keep one endpoint but enforce CSRF/session discipline for browser mutations and explicit bearer/service auth for non-browser callers.

Any public GraphQL endpoint should reject mutations unless the mutation auth path is deliberately configured and tested.

REST And Function View Rules​

DRF defaults already require authentication. Overrides must be intentional.

View shapeRule
ReadOnlyModelViewSet with public contentAllowAny may be acceptable.
ModelViewSet or write actionsRequire auth and role checks.
Function view creating rowsRequire auth and role unless deliberately public, rate-limited, and low impact.
Feedback/contact formsMay be public; rate-limit and avoid privileged side effects.
Admin/operator APIsRequire staff/superuser or explicit tenant admin role.

AllowAny on a write-capable view is a security exception and needs a comment, test, and documented rationale.

Frontend API Rules​

The SPA should converge on shared clients:

  • apiClient for REST;
  • graphqlClient for GraphQL.

Both clients should:

  • only accept relative same-origin paths such as /api/... and /graphql/;
  • reject absolute URLs in browser code;
  • set credentials: "same-origin" when session auth is used;
  • attach CSRF tokens for mutating session-authenticated requests;
  • attach JWT Authorization headers only through the auth module;
  • parse errors consistently;
  • expose typed helpers for common GraphQL/REST calls.

Components and hooks should not instantiate ad hoc fetch, axios, or graphql-request clients after the shared layer exists.

Tenant Role Helper Target​

The codebase should grow a small, shared authorization helper rather than duplicating checks in every resolver.

Target behavior:

  • require_authenticated_actor(request);
  • require_tenant_role(request, roles=[...]);
  • require_platform_staff(request);
  • require_platform_superuser(request);
  • return an actor object with user, tenant, membership, and role;
  • raise a consistent permission error that maps cleanly to GraphQL/REST responses.

The helper must treat public schema requests carefully: public platform routes may be platform-admin only, not tenant-admin by default.

Infrastructure Disclosure Rules​

Never return these to normal browser users:

  • database password;
  • cloud access key or secret key;
  • unrestricted database connection string;
  • internal service secret;
  • internal filesystem paths;
  • private object-storage keys unless scoped through signed URLs.

Server-side tools may introspect schemas or perform imports without disclosing their credentials to the browser.

Media And Object Storage Rules​

Every upload or generated artifact needs an access class:

  • public_published;
  • tenant_authenticated;
  • temporary_signed;
  • operator_private.

AWS_QUERYSTRING_AUTH = False is acceptable only for assets that are intended to be public. Draft uploads, import files, private overlays, source spreadsheets, and review artifacts need authenticated delivery or signed URLs.

Runtime And Header Rules​

Before public launch:

  • remove unsafe-eval from CSP unless a documented dependency blocks it;
  • reduce unsafe-inline to nonces/hashes where feasible;
  • avoid broad img-src https://* for private tenant surfaces;
  • remove localhost connect allowances from production settings;
  • keep HSTS, secure cookies, and content-type nosniff enabled in production;
  • define the allowed iframe/frame ancestors for public embeds and admin tools.

Security Regression Test Checklist​

Add or update tests whenever the related surface changes:

  • unauthenticated GraphQL mutation is rejected;
  • authenticated viewer cannot perform editor/admin mutation;
  • mutation cannot switch tenant with client schema_name;
  • mutation actor is server-derived, not client-supplied;
  • public GraphQL endpoint rejects mutations or enforces CSRF/auth;
  • write-capable DRF views are not AllowAny;
  • public read-only views remain read-only;
  • DB visualizer does not disclose passwords or unrestricted connection strings;
  • media draft/private assets are not exposed through public unsigned URLs;
  • frontend network tests prove Entry Surface uses the shared API layer and no V1 REST JSON data source after Spec 0009 cutover.
