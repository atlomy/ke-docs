Testing standards — Atlomy Atlas

This document captures the test conventions for the v2 / multi-tenant work. Aligns with the existing pytest.ini + tests/conftest.py infrastructure; adds explicit guidance for parser-first / LLM-second discipline (ADR-010) and slot-architecture testing.

Pyramid​

LLM-off litmus​

The repo uses LLM_DISABLED=1 as a profile that monkey-patches the LLM provider factory to refuse calls (see tests/conftest.py:llm_disabled_guard). The discipline:

  • Parser code MUST work under LLM_DISABLED=1. The parser is the deterministic-evidence layer of ADR-010; if a parser test needs an LLM to pass, the parser code is wrong.
  • Mark LLM-needing tests @pytest.mark.requires_llm — they get xfail'd under the litmus profile so they don't mask it.
  • Mark proof-of-no-LLM-path tests @pytest.mark.llm_off — these MUST pass under the litmus. They're the regression line for the parser-first commitment.

Run the litmus:

docker compose exec -T django_app sh -c "LLM_DISABLED=1 pytest tests/ -v"

If a test that doesn't expect an LLM accidentally hits one (via, e.g., schema-adapter heuristics that secretly call into data_import.llm_providers), the autouse guard fixture raises immediately — making the leak loud.

Multi-tenant test patterns​

django-tenants uses Postgres search_path per schema. Tests must scope explicitly:

import pytest
from django_tenants.utils import schema_context

pytestmark = pytest.mark.django_db(transaction=True)

def test_something_per_tenant(db):
    with schema_context("atlomy_atlas"):
        # query / write inside ATLOMY's schema
        ...
    with schema_context("visionis"):
        # query / write inside VISIONIS's schema; isolation enforced
        ...

Patterns:

  • Multi-tenant fixture: see tests/integration/test_tenant_isolation.py:two_tenants for creating ephemeral test tenants with their own schemas.
  • Per-tenant data setup: factories within a schema_context block; teardown via the same.
  • Cross-tenant assertions: explicit, never accidental — if a test ever sees data from a different tenant than the one it's currently scoped to, the platform's primary security invariant has broken.

Coverage​

pytest.ini declares source = retired external no-code surface,atlomyapp — extend to include epistemic (and data_import going forward). Targets:

  • Services / projection / parser: 80%+ line coverage
  • Models / admin: 60%+ (much is Django-machinery)
  • Migrations: excluded (already in omit)

Coverage report:

pytest --cov --cov-report=term-missing tests/

When you write a test​

A small checklist that prevents the common antipatterns this project has run into:

  1. Does this test assume a specific tenant exists? → schema_context, not bare ORM queries.
  2. Does this test invoke an LLM? → mark @pytest.mark.requires_llm AND verify the no-LLM equivalent path has its own @pytest.mark.llm_off test.
  3. Does this test bake tenant-specific data into Python code? → use fixtures (parameterizable across tenants) or load from the tenant's TenantArchetypeFormConfig rows.
  4. Does this test hit external services (S3, retired external no-code surface API, ES)? → conftest's override_storage_settings and disable_retired external no-code surface_signals handle the common cases; for new external dependencies, write an autouse fixture that intercepts.
  5. Is this test slow? → mark @pytest.mark.slow so the default fast profile excludes it.

Running​

# Default: fast profile, all unit + integration tests
docker compose exec -T django_app pytest tests/

# Unit only (sub-second feedback)
docker compose exec -T django_app pytest tests/unit/

# LLM-off litmus
docker compose exec -T django_app sh -c "LLM_DISABLED=1 pytest tests/"

# Specific markers
docker compose exec -T django_app pytest -m "unit and not slow" tests/
docker compose exec -T django_app pytest -m "llm_off" tests/

# Single file
docker compose exec -T django_app pytest tests/unit/test_xlsx_parser.py -v

CI expectations​

(Aspirational — actual CI config separate.) On every PR:

  1. Default profile: full unit + integration suite, blocking.
  2. LLM-off litmus profile: same suite under LLM_DISABLED=1, blocking. Catches accidental LLM dependencies.
  3. Coverage: report as PR comment; warn if below baseline (track per-PR delta, not absolute floor).
  4. E2E: nightly only or on-demand label, not blocking on every PR.

Anti-patterns (what NOT to do)​

  • Don't mock data_import.llm_providers per-test. The autouse fixture handles the litmus profile globally.
  • Don't write tests that pass under both LLM_DISABLED=0 and =1 while silently using an LLM in the first case. Mark explicitly.
  • Don't seed tenant-specific data in test code; use the tenant's own TenantArchetypeFormConfig rows or factories.
  • Don't write tests that assume a specific tenant schema name exists in production (atlomy_atlas, visionis). Create ephemeral tenants in fixtures (see test_tenant_isolation.py:two_tenants).
