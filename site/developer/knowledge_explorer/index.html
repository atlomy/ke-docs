Sprint 13: Knowledge Explorer & API Architecture

Last Updated: 2025-12-28 Version: 1.0

Overview​

This document outlines the architecture for the Knowledge Explorer (Sprint 13), including the new REST API layer, JWT authentication, and the React SPA integration.

Architecture​

1. Authentication Layer​

We use a Dual Authentication Strategy to support both legacy/server-rendered views and modern React SPAs.

  • Session Authentication: Used by Django admin and existing templates.
  • JWT Authentication (djangorestframework-simplejwt): Used by the React Knowledge Explorer SPA.

Token Configuration:

  • Access Token: 60 minutes lifetime.
  • Refresh Token: 7 days lifetime, with rotation (new refresh token issued on use).
  • Storage: Client-side localStorage in the SPA.

2. REST API (/api/v1/)​

Built with Django Rest Framework (DRF), this layer provides data access for the frontend.

Endpoints:

  • /api/v1/lemmas/: List and detail views for Lemma model.
    • Faceted Search: Filtering by language, root, archetype.
    • Search: Full-text search on lemma, definition.
    • Pagination: LimitOffsetPagination (default 50 items).
  • /api/v1/references/: Read-only access to Reference model.

Versioning: We use URL path versioning (e.g., v1). Future breaking changes will require a v2 namespace.

3. Frontend: Knowledge Explorer SPA​

Located in spa/src/apps/knowledge_explorer/, this is a standalone React 19 application embedded in a Django template.

Key Components:

  • Tech Stack: React 19, TypeScript, TanStack Query, Tailwind CSS.
  • Entry Point: spa/src/apps/knowledge_explorer/index.tsx.
  • State Management: Server state via TanStack Query; Auth state via React Context/Hooks.
  • Integration: Served via views.knowledge_explorer at /explorer/. The Django view enforces @login_required.

Dependencies & Compatibility​

  • Django: 4.2.7 (LTS) - Retained for django-tenants compatibility.
  • django-filter: 24.3 - Compatible with Django 4.2.
  • djangorestframework-simplejwt: 5.5.1.

Development Workflows​

Running the SPA​

The SPA is built via Webpack.

cd spa
npm run watch  # For development
npm run build  # For production

API Testing​

JWT tokens can be obtaining via:

curl -X POST /api/token/ -d '{"username":"...", "password":"..."}'

Verified endpoints require the Authorization: Bearer <token> header.
