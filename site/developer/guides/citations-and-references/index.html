Citations and References — the Consolidated Guide

Audience: Platform engineers and technically-minded tenant admins. Status: Current as of 2026-06-12 (post ADR-061 ratification). One-line summary: How published entries get evidence rows and scholarly citations — from tenant config, through the attestation walk and the CSL citation pipeline, to the public reader's row precedence.

This guide consolidates what was previously scattered across ADR-020, ADR-022, ADR-061, Spec 0008, the CROSSWALK research docs, and the publication service source. It is a clear-guide artifact, not a decision record: where it disagrees with an ADR, the ADR wins — file a fix here.

1. What the system does​

A published entry (a lemma, a person, an object — any anchor entity a tenant publishes) carries two reference-shaped things on its public surface:

  1. Evidence rows (attestations[]) — "here is where this thing occurs in the sources." One row per occurrence: a passage, a find record, a specimen, a manuscript witness. Each row may optionally bridge one or more paired editions — e.g. a modern critical edition and an early printed edition of the same source.
  2. Scholarly citations (citations[]) — properly formatted bibliographic strings (Chicago, APA, a journal style, a tenant's custom style), produced by the CSL citation framework, never by frontend string-building.

Both are standards-grounded (CSL 1.0.2 for citation grammar and styling; DOI/ORCID/IIIF/CIDOC in adjacent lanes) and both are config-driven: the platform ships the walk, the projector, and the renderer; the tenant declares which archetypes, edges, and fields mean what. Platform code carries no tenant vocabulary (enforced by scripts/lint_no_tenant_vocabulary.py --strict).

The governing contract for how the public reader renders all of this is ADR-061 (docs/developer/architecture/adr/061-reference-rendering-contract.md).

2. The pipeline​

Tenant source data (entities + relationship edges)
        │
        ▼
selector_rules.attestation_walk            (ADR-020; epistemic/services/publication.py::_attestations)
  anchor ──edge──▶ occurrences ──join──▶ paired edition sources
        │
        ▼
selector_rules.citation_rules              (Spec 0008; publication.py::_citations)
  structural projection ─▶ csl_projector ─▶ CSL JSON ─▶ citeproc + CSL style ─▶ citation text
        │
        ▼
EntryProjection public payload             (ADR-029)
  attestations[]  +  citations[]
        │
        ▼
Public reader                              (ADR-061; spa/src/pages/result_details/EntrySurfaceDetailShadow.jsx)
  one row per occurrence, ADR-061 text precedence, standalone source citations below

Step by step:

  1. Source data. The anchor entity (the published entry) is connected to occurrence entities by EntityRelationship edges. In v1 substrate terms an attestation is an EntityRelationship row whose rule_name matches the configured walk (ADR-022 §A.1).
  2. Attestation walk (selector_rules.attestation_walk, on the tenant's TenantEntrySurfaceConfig row — atlomyapp/models.py). The platform walks anchor→occurrence edges, then for each occurrence resolves zero or more editions by joining a field on the occurrence to a field on a source entity (declaratively — no code). Output: attestations[], one item per occurrence, each with optional editions[] carrying locator and source-metadata maps.
  3. Citation rules (selector_rules.citation_rules). For each rule, the platform builds a structural projection (entry + occurrence + source + per-edition payloads), projects it to CSL JSON via the declarative field grammar (epistemic/services/csl_projector.py), and renders text via citeproc with a style resolved from TenantCSLStyle (DB) or the vendored CSL catalog (epistemic/services/citation_renderer.py::load_csl_style). Output: citations[], each with text, style, source metadata (including occurrence_id for attestation-sourced citations), the raw csl_json, provenance, and warnings.
  4. Public payload. EntryPublishService writes both arrays into the published EntryProjection payload (ADR-029 — the projection-first published Entry layer). Dependencies (edges, occurrences, sources, styles) are captured so source writes re-trigger projection work.
  5. Reader rendering. EntrySurfaceDetailShadow.jsx composes the References section per the ADR-061 precedence (§6 below).

3. The config reference​

Both blocks live in TenantEntrySurfaceConfig.selector_rules (JSONB). All field names in the examples below — Modern Edition, Quote, Author, Editor-Abbreviated, every quoted column — are tenant data declared in tenant config. None of them exist in platform code.

3.1 attestation_walk​

KeyMeaning
occurrence_archetypeArchetype of the occurrence entities (the evidence rows). Required.
anchor_join_rule_name (or nested anchor_join.rule_name)EntityRelationship.rule_name that joins anchor↔occurrence. Required.
anchor_join_direction (or anchor_join.direction)"inbound" (default — occurrence is the edge source, entry the target) or "outbound".
relationship_statuses (aliases: anchor_join_statuses, statuses)Edge statuses to include; string or list. Default: all platform relationship statuses.
occurrence_label_field (alias: occurrence_word_field)Occurrence data field used as the row label (often the quote). Fallback: a label heuristic over canonical_form/title/name/label/term/lemma/keyword, then the entity pk.
editions[]Zero or more paired-edition declarations (below). Optional — an occurrence with no resolvable edition still produces a row (ADR-061).

Each entry in editions[]:

KeyMeaning
nameRole key, e.g. modern_edition. Skipped if empty. Also seeds the citation structural key (§3.2).
labelDisplay label; defaults to title-cased name.
occurrence_join_field (alias: occurrence_field)Occurrence data field holding the join value. No value → this edition is skipped for this occurrence (this is what makes editions optional).
source_archetypeArchetype of the source entity (e.g. a bibliography DOCUMENT).
source_canonical_typeOptional extra filter on the source.
source_join_fieldSource data field matched against the join value. Source not found → a placeholder source labeled with the join key (the row still renders).
occurrence_locatorMap of output key → occurrence data field. Output keys are platform-conventional (see below).
source_metadataMap of output key → source data field. Same convention.

Conventional output keys. The locator/metadata maps emit whatever keys the tenant declares, but the reader's structural composition (§6) recognizes a conventional set: author, editor, translator, treatise, title (source metadata); book, chapter, section, page, line, quote, text, word, word_translation (locator); editor_abbreviated / abbreviated (bridge abbreviation). Map your tenant columns onto these keys to get bridged rendering for free; unmapped keys still travel in the payload.

3.2 citation_rules​

A list (or single object) under citation_rules (aliases accepted: citations, citation). Each rule:

KeyMeaning
source"entry" (default — one citation for the entry itself), "attestations" (one citation per occurrence, joined back to its evidence row), or "media" (per media edge, with Anchor-derived locators).
source_roleFor source: "attestations" — which edition role's source backs the citation (e.g. modern_edition). Falls back to the first edition with a resolved source.
style_idCSL style id. For catalog/filesystem styles this is the filename including the .csl extension (e.g. chicago-author-date.csl). Lookup order: TenantCSLStyle DB row → epistemic/static/csl_styles/tenant/<schema>/ → epistemic/static/csl_styles/standard/. Not found → FileNotFoundError, surfaced to admin.
style_versionOptional version override; defaults to the resolved style's version (DB version or a file content hash).
localeciteproc locale, default en-US.
validate_schemaValidate the projected CSL JSON against csl-data.json (default true).
field_mapping (alias: csl_field_mapping)The CSL projection declaration (below). Rule is skipped without it.

field_mapping structure:

KeyMeaning
csl_typeCSL item type (chapter, book, manuscript, … 45-value enum). Default document.
idOptional explicit CSL item id; defaults to the structural id, else a content hash.
fields{<csl_variable>: <field spec>} — standard CSL variables only.
custom_extensions{<key>: <field spec>} → CSL custom.* — tenant-rich data that doesn't fit the standard schema (abbreviations, locator chains). Standards-conformant consumers ignore unknown keys.
fk_resolutions{<alias>: {from, target_archetype, identity_field, target_data_filters, …}} — pre-resolve a linked entity (e.g. an abbreviation TERM) and expose it under <alias> in structural paths. identity_field supports provenance.source_id (default), ledger.source_id, or data.<key>.
anchor_locatorFor media citations: {field, format, delimiter, first_only} — expose resolved Anchor selectors through a standard CSL field (default note).
_target_namespaceClaimCluster citations only — locked to metadata.citations (namespace contract; anything else raises).

Field spec grammar (csl_projector; exactly one selector per spec):

SelectorBehavior
fromResolve a structural path; may be a list of paths = first-non-empty fallback chain.
name_object_fromResolve, then parse into CSL name objects ("Family, Given", "Given Family", or {literal}). Lists supported.
date_fromResolve, then parse into CSL date-parts (1995, 1995-03, 1995-03-02) or {literal}.
formatTemplate with {path} placeholders, e.g. "{data['Vol']}.{data['Pg']}".
valueConstant.

Modifiers: default (used when empty), skip_if_any_empty (with format — emit nothing if any placeholder is missing), strip_suffix, transform: "roman_upper" (integer → Roman numeral). No conditionals, no loops — conditional rendering belongs to the CSL stylesheet, not the projector.

Structural paths available to attestation-sourced citations: entry.*, occurrence.*, source.* (the role-selected source), data.* (shorthand for the occurrence's data), plus one key per resolved edition: the edition's name (and optional structural_key / key / csl_structural_key), and — when the role ends in _edition — a <prefix>_doc alias (so modern_edition is also reachable as modern_doc). Entry-level citations see entry.*, data.*, provenance.*; media citations see entry.*, media.*, edge.*.

3.3 Worked generic example​

A classics-flavored tenant whose occurrences are passages, bridging a modern critical edition with an early printed edition. Target rendering on the reader: Author, On Anatomy, 3, 11, 21 = 6.366 (Ed.) — modern-edition citation parts, then a scholarly equivalence bridge to the early edition's volume.page plus its abbreviated editor. The abbreviation conventions — e.g. the OCD Abbreviations List, Bekker/Kühn pagination — are tenant data and CSL-style concerns, never platform code.

{
  "attestation_walk": {
    "occurrence_archetype": "PASSAGE",
    "anchor_join_rule_name": "term_occurrence",
    "anchor_join_direction": "inbound",
    "occurrence_label_field": "Quote",
    "editions": [
      {
        "name": "modern_edition",
        "label": "Modern edition",
        "occurrence_join_field": "Modern Edition",
        "source_archetype": "DOCUMENT",
        "source_canonical_type": "EDITION",
        "source_join_field": "Name",
        "occurrence_locator": {
          "book": "Book", "chapter": "Chapter", "section": "Section",
          "line": "Line Number", "quote": "Quote",
          "word": "Word", "word_translation": "Translation (EN)"
        },
        "source_metadata": {
          "author": "Author", "treatise": "Work",
          "editor_name": "Editor Name", "year": "Year of publication"
        }
      },
      {
        "name": "early_edition",
        "label": "Early printed edition",
        "occurrence_join_field": "Early Edition",
        "source_archetype": "DOCUMENT",
        "source_join_field": "Name",
        "occurrence_locator": {
          "book": "Early Volume", "page": "Early Page"
        },
        "source_metadata": {
          "editor_abbreviated": "Editor-Abbreviated"
        }
      }
    ]
  },
  "citation_rules": [
    {
      "source": "attestations",
      "source_role": "modern_edition",
      "style_id": "chicago-author-date.csl",
      "locale": "en-US",
      "field_mapping": {
        "csl_type": "chapter",
        "fields": {
          "author": { "name_object_from": "modern_doc.data.Author" },
          "title": { "from": "modern_doc.data.Work" },
          "editor": { "name_object_from": "modern_doc.data['Editor Name']" },
          "issued": { "date_from": "modern_doc.data['Year of publication']" },
          "page": { "from": "data.Page" }
        },
        "custom_extensions": {
          "editor_short": { "from": "early_doc.data['Editor-Abbreviated']" },
          "early_locator": {
            "format": "{data['Early Volume']}.{data['Early Page']}",
            "skip_if_any_empty": true
          }
        }
      }
    }
  ]
}

Reading the example: the walk finds passages joined to the entry by the tenant's term_occurrence edge rule. For each passage, Modern Edition (a passage column) is matched against Name on DOCUMENT entities to resolve the modern edition; Early Edition likewise. The bridge segment = 6.366 (Ed.) is tenant data — early-edition volume/page from the passage row, abbreviation from the edition record — routed through the declarative maps. The citation rule independently produces a Chicago-style citation per passage backed by the modern edition; the reader joins it to the row by occurrence id.

Again: every quoted field name above is tenant data. A prosopography tenant would declare a person↔attestation edge and archival-source joins; a biodiversity tenant a taxon↔specimen edge — same machinery, zero new code (this is the cross-discipline table in ADR-020).

4. Styles and the scholar workflow​

Citation text is owned by the Spec 0008 framework, end to end:

  • Style storage. TenantCSLStyle (DB; per-tenant, no deploy needed — Flow B's apply step writes here) takes precedence over the filesystem: epistemic/static/csl_styles/tenant/<schema>/ (bootstrap-only) and epistemic/static/csl_styles/standard/ (the vendored CSL catalog, platform-managed, refreshed from the citation-style-language/styles repo). Filesystem style_ids are filenames — they include .csl.
  • Ground truth. CitationTestCase rows pin scholar-verified citation strings per style ("Pin as test corpus" on any rendered citation). Validation re-checks pinned cases against any proposed style change; drift blocks the change unless the scholar explicitly re-approves.
  • Flow B — AI proposes → scholar reviews → admin applies. citation_ai_proposer adapts an existing catalog style or synthesizes a custom one from sample citations the scholar pastes. Proposals land in CitationProposal (pending_scholar_review → scholar_approved → admin_applied); AI never mutates production artifacts directly.
  • Validation and risk classes. citation_validation computes blast radius, sample render diffs, corpus regressions, and schema validity, and routes the proposal as low (express lane), medium (standard review), or high (mandatory tenant-admin co-review; never auto-applied). Risk class is routing metadata, not an auto-apply gate.
  • Per-entity override. A manual citation stored on EpistemicEntity.data.citation_override beats the style for that entity, with overridden_by / justification provenance.
  • Provenance. Every rendered citation carries style_id, style_version, fields consumed, custom extensions used, and engine — powering the "Why this citation?" overlay.

Style polish (punctuation, separators, abbreviated forms, locale) is style work, done through Flow B — never frontend string-tuning. Initial seeded styles may render roughly until a scholar ratifies a style.

5. Standards grounding​

The platform's standards evidence base is the CROSSWALK (docs/research/standards/CROSSWALK.md + CROSSWALK_extensions_2026-05-20.md): 8 families spanning 20 matrix rows / ~28 individual standards (several rows bundle sibling standards):

FamilyStandards (matrix rows)
metadataTEI-XML (P5); Dublin Core; MODS v3.8; CIDOC-CRM v7.1.3 (+ CRMtex, reinforced by CRMarchaeo + CRMsci); FRBR + LRMoo
lodBIBFRAME 2.4; PeriodO; GeoSPARQL 1.1; PROV-O / W3C PROV
harvestingOAI-PMH 2.0; IIIF (Presentation + Image 3.0)
identifiersDOI / Crossref / DataCite; ORCID + ROR; CSL 1.0.2 + CSL JSON; Pleiades + GeoNames + Wikidata
stemFAIR + DataCite Metadata Schema 4.5
geospatialGeoJSON (RFC 7946)
biodiversityDarwin Core
packagingRO-Crate v1.2

What matters for this system:

  • CSL 1.0.2 + CSL JSON is primary — the citation grammar, the style language, and the bibliographic exchange format. Tenant-rich data that doesn't fit the standard item schema travels in custom.* extensions.
  • CIDOC-CRM / Linked Art + IIIF are the lane for non-bibliographic evidence — objects, observations, image regions, 3D meshes (ADR-061 decision 5). The export profile choice is ADR-030 (still Proposed — do not claim conformance until ratified). Media citations already translate W3C Anchor selectors to CSL locators via selector_to_locator_map.
  • complies_with declarations (ADR-037) — slots declare conformance against a platform-canonical allowlist; declarations flow to JSON-LD dcterms:conformsTo triples on the published layer and steer export views.
  • Export formats — epistemic/services/bibliographic_export.py emits CSL JSON (.csl.json), BibTeX (.bib), and RIS (.ris), schema-validated; ecosystem wiring (Zotero, ORCID, Crossref) is the ADR-025 lane.

6. The reader contract (ADR-061) — edition-optional, precedence-ordered​

ADR-061's core decisions, as implemented in EntrySurfaceDetailShadow.jsx:

  1. One reference row per attestation (occurrence). Editions are optional. The renderer never gates evidence on the presence of an edition — a researcher's own catalogued manuscript or fragment with no published edition is first-class evidence.
  2. Row text precedence (first non-empty wins; amended 2026-06-12 PM — CSL first, because the CSL lane is the researcher-controllable surface for the exact scholarly format):
    1. CSL-rendered citation joined by citation.source.occurrence_id — the tenant-controlled text. The field mapping + tenant CSL style own abbreviation forms, p. prefixes, bracket layout, Roman-numeral books (transform: roman_upper), compact early-edition locators — e.g. Aristotle, Parts of Animals III, 7, p. 87 Louis (669b14) from a ~25-line tenant style stored in TenantCSLStyle. Also covers edition-less occurrences that still carry a citable source.
    2. Structural bridged composition (the no-citation-rules fallback) — primary edition citation parts (author/editor/translator, treatise/title/source label, book, chapter, section, page, line, joined ", "), then per secondary edition a bridge segment = <locator chain> (<abbreviated>) built from the locator keys joined with . and the editor_abbreviated/abbreviated metadata key.
    3. The occurrence's own label (the tenant-declared occurrence_label_field, often the quote).
  3. Row extras: an occurrence sub-line from the word_translation/word locator keys; a quote block from the quote/text locator keys (the label is not repeated as a quote when the row text already fell back to it).
  4. Standalone source citations: joined-but-unconsumed CSL citations and entry-level citations render as deduplicated rows after the evidence rows ("works cited" behavior).

Canonical vs tenant split: the walk + grammar + precedence + bridge rule + edition-optionality are canonical; which archetypes, edges, fields, styles, and abbreviations participate is tenant config.

Test coverage: spa/src/pages/result_details/EntrySurfaceDetailShadow.test.jsx (bridged paired-edition rows, edition-less occurrences via citation and via label, ordering).

7. Troubleshooting​

SymptomLikely causeFix
References section renders nothing at allNo attestation_walk seeded in selector_rules (or occurrence_archetype/anchor_join_rule_name missing — the walk silently yields [])Seed the walk on the entry role's TenantEntrySurfaceConfig; verify the edge rule_name and direction against actual EntityRelationship rows.
Evidence rows render but carry no scholarly citationsNo citation_rules configured, or style_id doesn't resolve — remember filesystem style ids include the .csl extension (chicago-author-date.csl, not chicago-author-date)Add a citation_rules entry with a resolvable style_id and a non-empty field_mapping; check TenantCSLStyle rows and the vendored catalog.
Citations render with rough punctuation/separatorsThe seeded style hasn't been scholar-tuned; citeproc output is a pure function of (CSL JSON, style)Style tuning via Flow B — propose, review against pinned CitationTestCase rows, apply to TenantCSLStyle. Do not patch the frontend.
Internal-reference values (row ids, opaque keys) leak into rendered rowsA locator or metadata map key points at a linked-record column (which stores a join/reference value) instead of a plain-text columnRe-point the map entry at the human-readable column; keep join columns in occurrence_join_field/source_join_field where they belong.
A row's source shows the raw join key as its labelThe edition's source entity wasn't found (source_archetype/source_join_field mismatch, or the source entity is missing)This is the designed placeholder behavior; fix the join declaration or import the missing source entity.
Edition rows duplicated per edition (legacy behavior)Pre-ADR-061 stub renderingShould not occur on current code — the stub's per-edition duplication was removed; file a bug if seen.
