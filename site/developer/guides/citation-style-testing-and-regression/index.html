Citation Style Testing & Regression

Audience: Engineers working on the citation framework (Spec 0008), and anyone changing a tenant's CSL style or citation field-mapping. Status: Current as of 2026-06-12. Companion to citations-and-references.md (the rendering pipeline) and docs/superpowers/specs/0008-citation-framework-csl/.

A citation style or field-mapping change is a high-blast-radius edit: a single style tweak can silently alter every reference on every published entry. The regression machinery below keeps those changes honest — scholar-approved renders are pinned as ground truth, and any proposed change is measured against them before it ships.

The two pieces​

1. CitationTestCase — pinned ground truth​

epistemic/models.py :: CitationTestCase stores one scholar-approved rendered reference per row, in the tenant schema. Key fields:

FieldMeaning
tenant_id, entityThe tenant and the canonical entity the reference belongs to.
archetype, style_idWhat kind of entry, and which CSL style produced the render.
expected_indexPosition of this reference in the assembler's references[] / projection citations[] list.
expected_citationThe exact rendered string the scholar approved.
csl_jsonThe CSL JSON that produced it — re-rendered through a proposed style during validation.
is_activeToggle a case in/out of the corpus without deleting it.

Unique slot: (tenant_id, entity, style_id, expected_index) — so re-seeding is idempotent (update_or_create on that key).

2. validate_change — the regression gate​

epistemic/services/citation_validation.py :: validate_change(tenant_schema, archetype, proposed_style_id, proposed_style_xml, *, tenant_id) runs the tenant's active corpus for (archetype, style_id) against a proposed style: for each pinned case it re-renders csl_json through the proposed XML and compares to expected_citation. It returns a ValidationReport with corpus_total, corpus_regressions, blast_radius_pct, and a risk_class:

  • low — blast radius ≤ 5% (scholar one-click approve)
  • medium — 5–25% (scholar reviews the diff; admin applies)
  • high — > 25% (mandatory second-eyes; never auto-applies)

risk_class is routing metadata for Flow B's review queue, not an auto-apply gate — AI never mutates production artifacts directly.

A second function, validate_test_cases_for_rendered(entity, style_id, rendered, *, tenant_id), asserts an already-rendered output list against the pinned cases by expected_index (used in assembler integration tests / strict mode). It is currently the dormant index-gate; validate_change is the live Flow B gate.

Pinning ground truth​

Ground truth is sourced from what the system actually rendered — the EntryProjection.public_payload['citations'][] items, which already carry text, csl_json, style, and provenance from the live publish pass. Pin those, rather than hand-typing strings (hand-typed expectations drift from the real renderer). Capture both csl_json (for validate_change's re-render) and expected_citation + expected_index (for the index gate).

Curation guidance for a useful, non-brittle corpus:

  • Diversity over volume. Pick exemplars spanning distinct csl_json shapes (a shape = csl.type + the set of populated top-level keys), so a style edit that breaks any field-handling path is caught. A handful per shape, capped to a tractable corpus, beats pinning thousands of near-identical rows.
  • Well-formed only. Skip degenerate renders (empty page locator, missing author/title) — the corpus should lock the gains, not the warts. Note that classics authors are modelled as opaque CSL literal strings, not family/given; a well-formed filter must accept either.
  • Verify after seeding. Run validate_change with the current style (loaded via citation_renderer.load_csl_style(schema, style_id, tenant_id)); it must report 0 regressions — the pinned csl_json round-trips to expected_citation by construction.

There is no create-endpoint for CitationTestCase yet (the shipped citation_style_test_corpus REST view only toggles is_active); pin via a data script or the create-endpoint when it lands.

A known limitation: schema validity is not separately surfaced​

validate_change does not populate ValidationReport.schema_validity / schema_errors, and citation_renderer.render swallows citeproc errors (falling back to _fallback_render). So a malformed style does not raise — it can be masked when the fallback render happens to match the pinned expectation. Detection of "CSL XML/JSON schema fail" therefore rides on corpus regressions, not a dedicated schema check. Tests assert the real behaviour and hold the schema-validity expectation as a strict xfail (tests/unit/test_citation_validation.py); see that file and the spec's §2.1 reconcile note. (citeproc itself is version-pinned — citeproc-py==0.9.3 — so cross-version render drift is mitigated.)

Tests​

  • tests/unit/test_citation_validation.py — risk-class boundaries, corpus regression detection, the malformed-style masking characterization, and the schema_validity xfail.
  • tests/unit/test_citation_ai_proposer.py — the proposer orchestration with a mocked LLM seam (no provider call).
  • tests/integration/test_citation_style_endpoints.py — Flow B endpoint flow (Codex-owned; do not duplicate here).

Run the unit set in the container with --reuse-db to avoid test-DB contention:

docker compose exec -T django_app python -m pytest \
  tests/unit/test_citation_validation.py \
  tests/unit/test_citation_ai_proposer.py --reuse-db
